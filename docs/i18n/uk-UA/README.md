Cacti Doctor — це плагін для Cacti, який діагностує інсталяцію за один прохід і застосовує невеликі виправлення лише за запитом адміністратора.

**Статус: у розробці, до версії 1.0.** Останній випуск — [0.6.1](https://github.com/somethingwithproof/plugin_doctor/releases/tag/v0.6.1). Цей патч додає каталоги гінді та арабською мовою і перекладені посібники користувача до функціональності версії 0.6.0: доступу з урахуванням ролей, покрокової діагностики, обмежених перевірок актуальності RRD, попереднього перегляду виправлень та історії аудиту, прийнятих винятків для попереджень і перекладів. Докладніше див. у [CHANGELOG.md](../../../CHANGELOG.md).

## Знімки екрана

Діагностика та налаштування розкладу в ізольованій демонстраційній інсталяції
Cacti 1.2.31 під керуванням PHP 8.3.36, включно з перевірками сумісності Cacti
з PHP, підтримки безпеки від розробників PHP (upstream) і стану бази даних.
Наведені тут попередження та збої описують саме це демонстраційне середовище.

![Таблиця діагностики Doctor із результатами пройдених перевірок, попереджень і збоїв](../../screenshots/diagnostics.png)

![Налаштування розкладу, сповіщень і порогів у Doctor](../../screenshots/settings.png)

Проблеми в Cacti зазвичай проявляються як симптоми: порожні графіки, зупинений опитувач (poller), плагін, який не встановлюється. Причиною часто є зміна передумов — наприклад, відсутнє розширення PHP у збірці CLI, каталог журналів, куди опитувач не може записувати, шлях до RRDtool, що вказує на неправильний виконуваний файл, або база даних без таблиць часових поясів. Doctor перевіряє ці передумови безпосередньо та звітує про кожну як «пройдено» (pass), «попередження» (warn) або «збій» (fail) із реченням, яке пояснює виявлене. Той самий звіт доступний на вебсторінці, у командному рядку та у форматі JSON для моніторингу.

## Що перевіряється

| Сфера | Перевірки |
|---|---|
| Doctor | Чи запущено сам Doctor від імені root, через що перевірки прав доступу описували б інший обліковий запис |
| Cacti та PHP | Версія Cacti, оновлення, яке встановлювач так і не завершив, увімкнені плагіни, файли яких відсутні, сумісність PHP зі встановленим пакетом Cacti, статус підтримки безпеки PHP від розробників (upstream) |
| Розширення PHP | Обов'язкові розширення у веб-PHP та у CLI PHP, який використовує опитувач, а також рекомендовані можливості |
| Конфігурація PHP | `memory_limit`, `max_execution_time` та `date.timezone` з урахуванням власних рекомендацій Cacti |
| База даних | З'єднання, відповідність версії сервера рекомендаціям Cacti, кодування UTF-8, таблиці часових поясів, основні таблиці, розбіжність годинника з вузлом PHP та налаштування InnoDB, які Cacti позначає як помилки |
| Стан бази даних | Ємність з'єднань, читання буферного пулу, дискові тимчасові таблиці, створення потоків з'єднань, повільні запити та очікування буфера журналу InnoDB із рекомендаціями щодо налаштування залежно від навантаження |
| Файлова система | Доступність для запису каталогів кешу, журналів і RRA; вільний простір для файлів RRD; активні джерела даних без файлу RRD або із простроченими оновленнями файлів; перевірка, що `include/config.php` не доступний для читання всім користувачам; доступність журналу Cacti для запису та відсутність перевищення розміру |
| Виконувані файли | PHP CLI, RRDtool, `snmpget`, `snmpwalk`, а також Spine, якщо його налаштовано як опитувач, включно з версіями там, де Cacti їх вказує |
| Журнал | Помилки серед останніх рядків журналу Cacti із найчастішим повідомленням |
| Пристрої | Увімкнені пристрої, які недоступні або відновлюються, три пристрої, що недоступні найдовше, з їхньою останньою помилкою, а також збій, коли більшість пристроїв недоступні одночасно |
| Опитувач | Тип та інтервал опитувача, час з моменту останнього завершення головного опитувача, тривалість роботи відносно інтервалу, вихідні дані опитувача, які не потрапили до файлу RRD, віддалені опитувачі, що припинили звітувати, зупинка Boost і конфігурація Spine, яка вказує на іншу базу даних |

Кожна перевірка має стабільний ідентифікатор, наприклад `database.timezone` або `binary.rrdtool`, щоб скрипти могли орієнтуватися на окремі результати.

## Рекомендації щодо стану бази даних

Вбудований PHP-аналізатор Doctor зчитує фіксований набір глобальних лічильників MySQL або MariaDB через наявне з'єднання Cacti з базою даних. Він виконує два запити лише для читання на один звіт, не потребує додаткових облікових даних чи виконуваних файлів і ніколи не змінює конфігурацію бази даних. Ці перевірки відображаються у вебзвіті, CLI, JSON, виводі для моніторингу, пакеті підтримки та запланованому відстеженні стану.

| ID перевірки | Тригер дослідження |
|---|---|
| `database.health_sample` | Менше 24 годин від запуску або `FLUSH STATUS`, або недоступний/непослідовний час безперервної роботи (uptime) |
| `database.connection_capacity` | Поточна або зафіксована пікова кількість з'єднань становить щонайменше 80% від поточного `max_connections` |
| `database.buffer_pool_reads` | `Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests` становить щонайменше 1% за наявності щонайменше 10 000 запитів на читання |
| `database.temporary_tables` | `Created_tmp_disk_tables / Created_tmp_tables` становить щонайменше 25% за наявності щонайменше 1 000 тимчасових таблиць |
| `database.thread_cache` | `Threads_created / Connections` становить щонайменше 5% за наявності щонайменше 1 000 спроб з'єднання та `thread_handling=one-thread-per-connection` |
| `database.slow_queries` | `Slow_queries / Queries` становить щонайменше 1% за наявності щонайменше 1 000 інструкцій |
| `database.redo_log_waits` | Ненульове значення `Innodb_log_waits` |

Це пороги для дослідження від Doctor, а не цільові значення конфігурації від постачальника. За винятком ємності з'єднань, накопичувальні рекомендації потребують зазначеного вище вікна спостереження. Відсутні, пошкоджені, дубльовані або надмірно великі лічильники, недостатня активність і непідтримувані режими потоків формують попередження замість висновку про справний стан або рекомендації з налаштування. Попередження можуть впливати на статус Nagios і заплановані сповіщення, коли ввімкнено параметр **Сповіщати про попередження**.

Аналізуйте виміряні лічильники та рекомендацію разом. Накопичувальні значення не визначають поточне навантаження; лічильники можуть мати різну історію скидання і не є атомарним знімком. Пікові з'єднання можуть відображати старіше обмеження. Кількість повільних запитів залежить від `long_query_time`, а лічильник дискових тимчасових таблиць MySQL може не враховувати файли, відображені в пам'ять (memory-mapped). Низьке співвідношення не доводить відсутність вузького місця. Підтвердьте тенденції під типовим навантаженням, перегляньте плани запитів і повторне використання з'єднань, а також виміряйте пам'ять на **хості бази даних**, перш ніж змінювати буфери чи обмеження з'єднань.

Якщо метрики недоступні, перевірте підтримку з боку сервера та доступ облікового запису Cacti до `SHOW GLOBAL STATUS` і `SHOW GLOBAL VARIABLES`; Doctor не запитує підвищених привілеїв. Визначення лічильників взято з [довідника змінних стану MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-status-variables.html) та [довідника змінних стану MariaDB](https://mariadb.com/docs/server/server-management/variables-and-modes/server-status-variables). Жодного скрипта чи коду MySQLTuner не використовується.

Міграція схеми чи конфігурації не потрібна. Розгорніть файли плагіна у звичайний спосіб; повернення попередніх файлів видалить додану діагностику. Наявний запланований стан оновиться під час наступного запуску.

## Як забезпечується безпека

Інструмент діагностики виконується з привілеями опитувача або вебсервера та зчитує шляхи з таблиці налаштувань, тому він має обережно ставитися до того, що запускає та змінює.

- Діагностика виконується лише для читання. Вона ніколи не змінює файли, налаштування чи дані.
- Doctor запускає налаштований виконуваний файл лише тоді, коли його назва відповідає очікуваній програмі (`php`, `rrdtool`, `snmpget` або `snmpwalk`). Інакше будь-хто, хто має право запису до таблиці налаштувань, міг би вибирати, що запускатиме Doctor. Про будь-яку іншу назву повідомляється як про попередження, і такий файл не виконується.
- Doctor ніколи не запускає налаштовані виконувані файли від імені root і повідомляє, коли сам виконується від імені root.
- Виправлення походять із фіксованого списку дозволених дій. Кожне з них потребує підтвердженої дії адміністратора у вебінтерфейсі або параметра `--yes` у CLI, і кожне записується до журналу Cacti.

## Встановлення

Завантажте `doctor-VERSION.tar.gz` або `doctor-VERSION.zip` і `SHA256SUMS` зі сторінки
[GitHub Releases](https://github.com/somethingwithproof/plugin_doctor/releases).
Перевірте контрольну суму SHA-256 архіву, а потім розпакуйте його каталог `doctor/` у
каталог `plugins/` Cacti. Це пакунки, призначені для встановлення; автоматичні архіви
вихідного коду GitHub мають іншу назву каталогу. Щоб запускати ще не випущені
напрацювання з гілки `develop`, виконайте встановлення з копії вихідного коду.

Для копій вихідного коду:

Клонуйте або розпакуйте репозиторій як `plugins/doctor` усередині інсталяції Cacti. Каталог повинен мати назву `doctor`, а не `plugin_doctor`.

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_doctor.git doctor
```

Встановіть і ввімкніть **Cacti Doctor** у розділі **Configuration > Plugin Management**, а потім надайте область прав **Doctor Viewer**, **Doctor Operator** або **Doctor Administrator** через дозволи користувача чи групи Cacti. Наявні права **Cacti Doctor** після оновлення зберігають рівень доступу Administrator. Звіт з'явиться в розділі **Utilities > Cacti Doctor**.

## Мови

Doctor постачається з 45 неангломовними каталогами перекладів у `locales/po/` та `locales/LC_MESSAGES/`, які охоплюють локалі розширеного першого рівня (`ar-SA`, `de-DE`, `es-ES`, `es-419`, `fr-FR`, `hi-IN`, `id-ID`, `it-IT`, `ja-JP`, `ko-KR`, `nl-NL`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `tr-TR`, `uk-UA`, `vi-VN`, `zh-CN`, `zh-TW`), африканські (`af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`) та азійські (`bn-BD`, `fa-IR`, `he-IL`, `mr-IN`, `ms-MY`, `ta-IN`, `te-IN`, `th-TH`, `ur-PK`, `fil-PH`). Cacti відображає каталог, щойно ввімкнено підтримку мов (**Configuration > Settings > General > Language Support**) і користувач обрав локаль, яку Cacti пропонує у своєму списку вибору мови; каталоги для локалей, яких ще немає в списку вибору мови Cacti, починають діяти, щойно Cacti їх додасть. Вебсторінка, налаштування, а також повідомлення та текст звіту, які виводить командний рядок, відповідають мові Cacti; сам звіт у командному рядку використовує типову мову Cacti, яка залишається англійською, доки ви її не зміните.

Машиночитний вивід ніколи не перекладається: ідентифікатори перевірок, ключі та значення статусів JSON, вивід `--format=nagios` і `--format=prometheus`, рядки журналу та заголовки розділів пакета підтримки залишаються англійською, щоб скрипти й системи моніторингу стабільно працювали за будь-якої мови. Єдиною перекладеною частиною JSON-звіту є текст `summary` і `detail` кожної перевірки.

Також постачається каталог для латиноамериканської іспанської (`es-419`), проте ані Cacti 1.2, ані Cacti 1.3 не мають відповідної локалі для вибору, тож він запрацює лише тоді, коли Cacti її додасть. До того часу обирайте іспанську (`es-ES`).

Cacti завантажує каталог плагіна з `plugins/doctor/locales/LC_MESSAGES/<locale>.mo` з доменом тексту `doctor` однаково у версіях 1.2.x і 1.3 (версія 1.3 визначає каталог плагінів через налаштовуваний шлях до плагінів).

## Рівні доступу

| Область прав | Можливості |
|---|---|
| Doctor Viewer | Перегляд останніх статусів запланованих перевірок, часу спостереження, актуальності та нещодавньої агрегованої історії. Без діагностичних команд, необроблених деталей, налаштувань чи виправлень. |
| Doctor Operator | Запуск діагностичного звіту з обмеженням часу виконання процесу у 120 секунд, перегляд знеособлених деталей і підтвердження виявлених проблем. Без зміни налаштувань чи виправлень. |
| Doctor Administrator | Можливості Operator, а також наявні виправлення зі списку дозволених і налаштування Doctor. Для виправлень і налаштувань також потрібна область прав Settings/System Utilities у Cacti. |

Меню Utilities відкриває сторінку для найвищої області прав Doctor, наданої користувачеві, включно з груповими дозволами. Нові області Viewer та Operator не отримують жодних автоматичних дозволів. Початковий ідентифікатор області прав залишається прив'язаним до `doctor.php` як Administrator, зберігаючи наявний доступ користувачів і груп.

Дані для ролі Viewer надходять із запланованих перевірок. Увімкніть планування перед наданням доступу Viewer; відсутні або прострочені спостереження відображаються як **unknown**, а не як справні. Журнал історії зберігає останні 20 запланованих агрегованих підрахунків і не містить статусів пристроїв. Оператори запускають нову діагностику явно; звичайне оновлення сторінки використовує останній звіт із їхньої сесії.

Деталі та підсумкові показники щодо пристроїв враховують дозволи поточного користувача на пристрої. Для фрагментів журналу додатково потрібна область прав Log Administration у Cacti. Секретні дані маскуються перед збереженням деталей діагностики у вебсесії або перед їх відображенням. Доступ через CLI й надалі регулюється обліковим записом операційної системи.

Підтвердження є персональними й записуються до журналу Cacti. Вони застосовуються лише до тієї самої проблеми та тих самих свідчень; зміна свідчень потребує нового підтвердження. Вони ніколи не змінюють статус pass/warn/fail, не пригнічують сповіщення й не позначають проблемну перевірку як справну. Це окремий механізм від винятків для прийнятих попереджень, які впливають на політику сповіщень без зміни зафіксованого статусу й описані нижче.

Кожна дія вимагає методу POST і дійсного токена CSRF. Виправлення відображають окрему сторінку підтвердження з посиланням Cancel, яке не надсилає форму, та записують користувача, який виконав дію, і результат до журналу Cacti.

## Командний рядок

Виконуйте ці команди з кореневого каталогу Cacti від імені користувача опитувача Cacti, а не root:

```console
php plugins/doctor/cli/doctor.php
php plugins/doctor/cli/doctor.php --json
php plugins/doctor/cli/doctor.php --repair=runtime_directories --yes
```

Текстовий вивід друкує один рядок на перевірку з її статусом, категорією, підсумком і деталями. `--json` виводить об'єкт `summary` із лічильниками статусів і масив `checks`, елементи якого містять поля `id`, `category`, `status`, `summary`, `detail`, а також `repair`/`repairable`, коли застосовне виправлення зі списку дозволених.

| Код завершення | Значення |
|---|---|
| `0` | Жодна перевірка не завершилася помилкою, або запитане виправлення виконано успішно. Попередження не змінюють код завершення. |
| `1` | Принаймні одна перевірка завершилася помилкою або запитане виправлення не вдалося виконати. |
| `2` | Помилка використання: запуск виправлення без `--yes` (`--preview` його не потребує), невідомий ідентифікатор виправлення, невідомий формат виводу, непідтримуване поєднання `--symptom` і формату або неможливість знайти інсталяцію Cacti. |

Cacti підвищує `memory_limit` для кожного CLI-скрипта, тому перевірка конфігурації середовища виконання PHP має сенс лише на вебсторінці.

## Заплановані перевірки та сповіщення

У розділі **Configuration > Settings > Doctor** увімкніть **Run Checks on a Schedule** та виберіть інтервал від 15 хвилин до доби. Після кожного циклу опитувача, для якого настав час запуску, Doctor виконує всі перевірки у фоновому процесі, тож це не впливає на час роботи самого опитувача.

Кожен запуск фіксує зафіксований статус кожної перевірки. Активні винятки для попереджень впливають на політику сповіщень, не змінюючи цього результату спостереження. Коли перевірка починає або припиняє завершуватися помилкою, Doctor записує зміну до журналу Cacti та, якщо задано **Alert Email Addresses**, надсилає електронного листа на ці адреси через налаштування пошти Cacti. Параметр **Alert on Warnings** додає сповіщення про переходи до стану попередження та вихід із нього. Перший запуск лише фіксує базовий рівень.

Заплановані звіти виконуються на основному опитувачі під рекомендаційним блокуванням бази даних і мають двохвилинне обмеження для робочого процесу. Doctor повідомляє про час останнього запуску та успішного завершення, щоб відсутні або застарілі результати були помітними. Результати вважаються актуальними протягом заданого інтервалу плюс одного циклу опитування і три хвилини. Запуск, що не завершився, повторюється через 5, 10, 20 і більше хвилин — аж до звичайного інтервалу. Невдалі спроби доставлення сповіщень зберігаються для щонайбільше трьох повторів зі зростаючими затримками; після цього виправте налаштування пошти Cacti та запустіть `php plugins/doctor/cli/doctor.php --scheduled --retry-alerts` від імені користувача опитувача. Прийняття листа поштовим сервером не гарантує його доставлення до скриньки.

На цій самій вкладці задаються порогові значення для часу роботи опитувача (80% від інтервалу), вільного місця на диску для RRA (попередження при менш ніж 10%, помилка при менш ніж 2%), розбіжності годинника бази даних (попередження понад 5 секунд, помилка понад 60) та розміру журналу Cacti (100 MB). Порожні або некоректні значення повертаються до цих типових значень.

## Інтеграція з системами моніторингу

```console
php plugins/doctor/cli/doctor.php --format=nagios
php plugins/doctor/cli/doctor.php --format=prometheus > /var/lib/node_exporter/textfile/cacti_doctor.prom
```

`--format=nagios` виводить один рядок стану з даними продуктивності та завершується з кодом `0` (OK), `1` (WARNING) або `2` (CRITICAL), тож Nagios, Icinga чи будь-яка сумісна система може запускати його безпосередньо. `--format=prometheus` формує текстовий формат Prometheus для колектора textfile у node_exporter: `cacti_doctor_check_status` для кожної перевірки (0 — успіх або прийняте попередження, 1 — попередження, що потребує уваги, 2 — помилка), `cacti_doctor_check_observed_status` до застосування винятків, `cacti_doctor_check_accepted`, `cacti_doctor_checks` для кожного статусу та `cacti_doctor_last_run_timestamp_seconds`. Рядки перевірок у JSON містять поле `assessment`; значення `not_assessed` означає, що перевірка не змогла дійти висновку на основі наявних даних.

## Пакет підтримки

```console
php plugins/doctor/cli/doctor.php --bundle=/tmp/cacti-doctor.txt
```

Пакет являє собою єдиний текстовий файл із версіями Doctor, Cacti, PHP, ОС і бази даних, статистикою опитувача та Boost, повним звітом та останніми 200 рядками журналу Cacti. Значення після назв паролів, секретів, токенів, community та ключів маскуються. Doctor створює файл, доступний для читання лише його власнику, та відмовляється перезаписувати наявний файл. Перегляньте його, перш ніж публікувати будь-де.

## Політика виправлень

Doctor містить одне виправлення — `runtime_directories`. Воно створює відсутні каталоги середовища виконання Cacti та додає права на читання, запис і виконання для власника, не видаляючи наявних прав доступу.

У Cacti 1.3 воно стосується `$cache_path`, `$log_path` і `$rra_path`, а в інших версіях — каталогів `cache`, `log` і `rra` інсталяції. Воно пропускає каталоги, до яких уже є доступ на запис, відхиляє каталоги за межами інсталяції Cacti (наприклад, каталог журналів у `/var/log`), відхиляє символічні посилання та відмовляється виконуватися від імені root. Воно ніколи не переходить за `path_cactilog`, тому файл журналу, налаштований у каталозі з кодом, не може перенаправити туди виправлення. Водночас діагностика перевіряє каталог налаштованого файлу журналу в кожному випуску.

Воно не змінює власника, не виконує команди оболонки, не перезаписує конфігурацію та не змінює дані застосунку Cacti. Кожне нове виправлення має включати діагностику, обробник із переліку дозволених, підтвердження, журналювання аудиту й тести.

## Дослідження симптомів

Оператори й адміністратори можуть вибрати **Дослідити симптом** на сторінці Doctor. Ті самі правила доступні через `--symptom=graphs_stopped`, `slow_polling`, `devices_missing` або `alerts_missing` із виводом у текстовому форматі або JSON. Пакети підтримки містять відповідні дослідження симптомів.

Для кожної можливої причини наведено зафіксовані перевірки та наступний крок верифікації. Можливі причини є гіпотезами, а не підтвердженими першопричинами. Відсутні, неоцінені або застарілі спостереження ніколи не встановлюють причину. Вебдослідження використовують звіт, відфільтрований за правами доступу; звіти CLI використовують доступ облікового запису операційної системи.

## Актуальність оновлень RRD

`filesystem.rrd_stale` перевіряє до 500 активних джерел даних, виключаючи вимкнені та недоступні пристрої. На більших інсталяціях вибірка змінюється щогодини, тому повторні запуски охоплюють різні файли. Перевірка порівнює час модифікації файлу з найбільшим із трьох значень — інтервалу опитувача, кроку вихідного RRD і кроку профілю — помноженим на значення параметра **Інтервали застарівання RRD** (типово 3). Вона показує три найстаріші застарілі файли та кількість уражених пристроїв. У вебінтерфейсі результати містять лише дозволені пристрої.

`filesystem.rrd_files` — це окрема перевірка наявності файлів. Вона шукає файл RRD для щонайбільше 5 000 активних джерел даних, включно з вимкненими та недоступними пристроями, і використовує ту саму щогодинну вибірку.

Boost додає подвійний налаштований інтервал скидання як допуск на запис на диск. Для іншого механізму відкладеного запису налаштуйте **Допуск відкладеного запису RRD (секунди)**. Оголошена змінна `RRDCACHED_ADDRESS` без заданого допуску або некоректний інтервал Boost дають неоцінений результат. Doctor ніколи не скидає кеш для виконання цієї перевірки. Час модифікації свідчить про дискову активність, а не про успішний збір даних. Зовнішнє кешування, яке Doctor не може виявити автоматично, потрібно налаштувати явно.

Відсутні, непридатні для читання та датовані майбутнім часом файли підраховуються в деталях. Результат є неоціненим лише тоді, коли жоден файл із вибірки не доступний для читання. Результат вибіркової перевірки зазначає, що він охоплює лише частину інсталяції; успішне проходження не поширюється на файли поза вибіркою.

## Попередній перегляд виправлень та історія аудиту

Сторінка виправлень адміністратора показує кожен уражений шлях, запропоновану дію, поточні права доступу та цільові права доступу. Схвалення прив'язується до цього попереднього перегляду, поточного користувача та п'ятихвилинного строку дії. Підтвердження використовує попередній перегляд одноразово; зміна стану файлової системи вимагає нового попереднього перегляду. Виконання від імені root, шляхи за межами інсталяції, посилання, що потребують виправлення, та невиконані вимоги до прав файлової системи унеможливлюють схвалення.

`--repair=runtime_directories --preview` виводить план у форматі JSON лише для читання. `--repair=runtime_directories --yes` схвалює щойно обчислений план CLI та повторно перевіряє його перед виконанням. Обліковий запис CLI уже повинен мати права на виправлення інсталяції; він не успадковує вебролі.

Структурований запис `repair.started` має бути збережений перед будь-якою зміною у файловій системі. Пов'язаний запис `repair.completed` містить знімок стану після виправлення та результат верифікації. Перервана операція залишає запис про початок для подальшого аналізу. Збій аудиту завершення повідомляється як збій, навіть якщо зміни у файловій системі відбулися. Doctor додає права власника та створює каталоги; він не виконує автоматичного відкату.

Адміністратори з правом Cacti Settings/System Utilities можуть переглядати останні 20 записів аудиту на сторінці Doctor. Плагін зберігає останні 200 записів у `plugin_doctor_audit`; журнал Cacti також фіксує їхні ідентифікатори, дії та виконавців. Вміст записів аудиту проходить редагування конфіденційних даних.

## Прийняті попередження

Адміністратори з правом Cacti Settings/System Utilities можуть створити **Виняток для попередження** на основі актуального оціненого попередження на сторінці Doctor. Виняток вимагає зазначення відповідальної особи, причини та дати перегляду за UTC у межах 90 днів. Термін дії спливає опівночі за UTC на початку цієї дати. Можна налаштувати до 100 винятків. Список відображає прострочені записи та ідентифікатори, відсутні в поточному звіті, і дозволяє їх видаляти.

Зафіксоване попередження залишається видимим, а відповідальна особа, причина та термін дії відображаються в деталях діагностики. Формат JSON зберігає зафіксований статус і додає метадані `accepted` та `acceptance`. Nagios виключає активні прийняті попередження зі свого підсумкового рівня серйозності, але вказує їх у виводі. Prometheus експортує як зафіксовану, так і актуальну для реагування серйозність. Звичайний код виходу CLI залишається незмінним: попередження вже завершуються з кодом нуль, збої — з кодом один.

Заплановані сповіщення про попередження пригнічуються, доки діє виняток; після завершення терміну дії або видалення винятку триваюче попередження знову підлягає сповіщенням. Переходи до стану збою та відновлення після збою й надалі викликають сповіщення. Неоцінений результат або збій не можна прийняти. Персональне підтвердження є окремим механізмом і нічого не пригнічує. Створення та видалення винятків виконуються транзакційно разом із записом аудиту.

Оновлення створює таблиці `plugin_doctor_audit` і `plugin_doctor_acceptance` без зміни даних застосунку Cacti. Експортуйте потрібну історію перед видаленням плагіна: деінсталяція видаляє обидві таблиці плагіна та його налаштування. Відкат файлів плагіна залишає таблиці доступними для аналізу, але старіші версії не враховують винятки для попереджень.

## Вимоги

| Cacti | PHP | Примітки |
|---|---|---|
| 1.2.20 | 5.4 або новіша | Власний код Doctor сумісний із PHP 5.4, щоб діагностувати застарілі системи перед оновленням |
| 1.2.31 | 8.0 або новіша | Файл `composer.json` у Cacti вимагає `>=8.0` |
| Поточна 1.2.x | 8.2 або новіша | Файл `composer.json` у Cacti вимагає `>=8.2` |
| `develop` (1.3) | 8.3 або новіша | Файл `composer.json` у Cacti вимагає `^8.3` |

Рядок **Сумісність PHP з інстальованою версією Cacti** порівнює запущену версію PHP із вимогою до PHP у кореневому файлі `composer.json` самої Cacti, включно з верхньою межею каретного обмеження, такого як `^8.3`. Налаштований виконуваний файл PHP CLI перевіряється за тією самою вимогою. Doctor розпізнає форми обмежень `>=` і `^`, які використовуються в цих пакунках Cacti. Непридатна для читання, пошкоджена, відсутня або нерозпізнана вимога призводить до попередження; інсталяції Cacti 1.2.20–1.2.30 без маніфесту зберігають задокументований мінімальний поріг інсталятора PHP 5.4. Власна сумісність Doctor із PHP 5.4 не означає сумісності з новішою інсталяцією Cacti.

Рядок **Підтримка безпеки PHP від розробників** відповідає на окреме питання: чи отримує ця гілка випусків PHP виправлення безпеки від проєкту PHP? Він повідомляє опубліковану дату завершення підтримки безпеки цієї гілки та попереджає після її настання. Наприклад, PHP 8.1 може відповідати вимогам середовища виконання старішої інсталяції Cacti, але водночас уже не отримувати виправлень безпеки від розробників. Успішний результат не означає, що встановлений патч-випуск є актуальним, і Doctor не може визначити, чи постачає постачальник ОС бекпортовані виправлення.

Дати підтримки постачаються разом із Doctor на основі [графіка підтримки PHP](https://www.php.net/supported-versions.php) та [списку завершення життєвого циклу](https://www.php.net/eol.php), востаннє перевірених 2026-11-08. Невідомі гілки та попередні випуски викликають попередження замість умовного проходження перевірки. Під час діагностики мережеві запити не виконуються. Оновлюйте дані підтримки Doctor, коли PHP публікує новий графік. Наявні ідентифікатори JSON/моніторингу `php.version` і `php.security_baseline` залишаються незмінними.

## Розробка

Набір модульних тестів використовує Pest і запускається на PHP 8.2 або новішій версії:

```console
composer install
composer test
```

Тести замінюють функції Cacti, які викликає Doctor, невеликими заглушками у файлі `tests/CactiStubs.php`, тому вони виконуються без інсталяції Cacti.

GitHub Actions виконує чотири типи перевірок під час кожного push та pull request:

- `php -l` для кожного файлу PHP на версіях PHP 5.4, 5.6, 7.0, 7.1, 7.4 та від 8.0 до 8.4.
- Набір модульних тестів на PHP 8.2, 8.3 і 8.4.
- `locales/build_gettext.sh --check`, який завершується з помилкою у разі застарілого шаблону перекладу, неповного або нечіткого (fuzzy) каталогу чи скомпільованого каталогу, що відрізняється від вихідного.
- Сім інтеграційних завдань, які встановлюють Cacti 1.2.20, поточну гілку 1.2.x і `develop` із MySQL та MariaDB, а також з cmd.php і Spine. Кожне завдання встановлює та вмикає плагін, запускає повний звіт CLI і перевіряє схему звіту, підсумкові показники, очікувані статуси та точний набір збоїв. Потім воно порушує шлях до виконуваного файлу та часову позначку опитувача, підтверджує, що про обидві проблеми повідомлено, відновлює їх, перевіряє роботу виправлення та його підтвердження, а також виконує вимкнення, увімкнення, видалення й повторне встановлення. У разі збою завдання звіт у форматі JSON зберігається як артефакт.

## Участь у розробці

Запити на злиття (pull requests) надсилайте до гілки `develop`. Забезпечте сумісність робочих файлів із PHP 5.4 та дотримуйтеся стилю коду Cacti: табуляція, рядки в одинарних лапках і допоміжні функції Cacti, як-от `read_config_option()` і `db_fetch_cell()`. Додайте модульний тест для кожної зміни поведінки, підпишіть свої коміти (`git commit -s`) і додайте рядок до `CHANGELOG.md`.

### Переклади

Обгортайте кожне видиме для користувача повідомлення у `__('...', 'doctor')` (або `__n()`, `__x()`, `__esc()`), а речення, що містить значення, оформлюйте одним рядком форматування з послідовними заповнювачами `%s`/`%d` замість конкатенації частин. Функція `__()` у Cacti форматує повідомлення лише тоді, коли воно містить специфікатор формату, і не підтримує позиційні форми `%1$s`. Вона також перетворює `%%` на `%` перед форматуванням, тому ніколи не вставляйте літеральний знак відсотка в повідомлення: передавайте значення разом зі знаком як аргумент (`__('Usage: %s', '50%', 'doctor')`). Рядки журналу залишаються англійською: використовуйте `doctor_repair_message()` для тексту виправлення та `doctor_n_()` для повідомлень, які записуються до журналу й перекладаються лише в місці відображення. Залишайте ідентифікатори перевірок, ключі JSON, ключові слова стану, вивід моніторингу та рядки журналу неперекладеними.

Скрипт `locales/build_gettext.sh` повторно генерує шаблон `locales/po/cacti.pot`, об’єднує його з кожним каталогом `locales/po/<locale>.po` та компілює `locales/LC_MESSAGES/<locale>.mo`; додайте до коміту всі три файли. CI запускає `sh locales/build_gettext.sh --check`, який завершується помилкою, якщо шаблон застарів, у каталозі відсутній або неточний (fuzzy) запис, відрізняється заповнювач або скомпільований файл неактуальний. Тому змінене повідомлення потребує оновлення перекладів у тому самому запиті на злиття. Для цього потрібен GNU gettext (`xgettext`, `msgmerge`, `msgfmt`, `msgunfmt`). Нова мова додається як новий файл `<locale>.po`, названий відповідно до іменування локалей у Cacti (наприклад, `pt-BR`).
