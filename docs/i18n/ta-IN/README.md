Cacti Doctor என்பது ஒரே சுற்றில் ஒரு Cacti நிறுவலை ஆய்வு செய்து, நிர்வாகி கோரும்போது மட்டுமே சிறிய திருத்தங்களைப் பயன்படுத்தும் ஒரு Cacti செருகுநிரலாகும்.

**நிலை: உருவாக்கத்தில் உள்ளது, 1.0 பதிப்புக்கு முந்தையது.** சமீபத்திய வெளியீடு [0.6.1](https://github.com/somethingwithproof/plugin_doctor/releases/tag/v0.6.1) ஆகும். இந்தத் திருத்தப் பதிப்பு, 0.6.0-இல் உள்ள பங்கு-வரம்பிடப்பட்ட அணுகல், வழிகாட்டப்பட்ட ஆய்வு, வரம்பிடப்பட்ட RRD புதுமைச் சோதனைகள், பழுதுபார்ப்பு முன்னோட்டங்கள் மற்றும் தணிக்கை வரலாறு, ஏற்கப்பட்ட எச்சரிக்கை விலக்குகள் மற்றும் மொழிபெயர்ப்புகளுடன் இந்தி மற்றும் அரபுப் பட்டியல்களையும் மொழிபெயர்க்கப்பட்ட பயனர் வழிகாட்டிகளையும் சேர்க்கிறது. விவரங்களுக்கு [CHANGELOG.md](../../../CHANGELOG.md) கோப்பைப் பார்க்கவும்.

## திரைப்பிடிப்புகள்

PHP 8.3.36 இயங்கும் ஒரு தனிமைப்படுத்தப்பட்ட Cacti 1.2.31 செயல்விளக்க நிறுவலில் உள்ள ஆய்வு மற்றும் அட்டவணைப்படுத்தல் அமைப்புகள்; இதில் Cacti PHP இணக்கத்தன்மை, மூலப் பாதுகாப்பு-ஆதரவு மற்றும் தரவுத்தள-ஆரோக்கியச் சோதனைகள் ஆகியவை அடங்கும். இங்கே காட்டப்பட்டுள்ள எச்சரிக்கைகளும் தோல்விகளும் அந்தச் செயல்விளக்கச் சூழலை விவரிக்கின்றன.

![வெற்றி, எச்சரிக்கை மற்றும் தோல்வி முடிவுகளுடன் கூடிய Doctor ஆய்வு அட்டவணை](../../screenshots/diagnostics.png)

![Doctor அட்டவணைப்படுத்தல், அறிவிப்பு மற்றும் வரம்பு அமைப்புகள்](../../screenshots/settings.png)

Cacti சிக்கல்கள் பொதுவாக அறிகுறிகளாகவே வெளிப்படும்: வெற்று வரைபடங்கள், நின்றுபோன சேகரிப்பான் (poller), நிறுவ முடியாத செருகுநிரல். இதற்குக் காரணம் பெரும்பாலும் மாறிப்போன ஒரு முன்நிபந்தனையாக இருக்கும்; எடுத்துக்காட்டாக, CLI கட்டமைப்பில் விடுபட்ட PHP நீட்டிப்பு, சேகரிப்பான் எழுத முடியாத பதிவு அடைவு, தவறான இயங்குகோப்பைச் சுட்டும் RRDtool பாதை, அல்லது நேரமண்டல அட்டவணைகள் இல்லாத தரவுத்தளம். Doctor அந்த முன்நிபந்தனைகளை நேரடியாகச் சரிபார்த்து, ஒவ்வொன்றையும் வெற்றி, எச்சரிக்கை அல்லது தோல்வி என அறிவித்து, அது கண்டறிந்ததை விளக்கும் ஒரு வாக்கியத்தையும் தருகிறது. இதே அறிக்கை வலைப்பக்கத்திலும், கட்டளை வரியிலும், கண்காணிப்பிற்கான JSON வடிவிலும் கிடைக்கிறது.

## இது என்ன சோதனை செய்கிறது

| பகுதி | சோதனைகள் |
|---|---|
| Doctor | Doctor தானே root பயனராக இயங்குகிறதா என்பது; அவ்வாறு இயங்கினால் அனுமதிச் சோதனைகள் தவறான கணக்கை விவரிக்கும் |
| Cacti மற்றும் PHP | Cacti பதிப்பு, நிறுவி முழுமையடையாமல் விட்ட மேம்படுத்தல், கோப்புகள் காணாமல் போன செயல்படுத்தப்பட்ட செருகுநிரல்கள், நிறுவப்பட்ட Cacti தொகுப்புடனான PHP இணக்கத்தன்மை, PHP மூலப் பாதுகாப்பு-ஆதரவு நிலை |
| PHP நீட்டிப்புகள் | வலை PHP-யிலும் சேகரிப்பான் பயன்படுத்தும் CLI PHP-யிலும் தேவையான நீட்டிப்புகள், மேலும் பரிந்துரைக்கப்பட்ட அம்சங்கள் |
| PHP உள்ளமைவு | Cacti-யின் சொந்தப் பரிந்துரைகளைப் பயன்படுத்தி `memory_limit`, `max_execution_time`, மற்றும் `date.timezone` |
| தரவுத்தளம் | இணைப்புத் திறன், Cacti-யின் பரிந்துரைக்கு எதிரான சேவையகப் பதிப்பு, UTF-8 எழுத்துத் தொகுப்பு, நேரமண்டல அட்டவணைகள், அடிப்படை அட்டவணைகள், PHP புரவலனுடனான கடிகார வேறுபாடு, மற்றும் Cacti பிழைகளாகக் குறிக்கும் InnoDB அமைப்புகள் |
| தரவுத்தள ஆரோக்கியம் | இணைப்புக் கொள்ளளவு, இடையகத் தொகுதிப் படிப்புகள் (buffer-pool reads), வட்டு தற்காலிக அட்டவணைகள், இணைப்பு இழை உருவாக்கம், மெதுவான வினவல்கள் மற்றும் InnoDB பதிவு-இடையகக் காத்திருப்புகள், பணிச்சுமை சார்ந்த சீரமைப்புப் பரிந்துரைகளுடன் |
| கோப்பு முறைமை | எழுதக்கூடிய இடைமாற்று (cache), பதிவு (log) மற்றும் RRA அடைவுகள்; RRD கோப்புகளுக்கான காலி இடம்; RRD கோப்பு இல்லாத அல்லது கோப்புப் புதுப்பிப்புகள் தாமதமான செயலில் உள்ள தரவு மூலங்கள்; `include/config.php` அனைவராலும் படிக்க முடியாத நிலையில் உள்ளதா என்பது; Cacti பதிவு எழுதக்கூடியதாகவும் அளவுக்கதிகமாக இல்லாமலும் உள்ளதா என்பது |
| இயங்குகோப்புகள் | PHP CLI, RRDtool, `snmpget`, `snmpwalk`, மற்றும் Spine கட்டமைக்கப்பட்ட சேகரிப்பானாக இருக்கும்போது அதுவும், Cacti பதிப்பைக் குறிப்பிடும் இடங்களில் பதிப்புகளும் உட்பட |
| பதிவு | மிகச் சமீபத்திய Cacti பதிவு வரிகளில் உள்ள பிழைகள், அதிகமாகத் தோன்றும் செய்தியுடன் |
| சாதனங்கள் | செயலிழந்த அல்லது மீண்டுவரும் செயல்படுத்தப்பட்ட சாதனங்கள், நீண்ட காலமாகச் செயலிழந்துள்ள மூன்று சாதனங்கள் அவற்றின் கடைசிப் பிழையுடன், மற்றும் பெரும்பாலான சாதனங்கள் ஒரே நேரத்தில் செயலிழக்கும்போது ஏற்படும் தோல்வி |
| சேகரிப்பான் (Poller) | சேகரிப்பான் வகை மற்றும் இடைவெளி, முதன்மைச் சேகரிப்பான் கடைசியாக முடிந்ததிலிருந்து கடந்த நேரம், இடைவெளிக்கு எதிரான இயக்க நேரம், RRD கோப்பைச் சென்றடையாத சேகரிப்பான் வெளியீடு, அறிக்கையிடுவதை நிறுத்திய தொலைநிலைச் சேகரிப்பான்கள், முடங்கிய Boost, மற்றும் வேறொரு தரவுத்தளத்தைச் சுட்டும் Spine உள்ளமைவு |

ஒவ்வொரு சோதனைக்கும் `database.timezone` அல்லது `binary.rrdtool` போன்ற ஒரு நிலையான அடையாள எண் (ID) உள்ளது; இதனால் உரைநிரல்கள் (scripts) தனிப்பட்ட முடிவுகளைக் கொண்டு செயல்பட முடியும்.

## தரவுத்தள ஆரோக்கிய ஆலோசனை

Doctor-இன் உள்ளார்ந்த PHP பகுப்பாய்வி, Cacti-யின் தற்போதைய தரவுத்தள இணைப்பின் வழியாக MySQL அல்லது MariaDB உலகளாவிய எண்ணிகளின் நிலையான தொகுப்பைப் படிக்கிறது. இது ஒரு அறிக்கைக்கு இரண்டு படிக்க-மட்டுமான வினவல்களைச் செய்கிறது, கூடுதல் நற்சான்றிதழ்களோ இயங்குகோப்புகளோ தேவையில்லை, மேலும் தரவுத்தள உள்ளமைவை ஒருபோதும் மாற்றாது. இந்தச் சோதனைகள் வலை அறிக்கை, CLI, JSON, கண்காணிப்பு வெளியீடு, ஆதரவுத் தொகுப்பு மற்றும் அட்டவணைப்படுத்தப்பட்ட நிலைக் கண்காணிப்பில் தோன்றும்.

| சோதனை ID | ஆய்வுத் தூண்டுதல் |
|---|---|
| `database.health_sample` | தொடக்கத்திலிருந்து அல்லது `FLUSH STATUS`-இலிருந்து 24 மணி நேரத்திற்கும் குறைவாக இருத்தல், அல்லது கிடைக்காத/முரணான இயக்க நேரம் |
| `database.connection_capacity` | தற்போதைய அல்லது பதிவுசெய்யப்பட்ட உச்ச இணைப்புகள் தற்போதைய `max_connections`-இல் குறைந்தது 80% இருத்தல் |
| `database.buffer_pool_reads` | குறைந்தது 10,000 படிப்புக் கோரிக்கைகளுடன் `Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests` குறைந்தது 1% இருத்தல் |
| `database.temporary_tables` | குறைந்தது 1,000 தற்காலிக அட்டவணைகளுடன் `Created_tmp_disk_tables / Created_tmp_tables` குறைந்தது 25% இருத்தல் |
| `database.thread_cache` | குறைந்தது 1,000 இணைப்பு முயற்சிகள் மற்றும் `thread_handling=one-thread-per-connection` உடன் `Threads_created / Connections` குறைந்தது 5% இருத்தல் |
| `database.slow_queries` | குறைந்தது 1,000 கூற்றுகளுடன் `Slow_queries / Queries` குறைந்தது 1% இருத்தல் |
| `database.redo_log_waits` | சுழியமற்ற `Innodb_log_waits` |

இவை Doctor-இன் ஆய்வு வரம்புகளாகும், விற்பனையாளர் உள்ளமைவு இலக்குகள் அல்ல. இணைப்புக் கொள்ளளவைத் தவிர, திரட்டப்பட்ட ஆலோசனைகளுக்கு மேலே உள்ள கவனிப்புக் கால அளவு தேவைப்படுகிறது. விடுபட்ட, சிதைந்த, நகலெடுக்கப்பட்ட அல்லது அளவுக்கதிகமான எண்ணிகள், போதுமான செயல்பாடு இல்லாமை மற்றும் ஆதரிக்கப்படாத இழை முறைகள் ஆகியவை ஆரோக்கியமான தீர்ப்பு அல்லது சீரமைப்புப் பரிந்துரைக்குப் பதிலாக எச்சரிக்கைகளை உருவாக்குகின்றன. **எச்சரிக்கைகளில் அறிவிப்பு (Alert on Warnings)** இயக்கப்படும்போது, எச்சரிக்கைகள் Nagios நிலையையும் அட்டவணைப்படுத்தப்பட்ட அறிவிப்புகளையும் பாதிக்கலாம்.

அளவிடப்பட்ட எண்ணிகளையும் பரிந்துரையையும் சேர்த்துப் படிக்கவும். திரட்டப்பட்ட மதிப்புகள் தற்போதைய சுமையை உறுதிப்படுத்தாது; எண்ணிகள் வெவ்வேறு மீட்டமைப்பு வரலாறுகளைக் கொண்டிருக்கலாம் மற்றும் அவை ஒரு அணுநிலை நிழற்படமாக (atomic snapshot) இருக்காது. உச்ச இணைப்புகள் பழைய வரம்பைப் பிரதிபலிக்கலாம். மெதுவான-வினவல் எண்ணிக்கைகள் `long_query_time`-ஐச் சார்ந்துள்ளது, மேலும் MySQL-இன் வட்டு தற்காலிக-அட்டவணை எண்ணி நினைவக-வரைபடக் கோப்புகளைத் தவிர்க்கக்கூடும். குறைந்த விகிதம் ஒரு இடையூறு இல்லை என்பதை நிரூபிக்காது. இடையகங்கள் அல்லது இணைப்பு வரம்புகளை மாற்றுவதற்கு முன்பு, ஒரு மாதிரிப் பணிச்சுமையின் கீழ் போக்குகளை உறுதிப்படுத்தி, வினவல் திட்டங்களையும் இணைப்பு மறுபயன்பாட்டையும் மதிப்பாய்வு செய்து, **தரவுத்தளப் புரவலனில்** நினைவகத்தை அளவிடவும்.

அளவீடுகள் கிடைக்கவில்லை என்றால், சேவையக ஆதரவையும் `SHOW GLOBAL STATUS` மற்றும் `SHOW GLOBAL VARIABLES` ஆகியவற்றிற்கான Cacti கணக்கின் அணுகலையும் சரிபார்க்கவும்; Doctor உயர்த்தப்பட்ட நற்சான்றிதழ்களைக் கோருவதில்லை. எண்ணி வரையறைகள் [MySQL நிலை-மாறி குறிப்பு](https://dev.mysql.com/doc/refman/8.0/en/server-status-variables.html) மற்றும் [MariaDB நிலை-மாறி குறிப்பு](https://mariadb.com/docs/server/server-management/variables-and-modes/server-status-variables) ஆகியவற்றிலிருந்து வருகின்றன. எந்த MySQLTuner உரைநிரலும் அல்லது குறியீடும் பயன்படுத்தப்படவில்லை.

திட்டமுறை (schema) அல்லது உள்ளமைவு இடம்பெயர்வு எதுவும் தேவையில்லை. செருகுநிரல் கோப்புகளை வழக்கம்போல நிறுவவும்; அந்தக் கோப்புகளைத் திரும்பப் பெறுவது சேர்க்கப்பட்ட ஆய்வுகளை நீக்கிவிடும். தற்போதுள்ள அட்டவணைப்படுத்தப்பட்ட நிலை அடுத்த இயக்கத்தில் புதுப்பிக்கப்படும்.

## இது எவ்வாறு பாதுகாப்பாகச் செயல்படுகிறது

ஒரு கண்டறிதல் கருவி போல்லர் அல்லது வலைச் சேவையகத்தின் சிறப்புரிமைகளுடன் இயங்கி, அமைப்புகள் அட்டவணையிலிருந்து பாதைகளைப் படிப்பதால், அது எதை இயக்குகிறது மற்றும் எதை மாற்றுகிறது என்பதில் கவனமாக இருக்க வேண்டும்.

- கண்டறிதல்கள் படிக்க-மட்டுமானவை. அவை கோப்புகள், அமைப்புகள் அல்லது தரவை ஒருபோதும் மாற்றாது.
- கட்டமைக்கப்பட்ட இரும நிரலின் கோப்புப் பெயர் எதிர்பார்க்கப்படும் நிரலுடன் (`php`, `rrdtool`, `snmpget`, அல்லது `snmpwalk`) பொருந்தும்போது மட்டுமே Doctor அதை இயக்குகிறது. இல்லையெனில், அமைப்புகள் அட்டவணையில் எழுதக்கூடிய எவரும் Doctor எதை இயக்க வேண்டும் என்பதைத் தேர்ந்தெடுக்க முடியும். வேறு எந்தப் பெயரும் எச்சரிக்கையாகப் பதிவு செய்யப்பட்டு, இயக்கப்படாமல் விடப்படும்.
- கட்டமைக்கப்பட்ட இரும நிரல்களை Doctor ஒருபோதும் root பயனராக இயக்காது; மேலும் அது root ஆக இயங்கும்போது அதைப் புகாரளிக்கும்.
- சரிசெய்தல்கள் நிலையான அனுமதிப் பட்டியலிலிருந்து வருகின்றன. ஒவ்வொன்றுக்கும் வலைப் பயனர் இடைமுகத்தில் அங்கீகரிக்கப்பட்ட நிர்வாகி செயல்பாடு அல்லது CLI-இல் `--yes` தேவைப்படுகிறது, மேலும் ஒவ்வொன்றும் Cacti பதிவில் எழுதப்படுகிறது.

## நிறுவல்

[GitHub வெளியீடுகள்](https://github.com/somethingwithproof/plugin_doctor/releases) பக்கத்திலிருந்து `doctor-VERSION.tar.gz` அல்லது `doctor-VERSION.zip` மற்றும் `SHA256SUMS` ஆகியவற்றைப் பதிவிறக்கவும். காப்பகத்தின் SHA-256 செக்சம்மைச் சரிபார்த்து, பின்னர் அதன் `doctor/` கோப்பகத்தை Cacti-இன் `plugins/` கோப்பகத்திற்குள் பிரித்தெடுக்கவும். இவை நிறுவக்கூடிய தொகுப்புகள் ஆகும்; GitHub-இன் தானியங்கி மூலக் காப்பகங்கள் வேறு கோப்பகப் பெயரைக் கொண்டிருக்கும். `develop` கிளையிலிருந்து வெளியிடப்படாத பணிகளை இயக்க, மூலக் குறியீடு பதிவிறக்கத்திலிருந்து நிறுவவும்.

மூலக் குறியீடு பதிவிறக்கங்களுக்கு:

ஒரு Cacti நிறுவலுக்குள் களஞ்சியத்தை `plugins/doctor` என குளோன் செய்யவும் அல்லது பிரித்தெடுக்கவும். கோப்பகத்திற்கு `plugin_doctor` என அல்லாமல் `doctor` எனப் பெயரிடப்பட்டிருக்க வேண்டும்.

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_doctor.git doctor
```

**கட்டமைப்பு > செருகுநிரல் மேலாண்மை** என்பதிலிருந்து **Cacti Doctor** ஐ நிறுவி இயக்கவும், பின்னர் Cacti பயனர் அல்லது குழு அனுமதிகள் மூலம் **Doctor பார்வையாளர்**, **Doctor இயக்குநர்**, அல்லது **Doctor நிர்வாகி** ஆட்சிப் பகுதியை வழங்கவும். ஏற்கனவே உள்ள **Cacti Doctor** அனுமதிகள் மேம்படுத்தலுக்குப் பிறகும் நிர்வாகி அணுகலைத் தக்கவைக்கும். அறிக்கை **பயன்பாடுகள் > Cacti Doctor** என்பதன் கீழ் தோன்றும்.

## மொழிகள்

Doctor `locales/po/` மற்றும் `locales/LC_MESSAGES/` ஆகியவற்றின் கீழ், பரந்த முதல் நிலை (`ar-SA`, `de-DE`, `es-ES`, `es-419`, `fr-FR`, `hi-IN`, `id-ID`, `it-IT`, `ja-JP`, `ko-KR`, `nl-NL`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `tr-TR`, `uk-UA`, `vi-VN`, `zh-CN`, `zh-TW`), ஆப்பிரிக்க (`af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`), ஆசிய (`bn-BD`, `fa-IR`, `he-IL`, `mr-IN`, `ms-MY`, `ta-IN`, `te-IN`, `th-TH`, `ur-PK`, `fil-PH`), மற்றும் தென்கிழக்கு ஐரோப்பிய (`bs-BA`, `hr-HR`, `sr-RS`) ஆகிய மொழியிடங்களை உள்ளடக்கிய ஆங்கிலம் அல்லாத 48 மொழிபெயர்ப்புத் தொகுப்புகளை வழங்குகிறது. மொழி ஆதரவு இயக்கப்பட்டதும் (**கட்டமைப்பு > அமைப்புகள் > பொது > மொழி ஆதரவு**) Cacti தனது மொழித் தேர்வியில் வழங்கும் ஒரு மொழியிடத்தை ஒரு பயனர் தேர்ந்தெடுத்தவுடன் Cacti அந்தத் தொகுப்பைக் காண்பிக்கும்; Cacti-இன் தேர்வியில் இன்னும் பட்டியலிடப்படாத மொழியிடங்களுக்கான தொகுப்புகள், Cacti அவற்றைச் சேர்த்தவுடன் நடைமுறைக்கு வரும். வலைப்பக்கம், அமைப்புகள், மற்றும் கட்டளை வரி அச்சிடும் செய்திகள் மற்றும் அறிக்கை உரை ஆகியவை Cacti-இன் மொழியைப் பின்பற்றுகின்றன; கட்டளை வரி அறிக்கை Cacti இயல்புநிலை மொழியைப் பயன்படுத்துகிறது, நீங்கள் அதை மாற்றாதவரை அது ஆங்கிலத்திலேயே இருக்கும்.

இயந்திரம் படிக்கக்கூடிய வெளியீடு ஒருபோதும் மொழிபெயர்க்கப்படாது: சோதனை ID-கள், JSON விசைகள் மற்றும் நிலை மதிப்புகள், `--format=nagios` மற்றும் `--format=prometheus` வெளியீடுகள், பதிவு வரிகள், மற்றும் ஆதரவுத் தொகுப்புப் பிரிவுத் தலைப்புகள் ஆகியவை ஆங்கிலத்திலேயே இருக்கும்; இதனால் ஸ்கிரிப்டுகள் மற்றும் கண்காணிப்பு எல்லா மொழிகளிலும் தொடர்ந்து செயல்படும். JSON அறிக்கையில் மொழிபெயர்க்கப்படும் ஒரே பகுதி ஒவ்வொரு சோதனையின் `summary` மற்றும் `detail` உரை மட்டுமே ஆகும்.

லத்தீன் அமெரிக்க ஸ்பானிஷ் பட்டியலும் (`es-419`) வழங்கப்படுகிறது, ஆனால் Cacti 1.2 அல்லது Cacti 1.3 ஆகிய இரண்டிலும் தேர்ந்தெடுக்க லத்தீன் அமெரிக்க ஸ்பானிஷ் மொழியமைப்பு இல்லை, எனவே Cacti ஒன்றைச் சேர்க்கும்போது மட்டுமே அது நடைமுறைக்கு வரும். அதுவரை, ஸ்பானிஷ் (`es-ES`) ஐத் தேர்ந்தெடுக்கவும்.

1.2.x மற்றும் 1.3 ஆகிய இரண்டிலும் `doctor` ஐ உரைத் தளமாகக் கொண்டு `plugins/doctor/locales/LC_MESSAGES/<locale>.mo` இலிருந்து ஒரு செருகுநிரலின் பட்டியலை Cacti ஏற்றுகிறது (1.3 அதன் கட்டமைக்கக்கூடிய செருகுநிரல்கள் பாதை வழியாகச் செருகுநிரல் கோப்பகத்தைத் தீர்க்கிறது).

பயனருக்கு வழங்கப்பட்ட மிக உயர்ந்த Doctor ஆட்சிப் பகுதிக்கான பக்கத்தை பயன்பாடுகள் மெனு திறக்கிறது; இதில் குழு அனுமதிகளும் அடங்கும். புதிய பார்வையாளர் மற்றும் இயக்குநர் ஆட்சிப் பகுதிகளுக்குத் தானியங்கி அனுமதிகள் எதுவும் கிடைக்காது. அசல் ஆட்சிப் பகுதி ID நிர்வாகியாக `doctor.php` உடன் இணைக்கப்பட்டே இருக்கும், இது ஏற்கனவே உள்ள பயனர் மற்றும் குழு அணுகலைப் பாதுகாக்கிறது.

பார்வையாளர் தரவு திட்டமிடப்பட்ட சோதனைகளிலிருந்து வருகிறது. பார்வையாளர் அணுகலை வழங்குவதற்கு முன்பு திட்டமிடலை இயக்கவும்; விடுபட்ட அல்லது தாமதமான கண்காணிப்புகள் ஒருபோதும் ஆரோக்கியமானதாக அல்லாமல் **தெரியாதது** எனக் காண்பிக்கப்படும். வரலாறு கடைசி 20 திட்டமிடப்பட்ட திரட்டப்பட்ட எண்ணிக்கைகளைத் தக்கவைத்து, சாதன நிலையைத் தவிர்க்கிறது. இயக்குநர்கள் புதிய கண்டறிதல்களை வெளிப்படையாகத் தொடங்குகிறார்கள்; சாதாரண பக்கப் புதுப்பிப்புகள் அவர்களின் அமர்வின் கடைசி அறிக்கையைப் பயன்படுத்துகின்றன.

சாதன விவரங்கள் மற்றும் மொத்தங்கள் தற்போதைய பயனரின் சாதன அனுமதிகளைப் பயன்படுத்துகின்றன. பதிவுப் பகுதிகளுக்குக் கூடுதலாக Cacti-இன் பதிவு நிர்வாக ஆட்சிப் பகுதி தேவைப்படுகிறது. கண்டறிதல் விவரங்கள் வலை அமர்வில் சேமிக்கப்படுவதற்கு அல்லது காட்டப்படுவதற்கு முன்பு ரகசியங்கள் மறைக்கப்படுகின்றன. CLI அணுகல் தொடர்ந்து இயக்க முறைமைக் கணக்கால் நிர்வகிக்கப்படுகிறது.

ஒப்புதல்கள் தனிப்பட்டவை மற்றும் Cacti பதிவில் பதிவு செய்யப்படுகின்றன. அவை அதே கண்டறிதல் மற்றும் ஆதாரத்திற்கு மட்டுமே பொருந்தும்; மாறிய ஆதாரத்திற்குப் புதிய ஒப்புதல் தேவைப்படுகிறது. அவை ஒருபோதும் pass/warn/fail நிலையை மாற்றாது, எச்சரிக்கைகளை அடக்காது, அல்லது தோல்வியுற்ற சோதனையை ஆரோக்கியமானதாகக் குறிக்காது. இது ஏற்றுக்கொள்ளப்பட்ட-எச்சரிக்கை விதிவிலக்குகளிலிருந்து வேறுபட்டது; அவை கவனிக்கப்பட்ட நிலையை மாற்றாமல் எச்சரிக்கைக் கொள்கையைப் பாதிக்கின்றன மற்றும் கீழே விவரிக்கப்பட்டுள்ளன.

ஒவ்வொரு செயலுக்கும் POST மற்றும் செல்லுபடியாகும் CSRF டோக்கன் தேவைப்படுகிறது. சரிசெய்தல்கள் சமர்ப்பிக்காத ரத்துசெய் இணைப்புடன் தனி உறுதிப்படுத்தல் பக்கத்தைக் காண்பிக்கும், மேலும் செயல்படும் பயனர் மற்றும் முடிவை Cacti பதிவில் பதிவு செய்யும்.

## கட்டளை வரி

இவற்றை Cacti மூலத்திலிருந்து root ஆக அல்லாமல், Cacti போல்லர் பயனராக இயக்கவும்:

```console
php plugins/doctor/cli/doctor.php
php plugins/doctor/cli/doctor.php --json
php plugins/doctor/cli/doctor.php --repair=runtime_directories --yes
```

உரை வெளியீடு ஒவ்வொரு சோதனைக்கும் அதன் நிலை, வகை, சுருக்கம் மற்றும் விவரத்துடன் ஒரு வரியை அச்சிடுகிறது. `--json` நிலை எண்ணிக்கைகளைக் கொண்ட ஒரு `summary` பொருளையும், அனுமதிப் பட்டியலிடப்பட்ட சரிசெய்தல் பொருந்தும்போது `id`, `category`, `status`, `summary`, `detail`, மற்றும் `repair`/`repairable` ஆகியவற்றைக் கொண்ட `checks` வரிசையையும் அச்சிடுகிறது.

| வெளியேறும் நிலை | பொருள் |
|---|---|
| `0` | எந்தச் சோதனையும் தோல்வியடையவில்லை, அல்லது கோரப்பட்ட சரிசெய்தல் வெற்றி பெற்றது. எச்சரிக்கைகள் வெளியேறும் நிலையை மாற்றாது. |
| `1` | குறைந்தது ஒரு சோதனையாவது தோல்வியடைந்தது, அல்லது கோரப்பட்ட சரிசெய்தல் வெற்றி பெறவில்லை. |
| `2` | பயன்பாட்டுப் பிழை: `--yes` இல்லாமல் இயக்கப்பட்ட சரிசெய்தல் (`--preview` க்கு அது தேவையில்லை), அறியப்படாத சரிசெய்தல் ID, அறியப்படாத வெளியீட்டு வடிவம், ஆதரிக்கப்படாத `--symptom` அல்லது வடிவக் கலவை, அல்லது கண்டறிய முடியாத Cacti நிறுவல். |

ஒவ்வொரு CLI ஸ்கிரிப்டுக்கும் Cacti `memory_limit` ஐ உயர்த்துவதால், PHP இயக்க நேரக் கட்டமைப்புச் சோதனை வலைப்பக்கத்தில் மட்டுமே அர்த்தமுள்ளதாக இருக்கும்.

## திட்டமிடப்பட்ட சோதனைகள் மற்றும் எச்சரிக்கைகள்

**கட்டமைப்பு > அமைப்புகள் > Doctor** என்பதன் கீழ், **திட்டமிட்டபடி சோதனைகளை இயக்கு** என்பதை இயக்கி, 15 நிமிடங்கள் முதல் ஒரு நாள் வரையிலான இடைவெளியைத் தேர்ந்தெடுக்கவும். காலாவதியாகும் ஒவ்வொரு போல்லர் சுழற்சிக்கும் பிறகு, Doctor ஒரு பின்னணிச் செயல்முறையில் ஒவ்வொரு சோதனையையும் இயக்குகிறது, இதனால் போல்லரின் சொந்த இயக்க நேரம் பாதிக்கப்படாது.

ஒவ்வொரு இயக்கமும் ஒவ்வொரு சோதனையின் கவனிக்கப்பட்ட நிலையைப் பதிவு செய்கிறது. செயலில் உள்ள எச்சரிக்கை விதிவிலக்குகள் அந்தக் கண்காணிப்பை மாற்றாமல் எச்சரிக்கைக் கொள்கையைப் பாதிக்கின்றன. ஒரு சோதனை தோல்வியடையத் தொடங்கும்போது அல்லது நின்றுவிடும்போது, Doctor அந்த மாற்றத்தை Cacti பதிவில் எழுதுகிறது, மேலும் **எச்சரிக்கை மின்னஞ்சல் முகவரிகள்** அமைக்கப்பட்டிருந்தால், Cacti-இன் அஞ்சல் அமைப்புகள் மூலம் அந்த முகவரிகளுக்கு மின்னஞ்சல் அனுப்புகிறது. **எச்சரிக்கைகளில் எச்சரிக்கை செய்** என்பது எச்சரிக்கைகளுக்குள் செல்வது மற்றும் வெளியேறுவதிலான மாற்றங்களைச் சேர்க்கிறது. முதல் இயக்கம் ஒரு அடிப்படை நிலையை மட்டுமே பதிவு செய்கிறது.

திட்டமிடப்பட்ட அறிக்கைகள் தரவுத்தள ஆலோசனைப் பூட்டின் கீழ் முதன்மை போல்லரில் இயங்குகின்றன மற்றும் இரண்டு நிமிடப் பணியாளர் வரம்பைக் கொண்டுள்ளன. விடுபட்ட அல்லது பழைய முடிவுகள் தெரியும்படி கடைசித் தொடக்கம் மற்றும் வெற்றிகரமான நிறைவை Doctor புகாரளிக்கிறது. இடைவெளி கூட்டல் ஒரு போலிங் சுழற்சி மற்றும் மூன்று நிமிடங்களுக்கு முடிவுகள் தற்போதையதாகக் கருதப்படுகின்றன. நிறைவடையாத ஒரு இயக்கம் 5, 10, 20 மற்றும் அதற்கு மேற்பட்ட நிமிடங்களுக்குப் பிறகு, சாதாரண இடைவெளி வரை மீண்டும் முயற்சிக்கப்படும். தோல்வியடைந்த எச்சரிக்கை விநியோகம் அதிகரிக்கும் தாமதங்களுடன் மூன்று மறுமுயற்சிகள் வரை தக்கவைக்கப்படுகிறது; அதன் பிறகு, Cacti-இன் அஞ்சல் அமைப்புகளைச் சரிசெய்து, போல்லர் பயனராக `php plugins/doctor/cli/doctor.php --scheduled --retry-alerts` ஐ இயக்கவும். அஞ்சல்-சேவையக ஏற்பு இன்பாக்ஸ் விநியோகத்தை உறுதிப்படுத்தாது.

அதே தாவல் போல்லர் இயக்க நேரம் (இடைவெளியின் 80%), RRA இலவச வட்டு இடம் (10% க்குக் கீழே எச்சரிக்கை, 2% க்குக் கீழே தோல்வி), தரவுத்தளக் கடிகார நகர்வு (5 வினாடிகளுக்கு மேல் எச்சரிக்கை, 60 க்கு மேல் தோல்வி), மற்றும் Cacti பதிவு அளவு (100 MB) ஆகியவற்றுக்கான வரம்புகளை அமைக்கிறது. காலியான அல்லது தவறான மதிப்புகள் இந்த இயல்புநிலைகளுக்குத் திரும்பும்.

## கண்காணிப்பு ஒருங்கிணைப்பு

```console
php plugins/doctor/cli/doctor.php --format=nagios
php plugins/doctor/cli/doctor.php --format=prometheus > /var/lib/node_exporter/textfile/cacti_doctor.prom
```

`--format=nagios` செயல்திறன் தரவுடன் ஒரு நிலை வரியை அச்சிட்டு `0` (OK), `1` (WARNING), அல்லது `2` (CRITICAL) என வெளியேறுகிறது, எனவே Nagios, Icinga, அல்லது இணக்கமான எந்தவொரு கணினியும் அதை நேரடியாக இயக்க முடியும். `--format=prometheus` என்பது node_exporter-இன் textfile சேகரிப்பாளருக்கான Prometheus உரை வடிவத்தை எழுதுகிறது: ஒரு சோதனைக்கு `cacti_doctor_check_status` (0 தேர்ச்சி அல்லது ஏற்றுக்கொள்ளப்பட்ட எச்சரிக்கை, 1 நடவடிக்கை எடுக்கக்கூடிய எச்சரிக்கை, 2 தோல்வி), விதிவிலக்குகளுக்கு முன்பு `cacti_doctor_check_observed_status`, `cacti_doctor_check_accepted`, ஒரு நிலைக்கு `cacti_doctor_checks`, மற்றும் `cacti_doctor_last_run_timestamp_seconds`. JSON சோதனை வரிசைகளில் `assessment` புலம் அடங்கும்; கிடைக்கக்கூடிய தரவிலிருந்து சோதனையால் ஒரு முடிவுக்கு வர முடியவில்லை என்பதை `not_assessed` குறிக்கிறது.

## ஆதரவுத் தொகுப்பு

```console
php plugins/doctor/cli/doctor.php --bundle=/tmp/cacti-doctor.txt
```

இந்தத் தொகுப்பு Doctor, Cacti, PHP, OS, மற்றும் தரவுத்தளப் பதிப்புகள், போல்லர் மற்றும் Boost புள்ளிவிவரங்கள், முழு அறிக்கை, மற்றும் Cacti பதிவின் கடைசி 200 வரிகளைக் கொண்ட ஒற்றை உரைக் கோப்பாகும். password, secret, token, community, மற்றும் key பெயர்களைப் பின்தொடரும் மதிப்புகள் மறைக்கப்படுகின்றன. Doctor இந்தக் கோப்பை அதன் உரிமையாளரால் மட்டுமே படிக்கக்கூடியதாக உருவாக்குகிறது மற்றும் ஏற்கனவே உள்ள கோப்பை மேலெழுத மறுக்கிறது. எங்கும் பதிவிடும் முன்பு அதை மதிப்பாய்வு செய்யவும்.

## சீரமைப்புக் கொள்கை

Doctor ஒரு சீரமைப்பைக் கொண்டுள்ளது: `runtime_directories`. இது விடுபட்ட Cacti இயக்கநேர அடைவுகளை உருவாக்கி, ஏற்கனவே உள்ள அனுமதிகளை நீக்காமல் உரிமையாளருக்கான படித்தல், எழுதுதல் மற்றும் இயக்குதல் பிட்களைச் சேர்க்கிறது.

இது Cacti 1.3 இல் `$cache_path`, `$log_path`, மற்றும் `$rra_path` ஆகியவற்றையும், மற்ற பதிப்புகளில் நிறுவலின் `cache`, `log`, மற்றும் `rra` அடைவுகளையும் இலக்காகக் கொள்கிறது. ஏற்கனவே எழுதக்கூடிய அடைவுகளை இது தவிர்க்கிறது; Cacti நிறுவலுக்கு வெளியே உள்ள அடைவுகளையும் (`/var/log` என்பதன் கீழுள்ள பதிவு அடைவு போன்றவை), குறியீட்டு இணைப்புகளையும், root பயனராக இயக்குவதையும் இது மறுக்கிறது. இது ஒருபோதும் `path_cactilog` ஐப் பின்தொடராது, எனவே குறியீட்டு அடைவிற்குள் கட்டமைக்கப்பட்ட பதிவுக் கோப்பு சீரமைப்பை அங்கு திசைதிருப்ப முடியாது. ஆயினும், ஒவ்வொரு வெளியீட்டிலும் கட்டமைக்கப்பட்ட பதிவுக் கோப்பின் அடைவைக் கண்டறிதல் சோதனை தொடர்ந்து சரிபார்க்கிறது.

இது உரிமையுடைமையை மாற்றாது, ஷெல் கட்டளைகளை இயக்காது, கட்டமைப்பை மீண்டும் எழுதாது, அல்லது Cacti பயன்பாட்டுத் தரவை மாற்றாது. புதிய சீரமைப்புகள் ஒவ்வொன்றும் ஒரு கண்டறிதல் சோதனை, அனுமதிப்பட்டியலிடப்பட்ட கையாளுநர், உறுதிப்படுத்தல், தணிக்கைப்பதிவு மற்றும் சோதனைகளைக் கொண்டிருக்க வேண்டும்.

## அறிகுறிகளை ஆராய்தல்

இயக்குபவர்களும் நிர்வாகிகளும் Doctor பக்கத்தில் **அறிகுறியை ஆராய்** என்பதைத் தேர்ந்தெடுக்கலாம். இதே விதிகள் `--symptom=graphs_stopped`, `slow_polling`, `devices_missing`, அல்லது `alerts_missing` வழியாக உரை அல்லது JSON வெளியீட்டுடன் கிடைக்கின்றன. ஆதரவுத் தொகுப்புகளில் தொடர்புடைய அறிகுறி ஆய்வுகள் இடம்பெறும்.

சாத்தியமான ஒவ்வொரு காரணியும் கவனிக்கப்பட்ட சோதனைகளையும் அடுத்த சரிபார்ப்புப் படியையும் பட்டியலிடுகிறது. சாத்தியமான காரணிகள் கருதுகோள்கள் மட்டுமே, உறுதிப்படுத்தப்பட்ட மூல காரணங்கள் அல்ல. விடுபட்ட, மதிப்பிடப்படாத அல்லது பழமையான கவனிப்புகள் ஒருபோதும் ஒரு காரணத்தை உறுதிப்படுத்தா. வலை ஆய்வுகள் அனுமதி-வடிகட்டப்பட்ட அறிக்கையைப் பயன்படுத்துகின்றன; CLI அறிக்கைகள் இயக்க முறைமைக் கணக்கின் அணுகலைப் பயன்படுத்துகின்றன.

## RRD புதுப்பிப்புப் புதுமை

`filesystem.rrd_stale` செயல்பாட்டில் உள்ள 500 தரவு மூலங்கள் வரை சரிபார்க்கிறது; முடக்கப்பட்ட மற்றும் செயலற்ற சாதனங்களைத் தவிர்க்கிறது. பெரிய நிறுவல்களில் மாதிரி ஒவ்வொரு மணி நேரமும் மாறும், எனவே தொடர்ச்சியான இயக்கங்கள் வெவ்வேறு கோப்புகளை உள்ளடக்கும். இது கோப்பு மாற்ற நேரங்களை, போல்லர் இடைவெளி, மூல RRD படிநிலை மற்றும் சுயவிவரப் படிநிலை ஆகியவற்றில் பெரிய மதிப்பை **RRD பழமையான இடைவெளிகள்** (இயல்புநிலை 3) உடன் பெருக்கி கிடைக்கும் மதிப்புடன் ஒப்பிடுகிறது. இது மிகவும் பழமையான மூன்று கோப்புகளையும் பாதிக்கப்பட்ட சாதனங்களின் எண்ணிக்கையையும் காட்டுகிறது. வலை முடிவுகளில் அனுமதிக்கப்பட்ட சாதனங்கள் மட்டுமே இடம்பெறும்.

`filesystem.rrd_files` என்பது ஒரு தனி இருப்புச் சோதனையாகும். முடக்கப்பட்ட அல்லது செயலற்ற சாதனங்களில் உள்ளவை உட்பட, செயல்பாட்டில் உள்ள 5,000 தரவு மூலங்கள் வரையிலான RRD கோப்பை இது தேடுகிறது, மேலும் அதே மணி நேர மாதிரியைப் பயன்படுத்துகிறது.

Boost அதன் கட்டமைக்கப்பட்ட தற்காலிக சேமிப்பு வெளியேற்ற இடைவெளியின் இரு மடங்கை வட்டு-எழுதல் சலுகையாகச் சேர்க்கிறது. வேறொரு தாமதப்படுத்தப்பட்ட எழுதிக்கு, **தாமதப்படுத்தப்பட்ட RRD எழுதல் சலுகை (வினாடிகள்)** என்பதைக் கட்டமைக்கவும். சலுகை இல்லாமல் அறிவிக்கப்பட்ட `RRDCACHED_ADDRESS`, அல்லது தவறான Boost இடைவெளி மதிப்பிடப்படாத முடிவை உருவாக்கும். இந்தச் சோதனையைச் செய்ய Doctor ஒருபோதும் தற்காலிக சேமிப்பை வெளியேற்றாது. கோப்பு மாற்ற நேரம் என்பது வட்டு செயல்பாட்டின் சான்றே தவிர, வெற்றிகரமான தரவு சேகரிப்பின் சான்று அல்ல. Doctor ஆல் கண்டறிய முடியாத வெளிப்புறத் தற்காலிக சேமிப்பை வெளிப்படையாகக் கட்டமைக்க வேண்டும்.

விடுபட்ட, படிக்க முடியாத மற்றும் எதிர்காலத் தேதியிடப்பட்ட கோப்புகள் விவரத்தில் கணக்கிடப்படுகின்றன. மாதிரியாக எடுக்கப்பட்ட எந்தக் கோப்பும் படிக்க முடியாததாக இருக்கும்போது மட்டுமே முடிவு மதிப்பிடப்படாததாக இருக்கும். மாதிரி அடிப்படையிலான முடிவு நிறுவலின் ஒரு பகுதியை மட்டுமே உள்ளடக்குகிறது என்று கூறுகிறது; ஒரு தேர்ச்சி மாதிரியில் சேர்க்கப்படாத கோப்புகளை உள்ளடக்காது.

## சீரமைப்பு முன்னோட்டங்களும் தணிக்கை வரலாறும்

நிர்வாகி சீரமைப்புப் பக்கம் பாதிக்கப்பட்ட ஒவ்வொரு பாதை, முன்மொழியப்பட்ட செயல், தற்போதைய அனுமதிகள் மற்றும் இலக்கு அனுமதிகளைக் காட்டுகிறது. ஒப்புதல் அந்த முன்னோட்டம், செயல்படும் பயனர் மற்றும் ஐந்து நிமிட ஆயுட்காலம் ஆகியவற்றுடன் இணைக்கப்பட்டுள்ளது. உறுதிப்படுத்தல் முன்னோட்டத்தைப் பயன்படுத்திவிடும்; மாற்றப்பட்ட கோப்பு முறைமைக்கு மற்றொரு முன்னோட்டம் தேவைப்படும். root பயனர் இயக்கம், நிறுவலுக்கு வெளியே உள்ள பாதைகள், சீரமைப்பு தேவைப்படும் இணைப்புகள் மற்றும் பூர்த்தி செய்யப்படாத கோப்பு முறைமை அனுமதிகள் ஆகியவை ஒப்புதலைத் தடுக்கின்றன.

`--repair=runtime_directories --preview` படிக்க-மட்டுமான JSON திட்டத்தை அச்சிடுகிறது. `--repair=runtime_directories --yes` புதிதாகக் கணக்கிடப்பட்ட CLI திட்டத்திற்கு ஒப்புதல் அளித்து, செயல்படுத்துவதற்கு முன்பு அதை மீண்டும் சரிபார்க்கிறது. CLI கணக்கு ஏற்கனவே நிறுவலைச் சீரமைக்க அங்கீகரிக்கப்பட்டிருக்க வேண்டும்; அது வலைப் பாத்திரங்களைப் பெறாது.

எந்தவொரு கோப்பு முறைமை மாற்றத்திற்கும் முன்பு கட்டமைக்கப்பட்ட `repair.started` பதிவு சேமிக்கப்பட வேண்டும். இணைக்கப்பட்ட `repair.completed` பதிவில் சீரமைப்புக்குப் பிந்தைய நிலைப்படம் மற்றும் சரிபார்ப்பு முடிவு இருக்கும். இடையூறு ஏற்பட்ட செயல்பாடு ஆய்வுக்குத் தொடங்கப்பட்ட பதிவை விட்டுச்செல்லும். கோப்பு முறைமை மாற்றங்கள் நிகழ்ந்திருந்தாலும், நிறைவு-தணிக்கைத் தோல்வி ஒரு தோல்வியாகவே அறிவிக்கப்படும். Doctor உரிமையாளர் அனுமதிகளைச் சேர்த்து அடைவுகளை உருவாக்குகிறது; இது தானியங்கி பின்னோக்கு மீட்டெடுப்பை முயற்சிக்காது.

Cacti இன் Settings/System Utilities அனுமதி கொண்ட நிர்வாகிகள் Doctor பக்கத்தில் சமீபத்திய 20 தணிக்கை உள்ளீடுகளைப் படிக்கலாம். இந்தச் செருகுநிரல் `plugin_doctor_audit` இல் சமீபத்திய 200 பதிவுகளைத் தக்கவைக்கிறது; Cacti பதிவும் அவற்றின் அடையாள எண்கள், செயல்கள் மற்றும் செயல்படுத்தியவர்களைப் பதிவு செய்கிறது. தணிக்கைத் தரவுச் சுமைகளில் உள்ள முக்கிய விவரங்கள் மறைக்கப்படுகின்றன.

## ஏற்றுக்கொள்ளப்பட்ட எச்சரிக்கைகள்

Cacti இன் Settings/System Utilities அனுமதி கொண்ட நிர்வாகிகள் Doctor பக்கத்தில் புதிய, மதிப்பிடப்பட்ட எச்சரிக்கையிலிருந்து ஒரு **எச்சரிக்கை விலக்கு** உருவாக்கலாம். விலக்கிற்கு ஒரு உரிமையாளர், காரணம் மற்றும் 90 நாட்களுக்குள் ஒரு UTC மறுஆய்வுத் தேதி தேவை. அந்தத் தேதியின் தொடக்கத்தில் UTC நள்ளிரவில் அது காலாவதியாகிறது. 100 விலக்குகள் வரை கட்டமைக்கலாம். இந்தப் பட்டியல் காலாவதியான உள்ளீடுகளையும் தற்போதைய அறிக்கையில் இல்லாத அடையாள எண்களையும் காட்டுகிறது, மேலும் அவற்றை நீக்க அனுமதிக்கிறது.

கவனிக்கப்பட்ட எச்சரிக்கை, கண்டறிதல் விவரங்களில் அதன் உரிமையாளர், காரணம் மற்றும் காலாவதித் தேதியுடன் தொடர்ந்து தெரியும். JSON கவனிக்கப்பட்ட நிலையைத் தக்கவைத்து `accepted` மற்றும் `acceptance` மேனிலைத் தரவைச் சேர்க்கிறது. Nagios செயல்பாட்டில் உள்ள ஏற்றுக்கொள்ளப்பட்ட எச்சரிக்கைகளைத் தனது வெளியேறு தீவிரத்திலிருந்து விலக்குகிறது, ஆனால் அவற்றைத் தனது வெளியீட்டில் குறிப்பிடுகிறது. Prometheus கவனிக்கப்பட்ட மற்றும் நடவடிக்கை எடுக்கக்கூடிய தீவிரம் இரண்டையும் ஏற்றுமதி செய்கிறது. சாதாரண CLI வெளியேறு நிலை மாறாமல் இருக்கும்: எச்சரிக்கைகள் ஏற்கனவே பூஜ்ஜியத்துடன் வெளியேறுகின்றன, தோல்விகள் ஒன்றுடன் வெளியேறுகின்றன.

விலக்கு பொருந்தும் போது திட்டமிடப்பட்ட எச்சரிக்கை விழிப்பூட்டல்கள் தடுக்கப்படுகின்றன; காலாவதி அல்லது நீக்கம் தொடரும் எச்சரிக்கையை மீண்டும் எச்சரிக்கை விழிப்பூட்டல்களுக்குத் தகுதியுடையதாக்குகிறது. தோல்வி மாற்றங்களும் தோல்வியிலிருந்து மீள்வதும் விழிப்பூட்டல்களுக்குத் தொடர்ந்து தகுதியுடையவை. மதிப்பிடப்படாத முடிவையோ தோல்வியையோ ஏற்றுக்கொள்ள முடியாது. தனிப்பட்ட ஒப்புதல் என்பது தனித்தனியானது மற்றும் எதையும் தடுக்காது. விலக்கு உருவாக்கம் மற்றும் நீக்கம் ஆகியவை தணிக்கைப் பதிவுடன் பரிவர்த்தனை அடிப்படையில் இணைக்கப்பட்டுள்ளன.

மேம்படுத்தல் Cacti பயன்பாட்டுத் தரவை மாற்றாமல் `plugin_doctor_audit` மற்றும் `plugin_doctor_acceptance` ஆகியவற்றை உருவாக்குகிறது. நிறுவல் நீக்குவதற்கு முன்பு உங்களுக்குத் தேவையான வரலாற்றை ஏற்றுமதி செய்யுங்கள்: நிறுவல் நீக்கம் இரண்டு செருகுநிரல் அட்டவணைகளையும் அதன் அமைப்புகளையும் நீக்கிவிடும். செருகுநிரல் கோப்புகளை முந்தைய பதிப்பிற்கு மாற்றினால் ஆய்வுக்கு அட்டவணைகள் தொடர்ந்து இருக்கும், ஆனால் பழைய பதிப்புகள் எச்சரிக்கை விலக்குகளை மதிக்காது.

**நிறுவப்பட்ட Cacti உடனான PHP இணக்கத்தன்மை** வரிசை, இயங்கும் PHP பதிப்பை Cacti இன் சொந்த மூல `composer.json` இல் உள்ள PHP தேவையுடன் ஒப்பிடுகிறது; இதில் `^8.3` போன்ற கேரட் கட்டுப்பாட்டின் மேல் எல்லையும் அடங்கும். கட்டமைக்கப்பட்ட PHP CLI இயங்கக்கூடிய கோப்பும் அதே தேவையுடன் சரிபார்க்கப்படுகிறது. இந்த Cacti தொகுப்புகளால் பயன்படுத்தப்படும் `>=` மற்றும் `^` கட்டுப்பாட்டு வடிவங்களை Doctor அடையாளம் காண்கிறது. படிக்க முடியாத, தவறாக வடிவமைக்கப்பட்ட, விடுபட்ட அல்லது அடையாளம் காணப்படாத தேவை ஒரு எச்சரிக்கையை உருவாக்குகிறது; வெளிப்பாட்டுக் கோப்பு இல்லாத Cacti 1.2.20–1.2.30 நிறுவல்கள் அவற்றின் ஆவணப்படுத்தப்பட்ட PHP 5.4 நிறுவி அடிப்படைத் தேவையைத் தக்கவைக்கின்றன. Doctor இன் சொந்த PHP 5.4 இணக்கத்தன்மை புதிய Cacti நிறுவலுடன் இணக்கத்தன்மையை உறுதிப்படுத்தாது.

**PHP மேல்நிலை பாதுகாப்பு ஆதரவு** வரிசை ஒரு தனி கேள்விக்குப் பதிலளிக்கிறது: அந்த PHP வெளியீட்டுக் கிளை இன்னும் PHP திட்டத்திலிருந்து பாதுகாப்புத் திருத்தங்களைப் பெறுகிறதா? இது கிளையின் வெளியிடப்பட்ட பாதுகாப்பு-ஆதரவு முடிவுத் தேதியைப் புகாரளிக்கிறது மற்றும் அந்தத் தேதிக்குப் பிறகு எச்சரிக்கிறது. எடுத்துக்காட்டாக, PHP 8.1 பழைய Cacti நிறுவலின் இயக்கநேரத் தேவையைப் பூர்த்தி செய்யக்கூடும், ஆனால் இனி மேல்நிலை பாதுகாப்புத் திருத்தங்களைப் பெறாமல் இருக்கலாம். தேர்ச்சி முடிவு என்பது நிறுவப்பட்ட ஒட்டு வெளியீடு தற்போதையது என்று அர்த்தமல்ல, மேலும் ஒரு இயக்க முறைமை விற்பனையாளர் பின்னோக்கிப் பொருத்தப்பட்ட திருத்தங்களை வழங்குகிறாரா என்பதை Doctor ஆல் தீர்மானிக்க முடியாது.

ஆதரவுத் தேதிகள் [PHP ஆதரவு அட்டவணை](https://www.php.net/supported-versions.php) மற்றும் [ஆயுட்கால முடிவுப் பட்டியல்](https://www.php.net/eol.php) ஆகியவற்றிலிருந்து Doctor உடன் தொகுக்கப்பட்டுள்ளன; கடைசியாக 2026-11-08 அன்று சரிபார்க்கப்பட்டது. அறியப்படாத கிளைகள் மற்றும் முன்வெளியீடுகள் அனுமானிக்கப்பட்ட தேர்ச்சிக்குப் பதிலாக எச்சரிக்கையை உருவாக்குகின்றன. கண்டறிதல் சோதனையின்போது எந்த பிணையக் கோரிக்கையும் செய்யப்படுவதில்லை. PHP புதிய அட்டவணையை வெளியிடும்போது Doctor இன் ஆதரவுத் தரவைப் புதுப்பிக்கவும். ஏற்கனவே உள்ள JSON/கண்காணிப்பு அடையாள எண்களான `php.version` மற்றும் `php.security_baseline` மாற்றப்படவில்லை.

## மேம்பாடு

அலகு சோதனைத் தொகுப்பு Pest ஐப் பயன்படுத்துகிறது மற்றும் PHP 8.2 அல்லது புதிய பதிப்பில் இயங்குகிறது:

```console
composer install
composer test
```

Doctor அழைக்கும் Cacti செயல்பாடுகளுக்குப் பதிலாக `tests/CactiStubs.php` இல் உள்ள சிறிய மாற்றுச் செயல்பாடுகளைச் சோதனைகள் பயன்படுத்துகின்றன, எனவே அவை Cacti நிறுவல் இல்லாமலேயே இயங்கும்.

ஒவ்வொரு push மற்றும் pull request இன் போதும் GitHub Actions நான்கு வகையான சோதனைகளை இயக்குகிறது:

- PHP 5.4, 5.6, 7.0, 7.1, 7.4, மற்றும் 8.0 முதல் 8.4 வரையிலான பதிப்புகளில் உள்ள ஒவ்வொரு PHP கோப்பிலும் `php -l`.
- PHP 8.2, 8.3, மற்றும் 8.4 இல் அலகு சோதனைத் தொகுப்பு.
- `locales/build_gettext.sh --check`; இது பழமையான மொழிபெயர்ப்பு வார்ப்புரு, முழுமையற்ற அல்லது தெளிவற்ற பட்டியல், அல்லது அதன் மூலத்திலிருந்து வேறுபடும் தொகுக்கப்பட்ட பட்டியல் ஆகியவற்றில் தோல்வியடையும்.
- MySQL மற்றும் MariaDB உடன் cmd.php மற்றும் Spine ஆகிய இரண்டையும் கொண்டு Cacti 1.2.20, தற்போதைய 1.2.x கிளை, மற்றும் `develop` ஆகியவற்றை நிறுவும் ஏழு ஒருங்கிணைப்புப் பணிகள். ஒவ்வொரு பணியும் செருகுநிரலை நிறுவி செயல்படுத்துகிறது, முழு CLI அறிக்கையை இயக்குகிறது, மேலும் அறிக்கைத் திட்டம், சுருக்க மொத்தங்கள், எதிர்பார்க்கப்படும் நிலைகள் மற்றும் தோல்விகளின் துல்லியமான தொகுப்பைச் சரிபார்க்கிறது. பின்னர் அது ஒரு இருமப் பாதையையும் போல்லர் நேர முத்திரையையும் உடைத்து, இரண்டும் புகாரளிக்கப்படுவதை உறுதிசெய்து, அவற்றை மீட்டெடுத்து, சீரமைப்பையும் அதன் உறுதிப்படுத்தலையும் பரிசோதித்து, முடக்குதல், செயல்படுத்துதல், நிறுவல் நீக்குதல் மற்றும் மீண்டும் நிறுவுதல் ஆகியவற்றை இயக்குகிறது. ஒரு பணி தோல்வியடையும்போது JSON அறிக்கை ஒரு கலைப்பொருளாக வைக்கப்படுகிறது.

## பங்களித்தல்

புல் ரெக்வஸ்ட்கள் `develop` கிளைக்குச் செல்லும். தயாரிப்புக் கோப்புகளை PHP 5.4 உடன் இணக்கமாக வைத்திருங்கள், மேலும் Cacti-யின் நடையைப் பின்பற்றுங்கள்: தாவல்கள், ஒற்றை மேற்கோள் சரங்கள், மற்றும் `read_config_option()`, `db_fetch_cell()` போன்ற Cacti துணைச் செயலிகள். ஒவ்வொரு நடத்தை மாற்றத்திற்கும் ஒரு அலகு சோதனையைச் சேர்க்கவும், உங்கள் கமிட்களில் கையொப்பமிடவும் (`git commit -s`), மேலும் `CHANGELOG.md` கோப்பில் ஒரு வரியைச் சேர்க்கவும்.

### மொழிபெயர்ப்புகள்

பயனருக்குத் தெரியும் ஒவ்வொரு செய்தியையும் `__('...', 'doctor')` (அல்லது `__n()`, `__x()`, `__esc()`) இல் அமைக்கவும், மேலும் ஒரு மதிப்பைக் கொண்ட வாக்கியத்திற்குத் துண்டுகளை இணைப்பதற்குப் பதிலாக தொடர்ச்சியான `%s`/`%d` இடநிரப்பிகளைக் கொண்ட ஒரே வடிவமைப்புச் சரத்தை வழங்கவும். Cacti-யின் `__()` ஒரு செய்தியில் வடிவமைப்புக் குறிப்பான் இருக்கும்போது மட்டுமே அதை வடிவமைக்கிறது மற்றும் நிலைசார்ந்த `%1$s` வடிவங்களை ஆதரிக்காது. மேலும் இது வடிவமைப்பதற்கு முன்பு `%%` என்பதை `%` ஆக மாற்றுகிறது, எனவே ஒரு செய்தியில் நேரடியான சதவீதக் குறியீட்டை ஒருபோதும் இடாதீர்கள்: மதிப்பை அதன் குறியீட்டுடன் ஒரு அளபுருவாக அனுப்பவும் (`__('Usage: %s', '50%', 'doctor')`). பதிவு வரிகள் ஆங்கிலத்திலேயே இருக்கும்: சரிசெய்தல் உரைக்கு `doctor_repair_message()` என்பதையும், பதிவு செய்யப்பட்டுக் காட்டப்படும் இடத்தில் மட்டுமே மொழிபெயர்க்கப்படும் செய்திகளுக்கு `doctor_n_()` என்பதையும் பயன்படுத்தவும். சோதனை அடையாள எண்கள், JSON விசைகள், நிலைத் திறவுச்சொற்கள், கண்காணிப்பு வெளியீடு மற்றும் பதிவு வரிகளை மொழிபெயர்க்காமல் வைத்திருங்கள்.

`locales/build_gettext.sh` என்பது `locales/po/cacti.pot` வார்ப்புருவை மீண்டும் உருவாக்குகிறது, அதை ஒவ்வொரு `locales/po/<locale>.po` பட்டியலிலும் ஒன்றிணைக்கிறது, மேலும் `locales/LC_MESSAGES/<locale>.mo` கோப்பைத் தொகுக்கிறது; மூன்றையும் கமிட் செய்யுங்கள். CI ஆனது `sh locales/build_gettext.sh --check` ஐ இயக்குகிறது; வார்ப்புரு பழையதாக இருந்தாலோ, ஒரு பட்டியலில் பதிவு விடுபட்டிருந்தாலோ அல்லது தெளிவற்ற பதிவு இருந்தாலோ, இடநிரப்பி வேறுபட்டாலோ, அல்லது தொகுக்கப்பட்ட கோப்பு காலாவதியாகி இருந்தாலோ இது தோல்வியடையும். எனவே, மாற்றப்பட்ட ஒரு செய்திக்கு அதே புல் ரெக்வஸ்டில் அதன் மொழிபெயர்ப்புகள் புதுப்பிக்கப்பட வேண்டும். இதற்கு GNU gettext (`xgettext`, `msgmerge`, `msgfmt`, `msgunfmt`) தேவை. ஒரு புதிய மொழி என்பது Cacti தனது மொழிகளைப் பெயரிடும் விதத்தில் பெயரிடப்பட்ட புதிய `<locale>.po` கோப்பாகும் (எடுத்துக்காட்டாக `pt-BR`).
