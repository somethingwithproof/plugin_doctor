Cacti Doctor เป็นปลั๊กอินสำหรับ Cacti ที่ช่วยวินิจฉัยการติดตั้งในรอบเดียว และดำเนินการซ่อมแซมเล็กน้อยเฉพาะเมื่อผู้ดูแลระบบสั่งเท่านั้น

**สถานะ: อยู่ระหว่างการพัฒนา ยังไม่ถึงเวอร์ชัน 1.0** รุ่นล่าสุดคือ [0.6.1](https://github.com/somethingwithproof/plugin_doctor/releases/tag/v0.6.1) แพตช์นี้เพิ่มแคตตาล็อกภาษาฮินดีและภาษาอาหรับ รวมถึงคู่มือผู้ใช้ฉบับแปล เพิ่มเติมจากระบบการเข้าถึงตามขอบเขตบทบาท การวินิจฉัยแบบมีแนวทาง การตรวจสอบความสดใหม่ของ RRD ตามขอบเขต การแสดงตัวอย่างการซ่อมแซมและประวัติการตรวจสอบ ข้อยกเว้นคำเตือนที่ยอมรับ และคำแปลในเวอร์ชัน 0.6.0 ดูรายละเอียดเพิ่มเติมได้ที่ [CHANGELOG.md](../../../CHANGELOG.md)

## ภาพหน้าจอ

การวินิจฉัยและการตั้งค่ากำหนดเวลาในระบบสาธิต Cacti 1.2.31 แบบแยกส่วนซึ่งรันบน PHP 8.3.36 รวมถึงการตรวจสอบความเข้ากันได้ของ Cacti กับ PHP สถานะการสนับสนุนด้านความปลอดภัยจากต้นน้ำ และสุขภาพของฐานข้อมูล คำเตือนและความล้มเหลวที่แสดงในภาพเป็นการรายงานสภาพแวดล้อมสาธิตดังกล่าว

![ตารางการวินิจฉัยของ Doctor ที่แสดงผลลัพธ์ผ่าน คำเตือน และล้มเหลว](../../screenshots/diagnostics.png)

![การตั้งค่ากำหนดเวลา การแจ้งเตือน และเกณฑ์ของ Doctor](../../screenshots/settings.png)

ปัญหาของ Cacti มักปรากฏออกมาเป็นอาการ เช่น กราฟว่างเปล่า ตัวโพลเลอร์หยุดทำงาน หรือปลั๊กอินไม่สามารถติดตั้งได้ สาเหตุมักเกิดจากข้อกำหนดเบื้องต้นที่คลาดเคลื่อน เช่น ส่วนขยาย PHP ที่ขาดหายไปในบิลด์ CLI ไดเรกทอรีบันทึกที่โพลเลอร์ไม่สามารถเขียนได้ พาธของ RRDtool ที่ชี้ไปยังไบนารีผิดตัว หรือฐานข้อมูลที่ไม่มีตารางเขตเวลา Doctor จะตรวจสอบข้อกำหนดเบื้องต้นเหล่านั้นโดยตรงและรายงานผลแต่ละรายการเป็นผ่าน คำเตือน หรือล้มเหลว พร้อมประโยคอธิบายสิ่งที่พบ โดยสามารถดูรายงานเดียวกันนี้ได้ทั้งบนหน้าเว็บ บนบรรทัดคำสั่ง และในรูปแบบ JSON สำหรับการเฝ้าติดตาม

## สิ่งที่ตรวจสอบ

| หัวข้อ | รายการตรวจสอบ |
|---|---|
| Doctor | Doctor ทำงานด้วยสิทธิ์ root หรือไม่ ซึ่งจะทำให้การตรวจสอบสิทธิ์รายงานผลของบัญชีผู้ใช้ที่ไม่ถูกต้อง |
| Cacti และ PHP | เวอร์ชันของ Cacti การอัปเกรดที่ตัวติดตั้งดำเนินการไม่เสร็จสมบูรณ์ ปลั๊กอินที่เปิดใช้งานอยู่แต่ไฟล์สูญหาย ความเข้ากันได้ของ PHP กับแพ็กเกจ Cacti ที่ติดตั้งไว้ และสถานะการสนับสนุนด้านความปลอดภัยจากต้นน้ำของ PHP |
| ส่วนขยาย PHP | ส่วนขยายที่จำเป็นใน PHP สำหรับเว็บและใน CLI PHP ที่โพลเลอร์ใช้งาน รวมถึงฟีเจอร์ที่แนะนำ |
| การกำหนดค่า PHP | `memory_limit`, `max_execution_time` และ `date.timezone` โดยอ้างอิงตามคำแนะนำของ Cacti เอง |
| ฐานข้อมูล | การเชื่อมต่อ เวอร์ชันเซิร์ฟเวอร์เทียบกับคำแนะนำของ Cacti ชุดอักขระ UTF-8 ตารางเขตเวลา ตารางหลัก ความคลาดเคลื่อนของเวลาเทียบกับโฮสต์ PHP และการตั้งค่า InnoDB ที่ Cacti แจ้งเป็นข้อผิดพลาด |
| สุขภาพฐานข้อมูล | ความจุการเชื่อมต่อ การอ่านจาก buffer pool ตารางชั่วคราวบนดิสก์ การสร้างเธรดการเชื่อมต่อ คำสั่งที่ทำงานช้า และการรอของ InnoDB log buffer พร้อมคำแนะนำการปรับแต่งที่ขึ้นอยู่กับภาระงาน |
| ระบบไฟล์ | ไดเรกทอรีแคช บันทึก และ RRA ที่สามารถเขียนได้ พื้นที่ว่างสำหรับไฟล์ RRD แหล่งข้อมูลที่ใช้งานอยู่ซึ่งไม่มีไฟล์ RRD หรือไฟล์ไม่ได้รับการอัปเดตเกินกำหนด การตรวจสอบว่า `include/config.php` ไม่ได้เปิดสิทธิ์ให้ทุกคนอ่านได้ และไฟล์บันทึกของ Cacti สามารถเขียนได้และมีขนาดไม่ใหญ่เกินไป |
| ไบนารี | PHP CLI, RRDtool, `snmpget`, `snmpwalk` และ Spine เมื่อกำหนดให้เป็นโพลเลอร์หลัก รวมถึงเวอร์ชันในกรณีที่ Cacti ระบุไว้ |
| บันทึก | ข้อผิดพลาดในบรรทัดบันทึกของ Cacti ล่าสุด พร้อมข้อความที่พบบ่อยที่สุด |
| อุปกรณ์ | อุปกรณ์ที่เปิดใช้งานอยู่ซึ่งหยุดทำงานหรือกำลังกู้คืน สามอุปกรณ์ที่หยุดทำงานนานที่สุดพร้อมข้อผิดพลาดล่าสุด และสถานะล้มเหลวเมื่ออุปกรณ์ส่วนใหญ่หยุดทำงานพร้อมกัน |
| โพลเลอร์ | ประเภทและช่วงเวลาของโพลเลอร์ ระยะเวลาตั้งแต่โพลเลอร์หลักทำงานเสร็จครั้งล่าสุด เวลาที่ใช้ทำงานเทียบกับช่วงเวลา ผลลัพธ์ของโพลเลอร์ที่ไม่เคยไปถึงไฟล์ RRD โพลเลอร์ระยะไกลที่หยุดรายงานผล Boost ที่ค้าง และคอนฟิกของ Spine ที่ชี้ไปยังฐานข้อมูลอื่น |

การตรวจสอบทุกรายการมี ID ที่คงที่ เช่น `database.timezone` หรือ `binary.rrdtool` เพื่อให้สคริปต์สามารถอ้างอิงผลลัพธ์แต่ละรายการได้

## คำแนะนำด้านสุขภาพฐานข้อมูล

ตัววิเคราะห์ PHP ดั้งเดิมของ Doctor จะอ่านชุดตัวนับส่วนกลางของ MySQL หรือ MariaDB ที่กำหนดไว้ตายตัวผ่านการเชื่อมต่อฐานข้อมูลที่มีอยู่ของ Cacti โดยส่งคิวรีแบบอ่านอย่างเดียวสองครั้งต่อหนึ่งรายงาน ไม่ต้องใช้ข้อมูลรับรองหรือไฟล์ปฏิบัติการเพิ่มเติม และไม่เปลี่ยนแปลงการกำหนดค่าฐานข้อมูลแต่อย่างใด การตรวจสอบเหล่านี้จะปรากฏในรายงานบนเว็บ CLI JSON ผลลัพธ์สำหรับการเฝ้าติดตาม ชุดข้อมูลสนับสนุน และการติดตามสถานะตามกำหนดเวลา

| ID การตรวจสอบ | เงื่อนไขที่กระตุ้นการสืบค้นเพิ่มเติม |
|---|---|
| `database.health_sample` | เวลาตั้งแต่เริ่มต้นระบบหรือคำสั่ง `FLUSH STATUS` น้อยกว่า 24 ชั่วโมง หรือ uptime ไม่พร้อมใช้งาน/ไม่สอดคล้องกัน |
| `database.connection_capacity` | จำนวนการเชื่อมต่อปัจจุบันหรือจุดสูงสุดที่บันทึกไว้มีค่าอย่างน้อย 80% ของ `max_connections` ปัจจุบัน |
| `database.buffer_pool_reads` | `Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests` มีค่าอย่างน้อย 1% โดยมีคำขออ่านอย่างน้อย 10,000 ครั้ง |
| `database.temporary_tables` | `Created_tmp_disk_tables / Created_tmp_tables` มีค่าอย่างน้อย 25% โดยมีตารางชั่วคราวอย่างน้อย 1,000 ตาราง |
| `database.thread_cache` | `Threads_created / Connections` มีค่าอย่างน้อย 5% โดยมีความพยายามเชื่อมต่ออย่างน้อย 1,000 ครั้ง และ `thread_handling=one-thread-per-connection` |
| `database.slow_queries` | `Slow_queries / Queries` มีค่าอย่างน้อย 1% โดยมีคำสั่งอย่างน้อย 1,000 คำสั่ง |
| `database.redo_log_waits` | ค่าของ `Innodb_log_waits` ไม่เป็นศูนย์ |

เกณฑ์เหล่านี้เป็นเกณฑ์สำหรับการสืบค้นเพิ่มเติมของ Doctor ไม่ใช่เป้าหมายการตั้งค่าจากผู้ผลิต ยกเว้นความจุการเชื่อมต่อ คำแนะนำแบบสะสมจำเป็นต้องมีระยะเวลาสังเกตการณ์ตามที่ระบุข้างต้น ตัวนับที่ขาดหาย ผิดรูปแบบ ซ้ำซ้อน หรือมีขนาดใหญ่เกินไป กิจกรรมที่ไม่เพียงพอ และโหมดเธรดที่ไม่รองรับ จะแสดงเป็นคำเตือนแทนการสรุปว่าปกติหรือการแนะนำให้ปรับแต่ง คำเตือนอาจส่งผลต่อสถานะของ Nagios และการแจ้งเตือนตามกำหนดเวลาเมื่อเปิดใช้งาน **Alert on Warnings**

โปรดอ่านค่าตัวนับที่วัดได้ควบคู่กับคำแนะนำ ค่าสะสมไม่สามารถบ่งบอกภาระงานปัจจุบันได้ ตัวนับแต่ละตัวอาจมีประวัติการรีเซ็ตที่ต่างกันและไม่ใช่สแนปชอตในเวลาเดียวกัน ค่าการเชื่อมต่อสูงสุดอาจสะท้อนถึงขีดจำกัดเดิมก่อนหน้า จำนวนคิวรีที่ช้าขึ้นอยู่กับ `long_query_time` และตัวนับตารางชั่วคราวบนดิสก์ของ MySQL อาจไม่นับไฟล์แบบ memory-mapped อัตราส่วนที่ต่ำไม่ได้พิสูจน์ว่าไม่มีคอขวด โปรดยืนยันแนวโน้มภายใต้ภาระงานที่เป็นตัวแทน ตรวจสอบแผนการประมวลผลคิวรีและการใช้การเชื่อมต่อซ้ำ และวัดการใช้งานหน่วยความจำบน**โฮสต์ฐานข้อมูล**ก่อนเปลี่ยนแปลงขนาดบัฟเฟอร์หรือขีดจำกัดการเชื่อมต่อ

หากเมตริกไม่พร้อมใช้งาน ให้ตรวจสอบการรองรับของเซิร์ฟเวอร์และสิทธิ์การเข้าถึง `SHOW GLOBAL STATUS` และ `SHOW GLOBAL VARIABLES` ของบัญชี Cacti โดย Doctor จะไม่ขอข้อมูลรับรองที่มีสิทธิ์สูงขึ้น นิยามของตัวนับอ้างอิงจาก[เอกสารอ้างอิงตัวแปรสถานะของ MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-status-variables.html) และ[เอกสารอ้างอิงตัวแปรสถานะของ MariaDB](https://mariadb.com/docs/server/server-management/variables-and-modes/server-status-variables) โดยไม่มีการใช้สคริปต์หรือโค้ดของ MySQLTuner แต่อย่างใด

ไม่จำเป็นต้องย้ายสคีมาหรือปรับการกำหนดค่าใดๆ สามารถนำไฟล์ปลั๊กอินไปติดตั้งได้ตามปกติ และการย้อนกลับไฟล์เหล่านั้นจะนำการวินิจฉัยที่เพิ่มเข้ามาออก สถานะตามกำหนดเวลาที่มีอยู่จะได้รับการอัปเดตในการทำงานครั้งถัดไป

## แนวทางการรักษาความปลอดภัย

เครื่องมือวินิจฉัยจะทำงานด้วยสิทธิ์ของโพลเลอร์หรือเว็บเซิร์ฟเวอร์ และอ่านเส้นทางไฟล์จากตารางการตั้งค่า จึงต้องระมัดระวังสิ่งที่สั่งทำงานและเปลี่ยนแปลง

- การวินิจฉัยเป็นแบบอ่านอย่างเดียว โดยจะไม่แก้ไขไฟล์ การตั้งค่า หรือข้อมูลใดๆ
- Doctor จะเรียกใช้งานไบนารีที่กำหนดค่าไว้ก็ต่อเมื่อชื่อไฟล์ตรงกับโปรแกรมที่คาดหวัง (`php`, `rrdtool`, `snmpget` หรือ `snmpwalk`) เท่านั้น มิฉะนั้นผู้ที่สามารถเขียนตารางการตั้งค่าได้อาจเลือกให้ Doctor เรียกใช้คำสั่งใดก็ได้ ชื่อไฟล์อื่นใดจะถูกรายงานเป็นคำเตือนและไม่ถูกสั่งทำงาน
- Doctor จะไม่เรียกใช้งานไบนารีที่กำหนดค่าไว้ในฐานะ root และจะรายงานหากกำลังทำงานด้วยสิทธิ์ root
- การซ่อมแซมมาจากรายการที่อนุญาตแบบตายตัว แต่ละรายการต้องเป็นการดำเนินการของผู้ดูแลระบบที่ผ่านการยืนยันตัวตนในหน้าเว็บ หรือระบุ `--yes` บน CLI และแต่ละรายการจะถูกบันทึกลงในล็อกของ Cacti

## รุ่นที่เผยแพร่

หมายเลขรุ่นเป็นไปตาม SemVer และตรงกับไฟล์ `INFO` ของปลั๊กอิน ดู[กระบวนการเผยแพร่รุ่น](../../releasing.md) สำหรับการเลือกรุ่น เกณฑ์ตรวจสอบ CI เนื้อหาแพ็กเกจ ค่าตรวจสอบความถูกต้อง และขั้นตอนการย้อนกลับ

## การติดตั้ง

ดาวน์โหลด `doctor-VERSION.tar.gz` หรือ `doctor-VERSION.zip` และ `SHA256SUMS` จาก [GitHub Releases](https://github.com/somethingwithproof/plugin_doctor/releases) ตรวจสอบค่าตรวจสอบ SHA-256 ของไฟล์เก็บถาวร จากนั้นแตกไดเรกทอรี `doctor/` ไปไว้ในไดเรกทอรี `plugins/` ของ Cacti ไฟล์เหล่านี้คือแพ็กเกจสำหรับติดตั้ง ส่วนไฟล์เก็บถาวรซอร์สโค้ดที่ GitHub สร้างให้อัตโนมัติจะมีชื่อไดเรกทอรีที่ต่างออกไป หากต้องการใช้งานโค้ดที่ยังไม่เผยแพร่จาก `develop` ให้ติดตั้งจากการดึงซอร์สโค้ด

สำหรับการติดตั้งจากซอร์สโค้ด:

โคลนหรือแตกไฟล์ที่เก็บโค้ดเป็น `plugins/doctor` ภายในชุดติดตั้ง Cacti โดยไดเรกทอรีต้องชื่อ `doctor` ไม่ใช่ `plugin_doctor`

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_doctor.git doctor
```

ติดตั้งและเปิดใช้งาน **Cacti Doctor** จาก **การกำหนดค่า > การจัดการปลั๊กอิน** จากนั้นกำหนดขอบเขตสิทธิ์ **Doctor Viewer**, **Doctor Operator** หรือ **Doctor Administrator** ผ่านสิทธิ์ผู้ใช้หรือกลุ่มของ Cacti สิทธิ์ **Cacti Doctor** ที่มีอยู่เดิมจะยังคงสิทธิ์ระดับผู้ดูแลระบบหลังการอัปเกรด รายงานจะปรากฏใต้เมนู **เครื่องมือ > Cacti Doctor**

## ภาษา

Doctor มาพร้อมคำแปลภาษาสเปน (สเปน, `es-ES`), ฝรั่งเศส (`fr-FR`), เยอรมัน (`de-DE`), จีนตัวย่อ (`zh-CN`), ฮินดี (`hi-IN`), อาหรับ (`ar-SA`) และญี่ปุ่น (`ja-JP`) โดย Cacti จะแสดงภาษาเหล่านี้เมื่อเปิดใช้การรองรับภาษา (**การกำหนดค่า > การตั้งค่า > ทั่วไป > การรองรับภาษา**) และผู้ใช้เลือกภาษา หน้าเว็บ การตั้งค่า รวมถึงข้อความและรายงานที่บรรทัดคำสั่งพิมพ์ออกมาจะใช้ภาษาของ Cacti ส่วนรายงานจากบรรทัดคำสั่งเองจะใช้ภาษาเริ่มต้นของ Cacti ซึ่งจะเป็นภาษาอังกฤษเว้นแต่คุณจะเปลี่ยนค่า

ผลลัพธ์ที่อ่านได้ด้วยเครื่องจะไม่ถูกแปล ได้แก่ รหัสการตรวจสอบ คีย์ JSON และค่าสถานะ ผลลัพธ์ของ `--format=nagios` และ `--format=prometheus` บรรทัดล็อก และหัวข้อส่วนต่างๆ ของชุดข้อมูลสนับสนุนจะยังคงเป็นภาษาอังกฤษ เพื่อให้สคริปต์และระบบเฝ้าติดตามทำงานได้ต่อไปในทุกภาษา ข้อความ `summary` และ `detail` ของแต่ละการตรวจสอบเป็นส่วนเดียวของรายงาน JSON ที่ถูกแปล

นอกจากนี้ยังมีแค็ตตาล็อกภาษาสเปนละตินอเมริกา (`es-419`) รวมอยู่ด้วย แต่ทั้ง Cacti 1.2 และ Cacti 1.3 ยังไม่มีโลแคลภาษาสเปนละตินอเมริกาให้เลือก จึงจะมีผลก็ต่อเมื่อ Cacti เพิ่มโลแคลดังกล่าว ระหว่างนี้ให้เลือกภาษาสเปน (`es-ES`) แทน

Cacti จะโหลดแค็ตตาล็อกของปลั๊กอินจาก `plugins/doctor/locales/LC_MESSAGES/<locale>.mo` โดยใช้ `doctor` เป็น text domain ทั้งในรุ่น 1.2.x และ 1.3 (รุ่น 1.3 จะระบุไดเรกทอรีปลั๊กอินผ่านเส้นทางปลั๊กอินที่กำหนดค่าได้)

## ระดับการเข้าถึง

| ขอบเขตสิทธิ์ | ความสามารถ |
|---|---|
| Doctor Viewer | อ่านสถานะการตรวจสอบตามกำหนดเวลาล่าสุด เวลาที่สังเกตการณ์ ความใหม่ของข้อมูล และประวัติผลรวมล่าสุด ไม่สามารถสั่งคำสั่งวินิจฉัย ดูรายละเอียดดิบ กำหนดค่า หรือซ่อมแซมได้ |
| Doctor Operator | เรียกใช้รายงานวินิจฉัยภายใต้ขีดจำกัดเวลาประมวลผล 120 วินาที ตรวจสอบรายละเอียดที่ปกปิดข้อมูลลับแล้ว และรับทราบผลการตรวจ ไม่สามารถเปลี่ยนการตั้งค่าหรือซ่อมแซมได้ |
| Doctor Administrator | ความสามารถของ Operator พร้อมการซ่อมแซมตามรายการที่อนุญาตและการตั้งค่า Doctor การซ่อมแซมและการตั้งค่ายังต้องมีขอบเขตสิทธิ์ Settings/System Utilities ของ Cacti ด้วย |

เมนูเครื่องมือจะเปิดหน้าสำหรับขอบเขตสิทธิ์ Doctor สูงสุดที่ผู้ใช้ได้รับ รวมถึงสิทธิ์ที่ได้รับผ่านกลุ่ม ขอบเขตสิทธิ์ Viewer และ Operator ที่เพิ่มใหม่จะไม่ได้รับสิทธิ์โดยอัตโนมัติ รหัสขอบเขตสิทธิ์เดิมยังคงผูกอยู่กับ `doctor.php` ในฐานะ Administrator เพื่อรักษาสิทธิ์การเข้าถึงของผู้ใช้และกลุ่มที่มีอยู่เดิม

ข้อมูลของ Viewer มาจากการตรวจสอบตามกำหนดเวลา ควรเปิดใช้งานการตั้งเวลาไว้ก่อนมอบสิทธิ์ Viewer หากไม่มีข้อมูลสังเกตการณ์หรือข้อมูลเกินกำหนดเวลาจะแสดงเป็น **ไม่ทราบสถานะ** และจะไม่แสดงว่าปกติ ประวัติจะเก็บจำนวนผลรวมตามกำหนดเวลา 20 ครั้งล่าสุดและไม่รวมสถานะอุปกรณ์ ส่วน Operator จะเริ่มการวินิจฉัยใหม่อย่างชัดแจ้ง การรีเฟรชหน้าเว็บตามปกติจะใช้รายงานล่าสุดในเซสชันของตน

รายละเอียดและยอดรวมของอุปกรณ์ใช้สิทธิ์การเข้าถึงอุปกรณ์ของผู้ใช้ปัจจุบัน ข้อความที่ตัดตอนมาจากล็อกยังต้องมีขอบเขตสิทธิ์ Log Administration ของ Cacti ด้วย ข้อมูลลับจะถูกปิดบังก่อนจัดเก็บรายละเอียดการวินิจฉัยในเซสชันเว็บหรือแสดงผล การเข้าถึงผ่าน CLI ยังคงควบคุมโดยบัญชีของระบบปฏิบัติการ

การรับทราบผลเป็นข้อมูลส่วนบุคคลและบันทึกไว้ในล็อกของ Cacti โดยจะมีผลเฉพาะกับผลการตรวจและหลักฐานชุดเดิมเท่านั้น หากหลักฐานเปลี่ยนแปลงต้องรับทราบผลใหม่ การรับทราบผลไม่เคยเปลี่ยนสถานะผ่าน/เตือน/ล้มเหลว ไม่ระงับการแจ้งเตือน และไม่ทำให้การตรวจสอบที่ล้มเหลวกลายเป็นปกติ เรื่องนี้แยกต่างหากจากข้อยกเว้นสำหรับคำเตือนที่ยอมรับแล้ว ซึ่งมีผลต่อนโยบายการแจ้งเตือนโดยไม่เปลี่ยนสถานะที่สังเกตได้ตามที่อธิบายไว้ด้านล่าง

ทุกการดำเนินการต้องใช้ POST และโทเค็น CSRF ที่ถูกต้อง การซ่อมแซมจะแสดงหน้ายืนยันแยกต่างหากพร้อมลิงก์ยกเลิกที่ไม่ส่งฟอร์ม และบันทึกผู้ดำเนินการพร้อมผลลัพธ์ลงในล็อกของ Cacti

## บรรทัดคำสั่ง

เรียกใช้คำสั่งเหล่านี้จากรูทของ Cacti ในฐานะผู้ใช้โพลเลอร์ของ Cacti ไม่ใช่ root:

```console
php plugins/doctor/cli/doctor.php
php plugins/doctor/cli/doctor.php --json
php plugins/doctor/cli/doctor.php --repair=runtime_directories --yes
```

ผลลัพธ์แบบข้อความจะพิมพ์หนึ่งบรรทัดต่อหนึ่งการตรวจสอบ พร้อมสถานะ หมวดหมู่ สรุป และรายละเอียด ส่วน `--json` จะพิมพ์ออบเจ็กต์ `summary` ที่มีจำนวนนับตามสถานะ และอาร์เรย์ `checks` ซึ่งแต่ละรายการมี `id`, `category`, `status`, `summary`, `detail` และจะมี `repair`/`repairable` เมื่อมีการซ่อมแซมตามรายการที่อนุญาตที่เกี่ยวข้อง

| สถานะการออก | ความหมาย |
|---|---|
| `0` | ไม่มีการตรวจสอบใดล้มเหลว หรือการซ่อมแซมที่ร้องขอสำเร็จ คำเตือนไม่เปลี่ยนสถานะการออก |
| `1` | มีการตรวจสอบอย่างน้อยหนึ่งรายการล้มเหลว หรือการซ่อมแซมที่ร้องขอไม่สำเร็จ |
| `2` | ข้อผิดพลาดในการใช้งาน: การเรียกซ่อมแซมโดยไม่ระบุ `--yes` (`--preview` ไม่จำเป็นต้องระบุ), ไม่รู้จัก ID การซ่อมแซม, ไม่รู้จักรูปแบบผลลัพธ์, ชุดค่าผสมของ `--symptom` หรือรูปแบบที่ไม่รองรับ หรือไม่พบชุดติดตั้ง Cacti |

Cacti จะเพิ่มค่า `memory_limit` ให้กับสคริปต์ CLI ทุกตัว ดังนั้นการตรวจสอบการตั้งค่ารันไทม์ของ PHP จึงมีความหมายเฉพาะบนหน้าเว็บเท่านั้น

## การตรวจสอบตามกำหนดเวลาและการแจ้งเตือน

ภายใต้ **การกำหนดค่า > การตั้งค่า > Doctor** ให้เปิดใช้งาน **เรียกใช้การตรวจสอบตามกำหนดเวลา** และเลือกรอบเวลาตั้งแต่ 15 นาทีถึงหนึ่งวัน หลังจากรอบโพลเลอร์แต่ละครั้งที่ถึงกำหนด Doctor จะเรียกใช้การตรวจสอบทั้งหมดในโปรเซสเบื้องหลัง เพื่อไม่ให้กระทบต่อเวลาทำงานของโพลเลอร์เอง

การทำงานแต่ละครั้งจะบันทึกสถานะที่สังเกตได้ของทุกการตรวจสอบ ข้อยกเว้นคำเตือนที่เปิดใช้อยู่จะมีผลต่อนโยบายการแจ้งเตือนโดยไม่เปลี่ยนแปลงค่าที่สังเกตได้นั้น เมื่อการตรวจสอบเริ่มล้มเหลวหรือหยุดล้มเหลว Doctor จะเขียนการเปลี่ยนแปลงลงในล็อกของ Cacti และหากกำหนดค่า **ที่อยู่อีเมลแจ้งเตือน** ไว้ ก็จะส่งอีเมลไปยังที่อยู่เหล่านั้นผ่านการตั้งค่าเมลของ Cacti ส่วน **แจ้งเตือนเมื่อมีคำเตือน** จะเพิ่มการแจ้งเตือนเมื่อสถานะเปลี่ยนเข้าและออกจากคำเตือน การทำงานครั้งแรกจะบันทึกเพียงค่าพื้นฐานไว้เท่านั้น

รายงานตามกำหนดเวลาจะทำงานบนโพลเลอร์หลักภายใต้ advisory lock ของฐานข้อมูล และมีขีดจำกัดเวลาของเวิร์กเกอร์ที่สองนาที Doctor จะรายงานเวลาที่เริ่มและเวลาที่เสร็จสมบูรณ์ล่าสุด เพื่อให้มองเห็นผลลัพธ์ที่ขาดหายหรือล้าสมัยได้ ผลลัพธ์จะถือว่ายังเป็นปัจจุบันภายในช่วงเวลาของรอบการตรวจสอบบวกกับหนึ่งรอบโพลลิ่งและอีกสามนาที หากการทำงานไม่เสร็จสมบูรณ์ ระบบจะลองใหม่หลังจาก 5, 10, 20 นาทีขึ้นไป จนถึงรอบเวลาปกติ การส่งแจ้งเตือนที่ล้มเหลวจะถูกเก็บไว้เพื่อลองใหม่ได้สูงสุดสามครั้งโดยเพิ่มระยะหน่วงขึ้นเรื่อยๆ หลังจากนั้นให้แก้ไขการตั้งค่าเมลของ Cacti และเรียกใช้ `php plugins/doctor/cli/doctor.php --scheduled --retry-alerts` ในฐานะผู้ใช้โพลเลอร์ การที่เซิร์ฟเวอร์เมลรับข้อความไว้ไม่ได้ยืนยันว่าข้อความถึงกล่องจดหมายปลายทาง

แท็บเดียวกันนี้ใช้กำหนดเกณฑ์สำหรับเวลาทำงานของโพลเลอร์ (80% ของรอบเวลา) พื้นที่ดิสก์ว่างของ RRA (เตือนเมื่อต่ำกว่า 10%, ล้มเหลวเมื่อต่ำกว่า 2%) ความคลาดเคลื่อนของนาฬิกาฐานข้อมูล (เตือนเมื่อเกิน 5 วินาที, ล้มเหลวเมื่อเกิน 60 วินาที) และขนาดล็อกของ Cacti (100 MB) ค่าที่ว่างเปล่าหรือไม่ถูกต้องจะย้อนกลับไปใช้ค่าเริ่มต้นเหล่านี้

## การผสานรวมกับระบบเฝ้าติดตาม

```console
php plugins/doctor/cli/doctor.php --format=nagios
php plugins/doctor/cli/doctor.php --format=prometheus > /var/lib/node_exporter/textfile/cacti_doctor.prom
```

`--format=nagios` จะพิมพ์ผลลัพธ์หนึ่งบรรทัดสถานะพร้อมข้อมูลประสิทธิภาพ และออกด้วยรหัส `0` (OK), `1` (WARNING) หรือ `2` (CRITICAL) เพื่อให้ Nagios, Icinga หรือระบบที่เข้ากันได้เรียกใช้งานได้โดยตรง ส่วน `--format=prometheus` จะเขียนรูปแบบข้อความของ Prometheus สำหรับ textfile collector ของ node_exporter ได้แก่ `cacti_doctor_check_status` ต่อหนึ่งการตรวจสอบ (0 ผ่านหรือคำเตือนที่ยอมรับแล้ว, 1 คำเตือนที่ต้องดำเนินการ, 2 ล้มเหลว), `cacti_doctor_check_observed_status` ก่อนใช้ข้อยกเว้น, `cacti_doctor_check_accepted`, `cacti_doctor_checks` แยกตามสถานะ และ `cacti_doctor_last_run_timestamp_seconds` แถวการตรวจสอบใน JSON มีฟิลด์ `assessment` โดย `not_assessed` หมายถึงการตรวจสอบไม่สามารถหาข้อสรุปจากข้อมูลที่มีอยู่ได้

## ชุดข้อมูลสนับสนุน

```console
php plugins/doctor/cli/doctor.php --bundle=/tmp/cacti-doctor.txt
```

ชุดข้อมูลนี้เป็นไฟล์ข้อความไฟล์เดียวที่ประกอบด้วยเวอร์ชันของ Doctor, Cacti, PHP, ระบบปฏิบัติการ และฐานข้อมูล สถิติของโพลเลอร์และ Boost รายงานฉบับเต็ม และล็อกของ Cacti 200 บรรทัดล่าสุด ค่าที่อยู่ถัดจากชื่อรหัสผ่าน, secret, token, community และ key จะถูกปิดบังไว้ Doctor จะสร้างไฟล์ให้อ่านได้เฉพาะเจ้าของไฟล์เท่านั้น และปฏิเสธที่จะเขียนทับไฟล์ที่มีอยู่เดิม โปรดตรวจสอบเนื้อหาก่อนนำไปเผยแพร่ที่ใดๆ

## นโยบายการซ่อมแซม

Doctor มีการซ่อมแซมหนึ่งรายการคือ `runtime_directories` ซึ่งจะสร้างไดเรกทอรีรันไทม์ของ Cacti ที่ขาดหายไป และเพิ่มบิตสิทธิ์อ่าน เขียน และประมวลผลสำหรับเจ้าของ โดยไม่ลบสิทธิ์ที่มีอยู่เดิม

การซ่อมแซมนี้กำหนดเป้าหมายไปที่ `$cache_path`, `$log_path` และ `$rra_path` บน Cacti 1.3 หรือไดเรกทอรี `cache`, `log` และ `rra` ของการติดตั้งในกรณีอื่น โดยจะข้ามไดเรกทอรีที่สามารถเขียนได้อยู่แล้ว ปฏิเสธไดเรกทอรีที่อยู่นอกการติดตั้ง Cacti (เช่น ไดเรกทอรีบันทึกภายใต้ `/var/log`) ปฏิเสธลิงก์สัญลักษณ์ และปฏิเสธการทำงานในฐานะ root นอกจากนี้จะไม่ติดตาม `path_cactilog` ดังนั้นไฟล์บันทึกที่กำหนดค่าไว้ภายในไดเรกทอรีโค้ดจึงไม่สามารถเปลี่ยนเส้นทางการซ่อมแซมไปยังตำแหน่งนั้นได้ อย่างไรก็ตาม การวินิจฉัยยังคงตรวจสอบไดเรกทอรีของไฟล์บันทึกที่กำหนดค่าไว้ในทุกรุ่น

ระบบจะไม่เปลี่ยนความเป็นเจ้าของ เรียกใช้คำสั่งเชลล์ เขียนการกำหนดค่าใหม่ หรือแก้ไขข้อมูลแอปพลิเคชัน Cacti การซ่อมแซมใหม่แต่ละรายการต้องประกอบด้วยการวินิจฉัย ตัวจัดการที่อยู่ในรายการอนุญาต การยืนยัน การบันทึกการตรวจสอบ และการทดสอบ

## การตรวจสอบอาการ

ผู้ปฏิบัติงานและผู้ดูแลระบบสามารถเลือก **ตรวจสอบอาการ** ได้ในหน้า Doctor กฎเดียวกันนี้ยังใช้งานได้ผ่าน `--symptom=graphs_stopped`, `slow_polling`, `devices_missing` หรือ `alerts_missing` พร้อมเอาต์พุตแบบข้อความหรือ JSON ชุดข้อมูลสำหรับฝ่ายสนับสนุนจะรวมผลการตรวจสอบอาการที่เกี่ยวข้องไว้ด้วย

สาเหตุที่เป็นไปได้แต่ละรายการจะแสดงการตรวจสอบที่สังเกตพบและขั้นตอนการตรวจยืนยันถัดไป สาเหตุที่เป็นไปได้เป็นเพียงสมมติฐาน ไม่ใช่สาเหตุรากเหง้าที่ยืนยันแล้ว การสังเกตที่ขาดหายไป ยังไม่ถูกประเมิน หรือล้าสมัย จะไม่ถูกใช้เป็นข้อสรุปสาเหตุ การตรวจสอบผ่านเว็บจะใช้รายงานที่กรองตามสิทธิ์ ส่วนรายงาน CLI จะใช้สิทธิ์การเข้าถึงของบัญชีระบบปฏิบัติการ

## ความสดใหม่ของการอัปเดต RRD

`filesystem.rrd_stale` จะตรวจสอบแหล่งข้อมูลที่ใช้งานอยู่สูงสุด 500 รายการ โดยไม่รวมอุปกรณ์ที่ถูกปิดใช้งานและอุปกรณ์ที่หยุดทำงาน สำหรับการติดตั้งขนาดใหญ่ ตัวอย่างจะเปลี่ยนไปทุกชั่วโมง ดังนั้นการเรียกใช้ซ้ำจึงครอบคลุมไฟล์ที่แตกต่างกัน ระบบจะเปรียบเทียบเวลาแก้ไขไฟล์กับค่าที่มากที่สุดระหว่างช่วงเวลาของตัวดึงข้อมูล สเต็ป RRD ต้นทาง และสเต็ปโปรไฟล์ คูณด้วย **ช่วงเวลา RRD ค้าง** (ค่าเริ่มต้น 3) โดยจะแสดงไฟล์ที่ค้างเก่าที่สุดสามไฟล์และจำนวนอุปกรณ์ที่ได้รับผลกระทบ ผลลัพธ์บนเว็บจะแสดงเฉพาะอุปกรณ์ที่ได้รับอนุญาตเท่านั้น

`filesystem.rrd_files` เป็นการตรวจสอบการมีอยู่ของไฟล์แยกต่างหาก โดยจะค้นหาไฟล์ RRD ของแหล่งข้อมูลที่ใช้งานอยู่สูงสุด 5,000 รายการ รวมถึงรายการบนอุปกรณ์ที่ถูกปิดใช้งานหรือหยุดทำงาน และใช้ตัวอย่างรายชั่วโมงชุดเดียวกัน

Boost จะบวกค่าเผื่อการเขียนดิสก์เพิ่มเป็นสองเท่าของช่วงเวลาการล้างข้อมูลที่กำหนดค่าไว้ สำหรับตัวเขียนแบบหน่วงเวลารูปแบบอื่น ให้กำหนดค่า **ค่าเผื่อการเขียน RRD แบบหน่วงเวลา (วินาที)** การมี `RRDCACHED_ADDRESS` โดยไม่มีค่าเผื่อ หรือช่วงเวลา Boost ที่ไม่ถูกต้อง จะทำให้ได้ผลลัพธ์แบบยังไม่ถูกประเมิน Doctor จะไม่ล้างแคชเพื่อทำการตรวจสอบนี้ เวลาแก้ไขไฟล์เป็นหลักฐานของกิจกรรมบนดิสก์ ไม่ใช่ข้อพิสูจน์ว่าการเก็บข้อมูลสำเร็จ การแคชภายนอกที่ Doctor ไม่สามารถตรวจจับได้ต้องกำหนดค่าไว้อย่างชัดเจน

ไฟล์ที่หายไป อ่านไม่ได้ และมีวันที่ในอนาคตจะถูกนับรวมไว้ในรายละเอียด ผลลัพธ์จะเป็นแบบยังไม่ถูกประเมินเฉพาะเมื่อไม่มีไฟล์ตัวอย่างใดที่อ่านได้ ผลลัพธ์จากการสุ่มตัวอย่างจะระบุว่าครอบคลุมเพียงบางส่วนของการติดตั้งเท่านั้น การผ่านการตรวจสอบไม่ได้ครอบคลุมถึงไฟล์ที่ไม่ได้สุ่มตัวอย่าง

## การแสดงตัวอย่างการซ่อมแซมและประวัติการตรวจสอบ

หน้าการซ่อมแซมสำหรับผู้ดูแลระบบจะแสดงแต่ละพาธที่ได้รับผลกระทบ การดำเนินการที่เสนอ สิทธิ์ปัจจุบัน และสิทธิ์เป้าหมาย การอนุมัติจะผูกติดกับตัวอย่างนั้น ผู้ใช้ที่ดำเนินการ และอายุการใช้งานห้านาที การยืนยันจะใช้ตัวอย่างนั้นทันที หากระบบไฟล์มีการเปลี่ยนแปลงจะต้องสร้างตัวอย่างใหม่ การทำงานในฐานะ root พาธที่อยู่นอกการติดตั้ง ลิงก์ที่ต้องซ่อมแซม และสิทธิ์ของระบบไฟล์ที่ไม่เป็นไปตามเงื่อนไขจะไม่อนุญาตให้ดำเนินการอนุมัติ

`--repair=runtime_directories --preview` จะพิมพ์แผน JSON แบบอ่านอย่างเดียว `--repair=runtime_directories --yes` จะอนุมัติแผน CLI ที่คำนวณขึ้นใหม่และตรวจสอบซ้ำก่อนดำเนินการ บัญชี CLI ต้องได้รับสิทธิ์ในการซ่อมแซมการติดตั้งอยู่แล้ว โดยจะไม่สืบทอดบทบาทจากเว็บ

ต้องบันทึกระเบียน `repair.started` แบบมีโครงสร้างก่อนที่จะมีการเปลี่ยนแปลงระบบไฟล์ใดๆ ระเบียน `repair.completed` ที่เชื่อมโยงกันจะเก็บสแนปช็อตหลังการซ่อมแซมและผลการตรวจยืนยัน การดำเนินการที่ถูกขัดจังหวะจะทิ้งระเบียนเริ่มต้นไว้สำหรับการตรวจสอบ ความล้มเหลวในการบันทึกการตรวจสอบเมื่อเสร็จสิ้นจะถูกรายงานเป็นความล้มเหลว แม้ว่าจะมีการเปลี่ยนแปลงระบบไฟล์เกิดขึ้นแล้วก็ตาม Doctor จะเพิ่มสิทธิ์เจ้าของและสร้างไดเรกทอรีเท่านั้น และจะไม่พยายามย้อนกลับอัตโนมัติ

ผู้ดูแลระบบที่มีสิทธิ์การตั้งค่า/ยูทิลิตีระบบของ Cacti สามารถอ่านรายการตรวจสอบล่าสุด 20 รายการได้บนหน้า Doctor ปลั๊กอินจะเก็บระเบียนล่าสุด 200 รายการไว้ใน `plugin_doctor_audit` และบันทึกของ Cacti ยังบันทึกรหัส การดำเนินการ และผู้ดำเนินการด้วย เพย์โหลดการตรวจสอบจะถูกปกปิดข้อมูลสำคัญ

## คำเตือนที่ยอมรับแล้ว

ผู้ดูแลระบบที่มีสิทธิ์การตั้งค่า/ยูทิลิตีระบบของ Cacti สามารถสร้าง **ข้อยกเว้นคำเตือน** จากคำเตือนที่เพิ่งประเมินผลบนหน้า Doctor ได้ ข้อยกเว้นต้องระบุผู้รับผิดชอบ เหตุผล และวันที่ทบทวนตามเวลา UTC ภายใน 90 วัน โดยจะหมดอายุเวลาเที่ยงคืน UTC ณ จุดเริ่มต้นของวันที่ดังกล่าว สามารถกำหนดค่าข้อยกเว้นได้สูงสุด 100 รายการ รายการจะแสดงรายการที่หมดอายุและรหัสที่ไม่มีอยู่ในรายงานปัจจุบัน รวมถึงอนุญาตให้ลบออกได้

คำเตือนที่สังเกตพบจะยังคงแสดงอยู่ พร้อมผู้รับผิดชอบ เหตุผล และวันหมดอายุในรายละเอียดการวินิจฉัย JSON จะคงสถานะที่สังเกตพบไว้และเพิ่มเมตาดาตา `accepted` และ `acceptance` Nagios จะไม่นับรวมคำเตือนที่ยอมรับแล้วที่ยังมีผลอยู่ในระดับความรุนแรงของสถานะออก แต่จะระบุชื่อไว้ในเอาต์พุต Prometheus จะส่งออกทั้งระดับความรุนแรงที่สังเกตพบและระดับความรุนแรงที่ต้องดำเนินการ สถานะออกของ CLI ทั่วไปยังคงไม่เปลี่ยนแปลง กล่าวคือ คำเตือนออกด้วยศูนย์อยู่แล้ว และความล้มเหลวออกด้วยหนึ่ง

การแจ้งเตือนคำเตือนตามกำหนดเวลาจะถูกระงับไว้ในขณะที่ข้อยกเว้นมีผลบังคับใช้ การหมดอายุหรือการลบออกจะทำให้คำเตือนที่ยังคงอยู่กลับมามีสิทธิ์แจ้งเตือนคำเตือนอีกครั้ง การเปลี่ยนสถานะเป็นความล้มเหลวและการกู้คืนจากความล้มเหลวยังคงมีสิทธิ์ได้รับการแจ้งเตือน ผลลัพธ์ที่ยังไม่ถูกประเมินหรือความล้มเหลวไม่สามารถยอมรับได้ การรับทราบส่วนบุคคลแยกต่างหากและไม่ได้ระงับการแจ้งเตือนใดๆ การสร้างและลบข้อยกเว้นเป็นธุรกรรมร่วมกับระเบียนการตรวจสอบ

การอัปเกรดจะสร้าง `plugin_doctor_audit` และ `plugin_doctor_acceptance` โดยไม่เปลี่ยนแปลงข้อมูลแอปพลิเคชัน Cacti โปรดส่งออกประวัติใดๆ ที่คุณต้องการก่อนถอนการติดตั้ง เนื่องจากการถอนการติดตั้งจะลบทั้งสองตารางของปลั๊กอินและการตั้งค่าของปลั๊กอินออก การย้อนกลับไฟล์ปลั๊กอินจะยังคงเหลือตารางไว้สำหรับการตรวจสอบ แต่เวอร์ชันที่เก่ากว่าจะไม่รองรับข้อยกเว้นคำเตือน

## ข้อกำหนด

| Cacti | PHP | หมายเหตุ |
|---|---|---|
| 1.2.20 | 5.4 หรือใหม่กว่า | โค้ดของ Doctor เองเข้ากันได้กับ PHP 5.4 เพื่อให้สามารถวินิจฉัยระบบเดิมก่อนการอัปเกรดได้ |
| 1.2.31 | 8.0 หรือใหม่กว่า | `composer.json` ของ Cacti กำหนดให้ใช้ `>=8.0` |
| 1.2.x ปัจจุบัน | 8.2 หรือใหม่กว่า | `composer.json` ของ Cacti กำหนดให้ใช้ `>=8.2` |
| `develop` (1.3) | 8.3 หรือใหม่กว่า | `composer.json` ของ Cacti กำหนดให้ใช้ `^8.3` |

แถว **ความเข้ากันได้ของ PHP กับ Cacti ที่ติดตั้ง** จะเปรียบเทียบเวอร์ชัน PHP ที่กำลังทำงานอยู่กับข้อกำหนด PHP ใน `composer.json` ระดับรากของ Cacti เอง รวมถึงขอบเขตบนของข้อจำกัดแบบคาเรต เช่น `^8.3` ไฟล์ปฏิบัติการ PHP CLI ที่กำหนดค่าไว้จะถูกตรวจสอบเทียบกับข้อกำหนดเดียวกัน Doctor รู้จักรูปแบบข้อจำกัด `>=` และ `^` ที่ใช้โดยแพ็กเกจ Cacti เหล่านี้ ข้อกำหนดที่อ่านไม่ได้ รูปแบบไม่ถูกต้อง ขาดหายไป หรือไม่รู้จัก จะทำให้เกิดคำเตือน ส่วนการติดตั้ง Cacti 1.2.20–1.2.30 ที่ไม่มีไฟล์รายการจะยังคงใช้เกณฑ์ขั้นต่ำของตัวติดตั้ง PHP 5.4 ตามเอกสาร ความเข้ากันได้กับ PHP 5.4 ของ Doctor เองไม่ได้ยืนยันความเข้ากันได้กับการติดตั้ง Cacti เวอร์ชันที่ใหม่กว่า

แถว **การสนับสนุนด้านความปลอดภัยจากต้นน้ำของ PHP** จะตอบคำถามแยกต่างหากว่า สาขาการเผยแพร่ PHP นั้นยังคงได้รับการแก้ไขด้านความปลอดภัยจากโครงการ PHP อยู่หรือไม่ โดยจะรายงานวันที่สิ้นสุดการสนับสนุนด้านความปลอดภัยที่เผยแพร่ของสาขานั้น และแจ้งเตือนเมื่อพ้นวันที่ดังกล่าว ตัวอย่างเช่น PHP 8.1 อาจตรงตามข้อกำหนดรันไทม์ของการติดตั้ง Cacti เวอร์ชันเก่า แต่ไม่ได้รับการแก้ไขด้านความปลอดภัยจากต้นน้ำอีกต่อไป ผลลัพธ์ที่ผ่านไม่ได้หมายความว่ารุ่นแพตช์ที่ติดตั้งอยู่เป็นปัจจุบัน และ Doctor ไม่สามารถระบุได้ว่าผู้จำหน่ายระบบปฏิบัติการได้จัดเตรียมการแก้ไขแบบย้อนหลังให้หรือไม่

วันที่สนับสนุนถูกจัดเตรียมมาพร้อมกับ Doctor จาก [ตารางการสนับสนุน PHP](https://www.php.net/supported-versions.php) และ [รายการสิ้นสุดอายุการใช้งาน](https://www.php.net/eol.php) โดยตรวจสอบล่าสุดเมื่อ 2026-11-08 สาขาที่ไม่รู้จักและรุ่นก่อนเผยแพร่จะทำให้เกิดคำเตือนแทนที่จะถือว่าผ่าน ไม่มีการส่งคำขอเครือข่ายใดๆ ระหว่างการวินิจฉัย โปรดอัปเดตข้อมูลการสนับสนุนของ Doctor เมื่อ PHP เผยแพร่ตารางเวลาใหม่ รหัส JSON/การเฝ้าติดตามที่มีอยู่เดิมคือ `php.version` และ `php.security_baseline` ยังคงไม่เปลี่ยนแปลง

## การพัฒนา

ชุดการทดสอบย่อยใช้ Pest และทำงานบน PHP 8.2 หรือใหม่กว่า:

```console
composer install
composer test
```

การทดสอบจะแทนที่ฟังก์ชันของ Cacti ที่ Doctor เรียกใช้ด้วยฟังก์ชันจำลองขนาดเล็กใน `tests/CactiStubs.php` จึงสามารถทำงานได้โดยไม่ต้องติดตั้ง Cacti

GitHub Actions จะเรียกใช้การตรวจสอบสี่ประเภทในทุกการ push และ pull request:

- `php -l` กับไฟล์ PHP ทุกไฟล์ภายใต้ PHP 5.4, 5.6, 7.0, 7.1, 7.4 และ 8.0 ถึง 8.4
- ชุดการทดสอบย่อยบน PHP 8.2, 8.3 และ 8.4
- `locales/build_gettext.sh --check` ซึ่งจะล้มเหลวหากแม่แบบการแปลล้าสมัย แค็ตตาล็อกไม่สมบูรณ์หรือคลุมเครือ หรือแค็ตตาล็อกที่คอมไพล์แล้วแตกต่างจากต้นฉบับ
- งานทดสอบการรวมระบบเจ็ดงานที่ติดตั้ง Cacti 1.2.20 สาขา 1.2.x ปัจจุบัน และ `develop` ร่วมกับ MySQL และ MariaDB โดยใช้ทั้ง cmd.php และ Spine แต่ละงานจะติดตั้งและเปิดใช้งานปลั๊กอิน เรียกใช้รายงาน CLI ฉบับเต็ม และตรวจสอบสคีมาของรายงาน ยอดรวมสรุป สถานะที่คาดหวัง และชุดความล้มเหลวที่แน่นอน จากนั้นจะทำให้พาธของไบนารีและการประทับเวลาของตัวดึงข้อมูลเสียหาย ยืนยันว่าทั้งสองอย่างถูกรายงาน กู้คืนกลับ ทดสอบการซ่อมแซมและการยืนยัน และรันการปิดใช้งาน เปิดใช้งาน ถอนการติดตั้ง และติดตั้งใหม่ รายงาน JSON จะถูกเก็บไว้เป็นอาร์ติแฟกต์เมื่องานล้มเหลว

## การมีส่วนร่วม

ส่ง pull request ไปที่ `develop` รักษาความเข้ากันได้ของไฟล์สำหรับใช้งานจริงกับ PHP 5.4 และใช้รูปแบบโค้ดของ Cacti ได้แก่ การย่อหน้าด้วยแท็บ สตริงแบบอัญประกาศเดี่ยว และฟังก์ชันช่วยของ Cacti เช่น `read_config_option()` และ `db_fetch_cell()` เพิ่มการทดสอบยูนิตสำหรับการเปลี่ยนแปลงพฤติกรรมแต่ละรายการ ลงนามรับรองคอมมิตของคุณ (`git commit -s`) และเพิ่มรายการใน `CHANGELOG.md`

### การแปลภาษา

ครอบข้อความที่ผู้ใช้มองเห็นทุกข้อความด้วย `__('...', 'doctor')` (หรือ `__n()`, `__x()`, `__esc()`) และสำหรับประโยคที่มีค่าตัวแปร ให้ใช้สตริงรูปแบบเดียวพร้อมตัวแทนตำแหน่งตามลำดับ `%s`/`%d` แทนการต่อสตริงเป็นส่วน ๆ ฟังก์ชัน `__()` ของ Cacti จะจัดรูปแบบข้อความเฉพาะเมื่อมีตัวระบุรูปแบบเท่านั้น และไม่รองรับรูปแบบระบุตำแหน่งอย่าง `%1$s` นอกจากนี้ยังแปลง `%%` เป็น `%` ก่อนการจัดรูปแบบ ดังนั้นอย่าใส่เครื่องหมายเปอร์เซ็นต์จริงลงในข้อความ แต่ให้ส่งค่าพร้อมเครื่องหมายเป็นอาร์กิวเมนต์แทน (`__('Usage: %s', '50%', 'doctor')`) ข้อความบันทึก (log) ให้คงเป็นภาษาอังกฤษไว้ โดยใช้ `doctor_repair_message()` สำหรับข้อความการซ่อมแซม และใช้ `doctor_n_()` สำหรับข้อความที่ถูกบันทึกและแปลเฉพาะในจุดที่แสดงผล ส่วนรหัสการตรวจสอบ คีย์ JSON คำหลักสถานะ ผลลัพธ์การเฝ้าระวัง และข้อความบันทึก ให้คงไว้โดยไม่ต้องแปล

`locales/build_gettext.sh` จะสร้างเทมเพลต `locales/po/cacti.pot` ขึ้นมาใหม่ ผสานเข้ากับแค็ตตาล็อกแต่ละไฟล์ใน `locales/po/<locale>.po` และคอมไพล์เป็น `locales/LC_MESSAGES/<locale>.mo` จากนั้นให้คอมมิตทั้งสามไฟล์นี้ โดย CI จะรันคำสั่ง `sh locales/build_gettext.sh --check` ซึ่งจะล้มเหลวหากเทมเพลตล้าสมัย แค็ตตาล็อกขาดรายการหรือมีรายการแบบ fuzzy ตัวแทนตำแหน่งไม่ตรงกัน หรือไฟล์ที่คอมไพล์แล้วไม่เป็นปัจจุบัน ดังนั้นเมื่อมีการแก้ไขข้อความ จึงต้องอัปเดตคำแปลใน pull request เดียวกันด้วย ทั้งนี้จำเป็นต้องใช้ GNU gettext (`xgettext`, `msgmerge`, `msgfmt`, `msgunfmt`) สำหรับภาษาใหม่ให้สร้างไฟล์ `<locale>.po` ใหม่โดยตั้งชื่อตามรูปแบบโลแคลของ Cacti (เช่น `pt-BR`)
