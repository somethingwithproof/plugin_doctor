Cacti Doctor إضافة لـ Cacti تشخّص التثبيت في مرور واحد وتطبّق إصلاحات صغيرة فقط عندما يطلبها مسؤول.

**الحالة: قيد التطوير، قبل 1.0.** أحدث إصدار هو [0.6.0](https://github.com/somethingwithproof/plugin_doctor/releases/tag/v0.6.0). يضيف هذا الإصدار الوصول المحدد بالأدوار والتشخيص الموجّه وفحوص حداثة RRD محددة النطاق ومعاينات الإصلاح وسجل التدقيق واستثناءات التحذيرات المقبولة والترجمات. راجع [CHANGELOG.md](../../../CHANGELOG.md) للتفاصيل.

<a id="screenshots"></a>
## لقطات الشاشة

التشخيصات وإعدادات الجدولة في تثبيت تجريبي معزول لـ Cacti 1.2.31 يعمل على PHP 8.3.36، بما في ذلك فحوص توافق PHP مع Cacti ودعم الأمان من المصدر الأصلي وصحة قاعدة البيانات. تصف التحذيرات والإخفاقات المعروضة بيئة العرض تلك.

![جدول تشخيص Doctor بنتائج النجاح والتحذير والفشل](../../screenshots/diagnostics.png)

![إعدادات جدولة Doctor والتنبيهات والعتبات](../../screenshots/settings.png)

تظهر مشاكل Cacti عادةً كأعراض: رسوم فارغة، مستطلع توقف، أو إضافة لا تُثبّت. غالبًا يكون السبب متطلبًا أساسيًا تغيّر، مثل امتداد PHP مفقود من نسخة CLI، أو دليل سجلات لا يستطيع المستطلع الكتابة فيه، أو مسار RRDtool يشير إلى ملف تنفيذي خاطئ، أو قاعدة بيانات بلا جداول مناطق زمنية. يفحص Doctor هذه المتطلبات مباشرةً ويصف كلًا منها بالنجاح أو التحذير أو الفشل، مع جملة تشرح ما وجده. يتوفر التقرير نفسه على صفحة ويب وفي سطر الأوامر وكـ JSON للمراقبة.

## ما يفحصه

| المجال | الفحوص |
|---|---|
| Doctor | ما إذا كان Doctor نفسه يعمل بصلاحيات root، مما يجعل فحوص الأذونات تصف الحساب الخطأ |
| Cacti وPHP | إصدار Cacti، ترقية لم يكملها المثبت، إضافات مفعّلة ملفاتها مفقودة، توافق PHP مع حزمة Cacti المثبّتة، وحالة الدعم الأمني لـ PHP من المصدر الأصلي |
| امتدادات PHP | الامتدادات المطلوبة في PHP للويب وPHP CLI الذي يستخدمه المستطلع، والميزات الموصى بها |
| إعدادات PHP | `memory_limit` و`max_execution_time` و`date.timezone`، وفق توصيات Cacti |
| قاعدة البيانات | الاتصال، إصدار الخادم مقارنة بتوصية Cacti، محارف UTF-8، جداول المناطق الزمنية، الجداول الأساسية، انحراف الساعة عن مضيف PHP، وإعدادات InnoDB التي يعدّها Cacti أخطاء |
| صحة قاعدة البيانات | سعة الاتصالات، قراءات مخزن الذاكرة، الجداول المؤقتة على القرص، إنشاء خيوط الاتصال، العبارات البطيئة، وانتظار مخزن سجل InnoDB، مع اقتراحات ضبط تعتمد على عبء العمل |
| نظام الملفات | أدلة cache وlog وRRA القابلة للكتابة؛ مساحة ملفات RRD؛ مصادر بيانات نشطة دون ملف RRD أو بتحديثات متأخرة؛ عدم إتاحة قراءة `include/config.php` للجميع؛ سجل Cacti قابل للكتابة وغير متضخم |
| الملفات التنفيذية | PHP CLI وRRDtool و`snmpget` و`snmpwalk` وSpine عندما يكون المستطلع المضبوط، بما في ذلك الإصدارات حين يحدد Cacti إصدارًا |
| السجل | الأخطاء في أحدث أسطر سجل Cacti، مع الرسالة الأكثر تكرارًا |
| الأجهزة | الأجهزة المفعّلة المتوقفة أو المتعافية، والأجهزة الثلاثة الأطول توقفًا مع آخر خطأ لها، والفشل عندما تتوقف غالبية الأجهزة معًا |
| المستطلع | النوع والفاصل، الوقت منذ اكتمال المستطلع الرئيسي، مدة التشغيل مقارنة بالفاصل، إخراج لم يصل إلى RRD، مستطلعات بعيدة توقفت عن الإبلاغ، Boost متوقف، وإعداد Spine يشير إلى قاعدة بيانات مختلفة |

لكل فحص معرّف ثابت مثل `database.timezone` أو `binary.rrdtool`، كي تستطيع البرامج النصية تمييز النتائج الفردية.

<a id="database-health-advice"></a>
## نصائح صحة قاعدة البيانات

يقرأ محلل PHP الأصلي في Doctor مجموعة ثابتة من عدادات MySQL أو MariaDB العامة عبر اتصال قاعدة بيانات Cacti القائم. ينفّذ استعلامين للقراءة فقط لكل تقرير، ولا يتطلب بيانات اعتماد أو ملفًا تنفيذيًا إضافيًا، ولا يغيّر إعدادات قاعدة البيانات مطلقًا. تظهر هذه الفحوص في تقرير الويب وCLI وJSON وإخراج المراقبة وحزمة الدعم وتتبع الحالة المجدول.

| معرّف الفحص | محفّز التحقيق |
|---|---|
| `database.health_sample` | أقل من 24 ساعة منذ البدء أو `FLUSH STATUS`، أو زمن تشغيل غير متاح أو غير متسق |
| `database.connection_capacity` | الاتصالات الحالية أو الذروة المسجّلة تبلغ 80% على الأقل من `max_connections` الحالي |
| `database.buffer_pool_reads` | نسبة `Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests` لا تقل عن 1%، مع 10,000 طلب قراءة على الأقل |
| `database.temporary_tables` | نسبة `Created_tmp_disk_tables / Created_tmp_tables` لا تقل عن 25%، مع 1,000 جدول مؤقت على الأقل |
| `database.thread_cache` | نسبة `Threads_created / Connections` لا تقل عن 5%، مع 1,000 محاولة اتصال على الأقل و`thread_handling=one-thread-per-connection` |
| `database.slow_queries` | نسبة `Slow_queries / Queries` لا تقل عن 1%، مع 1,000 عبارة على الأقل |
| `database.redo_log_waits` | قيمة `Innodb_log_waits` غير صفرية |

هذه عتبات تحقيق يضعها Doctor، وليست أهداف إعداد يفرضها المورّد. باستثناء سعة الاتصالات، تتطلب النصائح التراكمية نافذة المراقبة السابقة. تنتج العدادات المفقودة أو غير الصحيحة أو المكررة أو المتضخمة، والنشاط غير الكافي، وأوضاع الخيوط غير المدعومة تحذيرات بدلًا من حكم بالصحة أو توصية بالضبط. يمكن أن تؤثر التحذيرات في حالة Nagios والتنبيهات المجدولة عند تفعيل **Alert on Warnings**.

اقرأ العدادات المقاسة والاقتراح معًا. القيم التراكمية لا تثبت الحمل الحالي؛ قد تختلف تواريخ إعادة ضبط العدادات، وليست لقطة ذرية. قد تعكس ذروة الاتصالات حدًا سابقًا. تعتمد أعداد الاستعلامات البطيئة على `long_query_time`، وقد يستثني عداد الجداول المؤقتة على القرص في MySQL ملفات معيّنة للذاكرة. النسبة المنخفضة لا تثبت غياب عنق زجاجة. تأكد من الاتجاهات تحت عبء ممثل، وراجع خطط الاستعلام وإعادة استخدام الاتصالات، وقِس الذاكرة على **مضيف قاعدة البيانات** قبل تغيير المخازن أو حدود الاتصالات.

إذا لم تتوفر المقاييس، تحقق من دعم الخادم ووصول حساب Cacti إلى `SHOW GLOBAL STATUS` و`SHOW GLOBAL VARIABLES`؛ لا يطلب Doctor بيانات اعتماد مرتفعة الصلاحيات. تأتي تعريفات العدادات من [مرجع متغيرات الحالة في MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-status-variables.html) و[مرجع MariaDB](https://mariadb.com/docs/server/server-management/variables-and-modes/server-status-variables). لا تُستخدم شيفرة أو برامج نصية من MySQLTuner.

لا يلزم ترحيل المخطط أو الإعدادات. انشر ملفات الإضافة كالمعتاد؛ يؤدي إرجاعها إلى إزالة التشخيصات المضافة. تُحدّث الحالة المجدولة القائمة في التشغيل التالي.

<a id="how-it-stays-safe"></a>
## كيف يحافظ على الأمان

تعمل أداة التشخيص بصلاحيات المستطلع أو خادم الويب وتقرأ المسارات من جدول الإعدادات، لذا يجب أن تضبط ما تنفّذه وتعدّله.

- التشخيصات للقراءة فقط. لا تغيّر الملفات أو الإعدادات أو البيانات مطلقًا.
- لا ينفّذ Doctor ملفًا ثنائيًا مضبوطًا إلا عندما يطابق اسمه البرنامج المتوقع (`php` أو `rrdtool` أو `snmpget` أو `snmpwalk`). وإلا لأمكن لأي شخص يكتب في جدول الإعدادات اختيار ما ينفّذه Doctor. يُبلّغ عن أي اسم آخر كتحذير ولا يُنفّذ.
- لا ينفّذ Doctor الملفات الثنائية المضبوطة بصلاحيات root، ويبلّغ عندما يعمل نفسه بهذه الصلاحيات.
- تأتي الإصلاحات من قائمة سماح ثابتة. يحتاج كل منها إلى إجراء مسؤول مصادق عليه في الواجهة أو `--yes` في CLI، ويُسجّل كل منها في سجل Cacti.

<a id="installation"></a>
## التثبيت

نزّل `doctor-VERSION.tar.gz` أو `doctor-VERSION.zip` و`SHA256SUMS` من [GitHub Releases](https://github.com/somethingwithproof/plugin_doctor/releases). تحقق من مجموع SHA-256 للأرشيف، ثم استخرج دليل `doctor/` إلى دليل `plugins/` في Cacti. هذه الحزم قابلة للتثبيت؛ أرشيفات المصدر التلقائية من GitHub لها اسم دليل مختلف. لتشغيل عمل غير منشور من `develop`، ثبّت من نسخة مصدر.

لنسخ المصدر:

استنسخ المستودع أو فكّه باسم `plugins/doctor` داخل تثبيت Cacti. يجب أن يكون اسم الدليل `doctor`، وليس `plugin_doctor`.

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_doctor.git doctor
```

ثبّت **Cacti Doctor** وفعّله من **Configuration > Plugin Management**، ثم امنح نطاق **Doctor Viewer** أو **Doctor Operator** أو **Doctor Administrator** عبر أذونات مستخدمي Cacti أو مجموعاته. تحتفظ منح **Cacti Doctor** الحالية بوصول Administrator بعد الترقية. يظهر التقرير ضمن **Utilities > Cacti Doctor**.

<a id="languages"></a>
## اللغات

يحتوي Doctor على ترجمات للإسبانية في إسبانيا (`es-ES`) والفرنسية (`fr-FR`) والألمانية (`de-DE`) والصينية المبسطة (`zh-CN`) واليابانية (`ja-JP`) والهندية (`hi-IN`) والعربية (`ar-SA`)، إضافة إلى كتالوج إسبانية أمريكا اللاتينية (`es-419`) الموضح أدناه. يعرضها Cacti بعد تفعيل دعم اللغات (**Configuration > Settings > General > Language Support**) واختيار المستخدم لغته. تتبع صفحة الويب والإعدادات والرسائل ونصوص التقارير المطبوعة في سطر الأوامر لغة Cacti؛ ويستخدم تقرير سطر الأوامر اللغة الافتراضية لـ Cacti التي تبقى الإنجليزية ما لم تغيّرها.

لا يُترجم الإخراج المقروء آليًا مطلقًا: تبقى معرّفات الفحوص ومفاتيح JSON وقيم الحالة وإخراج `--format=nagios` و`--format=prometheus` وأسطر السجل وعناوين أقسام حزمة الدعم بالإنجليزية، لتعمل البرامج النصية والمراقبة في كل لغة. نصا `summary` و`detail` لكل فحص هما الجزء المترجم الوحيد من تقرير JSON.

يتوفر أيضًا كتالوج إسبانية أمريكا اللاتينية (`es-419`)، لكن لا يتيح Cacti 1.2 ولا Cacti 1.3 اختيار هذه اللغة المحلية؛ لذا لا يسري إلا عندما يضيفها Cacti. إلى ذلك الحين اختر الإسبانية (`es-ES`).

يحمّل Cacti كتالوج الإضافة من `plugins/doctor/locales/LC_MESSAGES/<locale>.mo` باستخدام نطاق النص `doctor` في 1.2.x و1.3 معًا (يحدد 1.3 دليل الإضافة عبر مسار الإضافات القابل للضبط).

<a id="access-levels"></a>
## مستويات الوصول

| النطاق | القدرات |
|---|---|
| Doctor Viewer | قراءة أحدث حالات الفحوص المجدولة ووقت الملاحظة وحداثتها والتاريخ التجميعي الحديث. لا أوامر تشخيص أو تفاصيل خام أو إعدادات أو إصلاحات. |
| Doctor Operator | تشغيل تقرير تشخيصي بمهلة عملية 120 ثانية، وفحص تفاصيل محجوبة الأسرار، والإقرار بالنتائج. لا تغييرات إعدادات أو إصلاحات. |
| Doctor Administrator | قدرات المشغّل مع الإصلاح الموجود في قائمة السماح وإعدادات Doctor. تتطلب الإصلاحات والإعدادات أيضًا نطاق Settings/System Utilities في Cacti. |

تفتح قائمة Utilities الصفحة لأعلى نطاق Doctor ممنوح للمستخدم، بما في ذلك منح المجموعات. لا تتلقى نطاقات Viewer وOperator الجديدة منحًا تلقائية. يبقى معرّف النطاق الأصلي مرتبطًا بـ `doctor.php` بوصفه Administrator، محافظًا على وصول المستخدمين والمجموعات الحالي.

تأتي بيانات Viewer من الفحوص المجدولة. فعّل الجدولة قبل منح وصول Viewer؛ تعرض الملاحظات المفقودة أو المتأخرة **غير معروف**، ولا تعرض حالة سليمة. يحتفظ التاريخ بآخر 20 عددًا تجميعيًا مجدولًا ويستثني حالة الأجهزة. يبدأ المشغّلون تشخيصات جديدة صراحةً؛ وتستخدم تحديثات الصفحة العادية آخر تقرير في جلستهم.

تستخدم تفاصيل الأجهزة وإجمالياتها أذونات أجهزة المستخدم الحالي. وتتطلب مقتطفات السجل أيضًا نطاق Log Administration. تُحجب الأسرار قبل تخزين التفاصيل التشخيصية في جلسة الويب أو عرضها. يبقى وصول CLI خاضعًا لحساب نظام التشغيل.

الإقرارات شخصية وخاضعة للتدقيق. تنطبق فقط على النتيجة والأدلة نفسيهما؛ وتستدعي الأدلة المتغيرة إقرارًا جديدًا. لا تغيّر حالة pass/warn/fail، ولا تكتم التنبيهات، ولا تعتبر فحصًا فاشلًا سليمًا. هذا منفصل عن استثناءات التحذيرات المقبولة، التي تؤثر في سياسة التنبيه دون تغيير الحالة المرصودة ويَرِد وصفها أدناه.

يتطلب كل إجراء POST ورمز CSRF صالحًا. تعرض الإصلاحات صفحة تأكيد منفصلة مع رابط Cancel لا يرسل النموذج، وتُسجّل المستخدم المنفّذ والنتيجة في سجل Cacti.

<a id="command-line"></a>
## سطر الأوامر

شغّل ما يلي من جذر Cacti كمستخدم مستطلع Cacti، وليس root:

```console
php plugins/doctor/cli/doctor.php
php plugins/doctor/cli/doctor.php --json
php plugins/doctor/cli/doctor.php --repair=runtime_directories --yes
```

يطبع الإخراج النصي سطرًا لكل فحص مع حالته وفئته وملخصه وتفاصيله. يطبع `--json` كائن `summary` بأعداد الحالات ومصفوفة `checks` تحتوي عناصرها على `id` و`category` و`status` و`summary` و`detail` و`repair`/`repairable` عندما ينطبق إصلاح من قائمة السماح.

| حالة الخروج | المعنى |
|---|---|
| `0` | لم يفشل فحص، أو نجح الإصلاح المطلوب. لا تغيّر التحذيرات حالة الخروج. |
| `1` | فشل فحص واحد على الأقل، أو لم ينجح إصلاح مطلوب. |
| `2` | خطأ في الاستخدام: طُلب إصلاح دون `--yes`، أو معرّف إصلاح غير معروف، أو تنسيق إخراج غير معروف، أو تركيبة غير مدعومة من `--symptom` أو التنسيق، أو تعذّر تحديد موقع تثبيت Cacti. |

يرفع Cacti قيمة `memory_limit` لكل برنامج نصي في CLI، لذا لا يكون فحص إعدادات تشغيل PHP ذا معنى إلا على صفحة الويب.

<a id="scheduled-checks-and-alerts"></a>
## الفحوص المجدولة والتنبيهات

ضمن **Configuration > Settings > Doctor**، فعّل **Run Checks on a Schedule** واختر فاصلًا من 15 دقيقة إلى يوم. بعد كل دورة مستطلع يحين فيها الموعد، يشغّل Doctor جميع الفحوص في عملية خلفية، فلا يتأثر زمن تشغيل المستطلع نفسه.

يسجل كل تشغيل الحالة المرصودة لكل فحص. تؤثر استثناءات التحذير النشطة في سياسة التنبيه دون تغيير الملاحظة. عندما يبدأ فحص بالفشل أو يتوقف عنه، يكتب Doctor التغيير في سجل Cacti، وإن ضُبطت **Alert Email Addresses** يرسل البريد إلى تلك العناوين عبر إعدادات بريد Cacti. يضيف **Alert on Warnings** الانتقال إلى حالة التحذير والخروج منها. لا يسجّل التشغيل الأول إلا خط أساس.

تعمل التقارير المجدولة على المستطلع الرئيسي تحت قفل استشاري لقاعدة البيانات، وبحد دقيقتين للعملية العاملة. يبلّغ Doctor عن آخر بدء واكتمال ناجح لتظهر النتائج المفقودة أو القديمة. تُحفظ محاولات تسليم التنبيهات الفاشلة لما يصل إلى ثلاث إعادات بتأخير متزايد؛ بعدها صحّح إعدادات بريد Cacti وشغّل `php plugins/doctor/cli/doctor.php --scheduled --retry-alerts` كمستخدم المستطلع. قبول خادم البريد لا يؤكد الوصول إلى صندوق الوارد.

تضبط علامة التبويب نفسها عتبات مدة المستطلع (80% من الفاصل)، ومساحة RRA الحرة (تحذير دون 10% وفشل دون 2%)، وانحراف ساعة قاعدة البيانات (تحذير فوق 5 ثوانٍ وفشل فوق 60)، وحجم سجل Cacti (100 MB). تعود القيم الفارغة أو غير الصالحة إلى هذه القيم الافتراضية.

<a id="monitoring-integration"></a>
## تكامل المراقبة

```console
php plugins/doctor/cli/doctor.php --format=nagios
php plugins/doctor/cli/doctor.php --format=prometheus > /var/lib/node_exporter/textfile/cacti_doctor.prom
```

يطبع `--format=nagios` سطر حالة مع بيانات أداء ويخرج بالقيمة `0` (OK) أو `1` (WARNING) أو `2` (CRITICAL)، فيستطيع Nagios أو Icinga أو أي نظام متوافق تشغيله مباشرةً. يكتب `--format=prometheus` صيغة نص Prometheus لجامع textfile في node_exporter: `cacti_doctor_check_status` لكل فحص (0 نجاح أو تحذير مقبول، 1 تحذير يتطلب إجراء، 2 فشل)، و`cacti_doctor_check_observed_status` قبل الاستثناءات، و`cacti_doctor_check_accepted`، و`cacti_doctor_checks` لكل حالة، و`cacti_doctor_last_run_timestamp_seconds`. تتضمن صفوف JSON حقل `assessment`؛ وتعني `not_assessed` أن الفحص لم يستطع الوصول إلى استنتاج من البيانات المتاحة.

<a id="support-bundle"></a>
## حزمة الدعم

```console
php plugins/doctor/cli/doctor.php --bundle=/tmp/cacti-doctor.txt
```

الحزمة ملف نصي واحد يتضمن إصدارات Doctor وCacti وPHP ونظام التشغيل وقاعدة البيانات، وإحصاءات المستطلع وBoost، والتقرير الكامل، وآخر 200 سطر من سجل Cacti. تُحجب القيم التي تلي أسماء password وsecret وtoken وcommunity وkey. ينشئ Doctor الملف بحيث يقرأه مالكه فقط، ويرفض الكتابة فوق ملف قائم. راجعه قبل نشره في أي مكان.

<a id="repair-policy"></a>
## سياسة الإصلاح

يتضمن Doctor إصلاحًا واحدًا هو `runtime_directories`. ينشئ أدلة تشغيل Cacti المفقودة ويضيف بتات القراءة والكتابة والتنفيذ للمالك دون إزالة الأذونات الحالية.

يستهدف `$cache_path` و`$log_path` و`$rra_path` في Cacti 1.3، أو أدلة `cache` و`log` و`rra` في التثبيت لغير ذلك. يتجاوز الأدلة القابلة للكتابة أصلًا، ويرفض الأدلة خارج تثبيت Cacti (مثل دليل سجلات تحت `/var/log`)، ويرفض الروابط الرمزية والتشغيل كـ root. لا يتبع `path_cactilog` مطلقًا، لذا لا يمكن لملف سجل مضبوط داخل دليل شيفرة أن يعيد توجيه الإصلاح إليه. يظل التشخيص يفحص دليل ملف السجل المضبوط في كل إصدار.

لا يغيّر الملكية أو يشغّل أوامر shell أو يعيد كتابة الإعدادات أو يعدّل بيانات تطبيق Cacti. يجب أن يتضمن كل إصلاح جديد تشخيصًا ومعالجًا في قائمة السماح وتأكيدًا وسجل تدقيق واختبارات.

<a id="investigating-symptoms"></a>
## التحقيق في الأعراض

يمكن للمشغّلين والمسؤولين اختيار **Investigate a symptom** على صفحة Doctor. تتوفر القواعد نفسها عبر `--symptom=graphs_stopped` أو `slow_polling` أو `devices_missing` أو `alerts_missing`، بإخراج نصي أو JSON. تتضمن حزم الدعم تحقيقات الأعراض ذات الصلة.

يسرد كل سبب محتمل الفحوص المرصودة وخطوة التحقق التالية. الأسباب المحتملة فرضيات وليست أسبابًا جذرية مؤكدة. لا تثبت الملاحظات المفقودة أو غير المقيّمة أو القديمة سببًا. تستخدم تحقيقات الويب التقرير المصفّى بالأذونات؛ وتستخدم تقارير CLI وصول حساب نظام التشغيل.

<a id="rrd-update-freshness"></a>
## حداثة تحديث RRD

يفحص `filesystem.rrd_stale` أول 500 مصدر بيانات نشط على الأكثر بحسب المعرّف، مستثنيًا الأجهزة المعطّلة والمتوقفة. يقارن أوقات تعديل الملفات بأكبر قيمة من فاصل المستطلع وخطوة RRD للمصدر وخطوة ملف التعريف، مضروبةً في **RRD Stale Intervals** (الافتراضي 3). يعرض أقدم ثلاثة ملفات متقادمة وعدد الأجهزة المتأثرة. لا تشمل نتائج الويب إلا الأجهزة المسموح بها.

يضيف Boost ضعفي فاصل التفريغ المضبوط كمهلة إضافية لكتابة القرص. لكاتب مؤجل آخر، اضبط **Deferred RRD Write Allowance (seconds)**. يؤدي وجود `RRDCACHED_ADDRESS` معلن دون مهلة، أو فاصل Boost غير صالح، إلى نتيجة غير مقيّمة. لا يفرغ Doctor ذاكرة مؤقتة لإجراء هذا الفحص. وقت التعديل دليل على نشاط القرص، وليس إثباتًا لنجاح جمع البيانات. يجب ضبط التخزين المؤقت الخارجي الذي لا يستطيع Doctor كشفه صراحةً.

تُبلّغ الملفات المفقودة أو غير القابلة للقراءة أو المؤرخة في المستقبل والعينة المحدودة كتغطية غير مكتملة بدلًا من تثبيت سليم. لا تُقيّم الملفات خارج العينة.

<a id="repair-previews-and-audit-history"></a>
## معاينات الإصلاح وسجل التدقيق

تعرض صفحة إصلاح المسؤول كل مسار متأثر وإجراءه المقترح وأذوناته الحالية والمستهدفة. ترتبط الموافقة بتلك المعاينة وبالمستخدم المنفّذ وبصلاحية خمس دقائق. يستهلك التأكيد المعاينة؛ ويستلزم تغير نظام الملفات معاينة أخرى. يمنع التشغيل كـ root، والمسارات الخارجية، والروابط التي تتطلب إصلاحًا، وعدم كفاية أذونات نظام الملفات الموافقة.

يطبع `--repair=runtime_directories --preview` خطة JSON للقراءة فقط. يوافق `--repair=runtime_directories --yes` على خطة CLI محسوبة للتو ويعيد فحصها قبل التنفيذ. يجب أن يكون حساب CLI مخوّلًا أصلًا لإصلاح التثبيت؛ ولا يرث أدوار الويب.

يجب حفظ سجل منظم `repair.started` قبل أي تغيير في نظام الملفات. يحتوي سجل `repair.completed` المرتبط على لقطة ما بعد الإصلاح ونتيجة التحقق. تترك العملية المنقطعة سجل بدء للتحقيق. يُبلّغ فشل تدقيق الاكتمال كفشل حتى لو حدثت تغييرات في نظام الملفات. يضيف Doctor أذونات المالك وينشئ الأدلة؛ ولا يحاول التراجع التلقائي.

يمكن للمسؤولين ذوي إذن Settings/System Utilities في Cacti قراءة أحدث 20 سجل تدقيق على صفحة Doctor. تحتفظ الإضافة بأحدث 200 سجل في `plugin_doctor_audit`؛ ويسجّل سجل Cacti أيضًا معرّفاتها وإجراءاتها ومنفّذيها. تُحجب البيانات الحساسة من محتوى التدقيق.

<a id="accepted-warnings"></a>
## التحذيرات المقبولة

يمكن للمسؤولين ذوي إذن Settings/System Utilities في Cacti إنشاء **Warning exception** من تحذير حديث ومقيّم على صفحة Doctor. يتطلب الاستثناء مالكًا وسببًا وتاريخ مراجعة UTC خلال 90 يومًا. ينتهي عند منتصف ليل UTC في بداية ذلك التاريخ. يمكن ضبط ما يصل إلى 100 استثناء. تعرض القائمة الإدخالات المنتهية والمعرّفات غير الموجودة في التقرير الحالي وتسمح بإزالتها.

يبقى التحذير المرصود ظاهرًا، مع مالكه وسببه وانتهائه في التفاصيل. يحتفظ JSON بالحالة المرصودة ويضيف بيانات `accepted` و`acceptance`. يستثني Nagios التحذيرات المقبولة النشطة من شدة الخروج، لكنه يسميها في الإخراج. يصدّر Prometheus الشدة المرصودة والشدة التي تتطلب إجراءً معًا. لا تتغير حالة خروج CLI العادية: التحذيرات تخرج أصلًا بصفر والإخفاقات بواحد.

تُكتم تنبيهات التحذير المجدولة أثناء انطباق الاستثناء؛ ويجعل انتهاؤه أو إزالته التحذير المستمر مؤهلًا للتنبيه مجددًا. تظل الانتقالات إلى الفشل والتعافي منه مؤهلة. لا يمكن قبول نتيجة غير مقيّمة أو فشل. الإقرار الشخصي منفصل ولا يكتم شيئًا. إنشاء الاستثناء وإزالته معاملتان مترابطتان مع سجل التدقيق.

تنشئ الترقية `plugin_doctor_audit` و`plugin_doctor_acceptance` دون تغيير بيانات تطبيق Cacti. صدّر التاريخ المطلوب قبل إلغاء التثبيت: يزيل إلغاء التثبيت الجدولين وإعدادات الإضافة. يترك إرجاع ملفات الإضافة الجداول متاحة للتحقيق، لكن الإصدارات القديمة لا تحترم استثناءات التحذيرات.

<a id="requirements"></a>
## المتطلبات

| Cacti | PHP | ملاحظات |
|---|---|---|
| 1.2.20 | 5.4 أو أحدث | شيفرة Doctor نفسها متوافقة مع PHP 5.4 لتشخيص الأنظمة القديمة قبل الترقية |
| 1.2.31 | 8.0 أو أحدث | يتطلب `composer.json` في Cacti استخدام `>=8.0` |
| 1.2.x الحالي | 8.2 أو أحدث | يتطلب `composer.json` في Cacti استخدام `>=8.2` |
| `develop` (1.3) | 8.3 أو أحدث | يتطلب `composer.json` في Cacti استخدام `^8.3` |

يقارن صف **PHP compatibility with installed Cacti** إصدار PHP العامل بمتطلب PHP في `composer.json` الجذري لـ Cacti، بما فيه الحد الأعلى لقيد بعلامة ^ مثل `^8.3`. يُفحص ملف PHP CLI التنفيذي المضبوط مقابل المتطلب نفسه. يتعرف Doctor على صيغتي `>=` و`^` المستخدمتين في هذه الحزم. يؤدي المتطلب غير المقروء أو غير الصحيح أو المفقود أو غير المعروف إلى تحذير؛ وتحتفظ تثبيتات Cacti 1.2.20–1.2.30 دون ملف بيان بحد مثبتها الموثّق PHP 5.4. توافق Doctor نفسه مع PHP 5.4 لا يثبت التوافق مع تثبيت Cacti أحدث.

يجيب صف **PHP upstream security support** عن سؤال منفصل: هل لا يزال فرع PHP هذا يتلقى إصلاحات أمنية من مشروع PHP؟ يعرض تاريخ نهاية الدعم الأمني المنشور ويحذّر بعده. مثلًا، قد يفي PHP 8.1 بمتطلب تشغيل Cacti قديم بينما لم يعد يتلقى إصلاحات أمنية أصلية. لا يعني النجاح أن إصدار التصحيح المثبّت حديث، ولا يستطيع Doctor تحديد ما إذا كان مورّد نظام التشغيل يوفر إصلاحات منقولة إلى الإصدارات القديمة.

تُرفق تواريخ الدعم مع Doctor من [جدول دعم PHP](https://www.php.net/supported-versions.php) و[قائمة نهاية العمر](https://www.php.net/eol.php)، وآخر تحقق منها في 2026-11-08. تنتج الفروع غير المعروفة والإصدارات التجريبية تحذيرًا بدلًا من افتراض النجاح. لا تُجرى طلبات شبكة أثناء التشخيص. حدّث بيانات دعم Doctor عندما ينشر PHP جدولًا جديدًا. لا تتغير معرّفات JSON والمراقبة `php.version` و`php.security_baseline`.

<a id="development"></a>
## التطوير

تستخدم مجموعة اختبارات الوحدات Pest وتعمل على PHP 8.2 أو أحدث:

```console
composer install
composer test
```

تستبدل الاختبارات دوال Cacti التي يستدعيها Doctor ببدائل صغيرة في `tests/CactiStubs.php`، فتعمل دون تثبيت Cacti.

يشغّل GitHub Actions أربعة أنواع من الفحوص مع كل دفع وطلب سحب:

- `php -l` لكل ملف PHP على PHP 5.4 و5.6 و7.0 و7.1 و7.4 ومن 8.0 إلى 8.4.
- مجموعة الوحدات على PHP 8.2 و8.3 و8.4.
- `locales/build_gettext.sh --check`، الذي يفشل عند تقادم قالب الترجمة، أو نقص كتالوج أو احتوائه على إدخالات غير مؤكدة، أو اختلاف الكتالوج المجمّع عن مصدره.
- سبع مهام تكامل تثبّت Cacti 1.2.20 وفرع 1.2.x الحالي و`develop` مع MySQL وMariaDB، باستخدام cmd.php وSpine معًا. تثبّت كل مهمة الإضافة وتفعّلها، وتشغّل تقرير CLI الكامل، وتتحقق من المخطط وإجماليات الملخص والحالات المتوقعة ومجموعة الإخفاقات الدقيقة. ثم تُفسد مسار ملف تنفيذي وطابع المستطلع الزمني، وتؤكد الإبلاغ عنهما، وتعيدهما، وتختبر الإصلاح وتأكيده، ثم التعطيل والتفعيل وإلغاء التثبيت وإعادة التثبيت. يُحفظ تقرير JSON كمنتج عندما تفشل مهمة.

<a id="translations"></a>
### الترجمات

غلّف كل رسالة ظاهرة للمستخدم بـ `__('...', 'doctor')` (أو `__n()` أو `__x()` أو `__esc()`)، واستخدم للجملة التي تحتوي قيمة سلسلة تنسيق واحدة بعناصر نائبة متتابعة `%s`/`%d` بدل وصل الأجزاء. لا تنسّق `__()` في Cacti الرسالة إلا عند وجود محدد تنسيق، ولا تدعم الصيغ الموضعية `%1$s`. كما تحوّل `%%` إلى `%` قبل التنسيق، لذا لا تضع علامة نسبة مئوية حرفية في الرسالة: مرّر القيمة مع علامتها كوسيط (`__('Usage: %s', '50%', 'doctor')`). تبقى السجلات بالإنجليزية: استخدم `doctor_repair_message()` لنصوص الإصلاح، و`doctor_n_()` للرسائل المسجّلة التي لا تُترجم إلا عند عرضها. لا تترجم معرّفات الفحوص أو مفاتيح JSON أو كلمات الحالة أو إخراج المراقبة أو أسطر السجل.

يعيد `locales/build_gettext.sh` توليد القالب `locales/po/cacti.pot`، ويدمجه في كل `locales/po/<locale>.po`، ويجمّع `locales/LC_MESSAGES/<locale>.mo`؛ أدرج الثلاثة في الإيداع. يشغّل CI الأمر `sh locales/build_gettext.sh --check`، الذي يفشل إذا تقادم القالب أو فُقد إدخال أو كان غير مؤكد أو اختلف عنصر نائب أو تقادم ملف مجمّع. لذا يجب تحديث ترجمات الرسالة المعدّلة في طلب السحب نفسه. يلزم GNU gettext (`xgettext` و`msgmerge` و`msgfmt` و`msgunfmt`). اللغة الجديدة ملف `<locale>.po` جديد باسم يطابق تسميات Cacti، مثل `pt-BR`.
