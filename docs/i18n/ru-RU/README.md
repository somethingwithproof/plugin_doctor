Cacti Doctor — это плагин для Cacti, который выполняет диагностику установки за один проход и применяет небольшие исправления только по запросу администратора.

**Статус: в разработке, версия до 1.0.** Последний выпуск — [0.6.1](https://github.com/somethingwithproof/plugin_doctor/releases/tag/v0.6.1). Это исправление добавляет каталоги переводов на хинди и арабский язык и переведённые руководства пользователя к появившимся в 0.6.0 доступу с разграничением по ролям, пошаговой диагностике, проверкам актуальности RRD в пределах области видимости, предпросмотру исправлений и истории аудита, принятым исключениям предупреждений и переводам. Подробности см. в [CHANGELOG.md](../../../CHANGELOG.md).

## Снимки экрана

Диагностика и настройки расписания в изолированной демонстрационной установке Cacti 1.2.31 под управлением PHP 8.3.36, включая проверки совместимости Cacti с PHP, статуса поддержки безопасности от разработчиков PHP и состояния базы данных. Показанные здесь предупреждения и сбои относятся к этой демонстрационной среде.

![Таблица диагностики Doctor с результатами «успешно», «предупреждение» и «сбой»](../../screenshots/diagnostics.png)

![Настройки расписания, оповещений и пороговых значений Doctor](../../screenshots/settings.png)

Проблемы Cacti обычно проявляются как симптомы: пустые графики, остановившийся поллер, плагин, который не устанавливается. Причиной часто бывает изменившееся предварительное требование, например отсутствующее расширение PHP в сборке CLI, каталог журналов, в который поллер не может записывать, путь к RRDtool, указывающий на неверный исполняемый файл, или база данных без таблиц часовых поясов. Doctor проверяет эти требования напрямую и для каждого из них сообщает статус (успешно, предупреждение или сбой) вместе с предложением, объясняющим, что именно было обнаружено. Этот же отчёт доступен на веб-странице, в командной строке и в формате JSON для мониторинга.

## Что проверяется

| Область | Проверки |
|---|---|
| Doctor | Не запущен ли сам Doctor от имени root, из-за чего проверки прав доступа описывали бы неверную учётную запись |
| Cacti и PHP | Версия Cacti, незавершённое установщиком обновление, включённые плагины с отсутствующими файлами, совместимость PHP с установленным пакетом Cacti, статус поддержки безопасности PHP со стороны разработчиков |
| Расширения PHP | Обязательные расширения в веб-PHP и в CLI PHP, который использует поллер, а также рекомендуемые возможности |
| Конфигурация PHP | `memory_limit`, `max_execution_time` и `date.timezone` с использованием собственных рекомендаций Cacti |
| База данных | Подключение, соответствие версии сервера рекомендациям Cacti, кодировка UTF-8, таблицы часовых поясов, основные таблицы, расхождение времени с хостом PHP и параметры InnoDB, которые Cacti отмечает как ошибки |
| Состояние базы данных | Запас подключений, чтения пула буферов, временные таблицы на диске, создание потоков подключений, медленные запросы и ожидания буфера журнала InnoDB с рекомендациями по настройке в зависимости от нагрузки |
| Файловая система | Доступные для записи каталоги кэша, журналов и RRA; свободное место для RRD-файлов; активные источники данных без RRD-файла или с просроченным обновлением файла; проверка того, что `include/config.php` не доступен для чтения всем пользователям; возможность записи в журнал Cacti и отсутствие превышения его размера |
| Исполняемые файлы | PHP CLI, RRDtool, `snmpget`, `snmpwalk` и Spine, если он настроен в качестве поллера, включая версии, когда Cacti их указывает |
| Журнал | Ошибки среди последних строк журнала Cacti с указанием наиболее часто встречающегося сообщения |
| Устройства | Включённые устройства в состоянии сбоя или восстановления, три устройства, находящиеся в состоянии сбоя дольше всего, с их последней ошибкой, а также сбой при одновременной недоступности большинства устройств |
| Поллер | Тип и интервал поллера, время с момента последнего завершения основного поллера, время выполнения относительно интервала, вывод поллера, так и не попавший в RRD-файл, удалённые поллеры, переставшие отправлять отчёты, зависший Boost и конфигурация Spine, указывающая на другую базу данных |

Каждая проверка имеет стабильный идентификатор, например `database.timezone` или `binary.rrdtool`, чтобы скрипты могли обращаться к отдельным результатам.

## Рекомендации по состоянию базы данных

Встроенный анализатор Doctor на PHP считывает фиксированный набор глобальных счётчиков MySQL или MariaDB через существующее подключение Cacti к базе данных. Он выполняет два запроса только для чтения на отчёт, не требует дополнительных учётных данных или исполняемых файлов и никогда не изменяет конфигурацию базы данных. Эти проверки отображаются в веб-отчёте, CLI, JSON, выводе для мониторинга, пакете поддержки и отслеживании состояния по расписанию.

| Идентификатор проверки | Условие срабатывания расследования |
|---|---|
| `database.health_sample` | Менее 24 часов с момента запуска или выполнения `FLUSH STATUS`, либо недоступное/несогласованное время работы |
| `database.connection_capacity` | Текущее или зафиксированное пиковое число подключений составляет не менее 80% от текущего `max_connections` |
| `database.buffer_pool_reads` | `Innodb_buffer_pool_reads / Innodb_buffer_pool_read_requests` не менее 1% при не менее чем 10 000 запросов на чтение |
| `database.temporary_tables` | `Created_tmp_disk_tables / Created_tmp_tables` не менее 25% при не менее чем 1 000 временных таблиц |
| `database.thread_cache` | `Threads_created / Connections` не менее 5% при не менее чем 1 000 попыток подключения и `thread_handling=one-thread-per-connection` |
| `database.slow_queries` | `Slow_queries / Queries` не менее 1% при не менее чем 1 000 запросов |
| `database.redo_log_waits` | Ненулевое значение `Innodb_log_waits` |

Это пороговые значения Doctor для расследования, а не целевые значения конфигурации от поставщика СУБД. За исключением запаса подключений, накопительные рекомендации требуют указанного выше окна наблюдения. Отсутствующие, некорректные, дублирующиеся или выходящие за допустимые пределы счётчики, недостаточная активность и неподдерживаемые режимы потоков приводят к предупреждениям вместо вердикта о нормальном состоянии или рекомендации по настройке. Предупреждения могут влиять на статус Nagios и оповещения по расписанию, если включён параметр **Оповещать о предупреждениях** (Alert on Warnings).

Рассматривайте измеренные счётчики и рекомендацию вместе. Накопительные значения не показывают текущую нагрузку; счётчики могут иметь разную историю сбросов и не являются атомарным снимком. Пиковое число подключений может отражать прежнее ограничение. Количество медленных запросов зависит от `long_query_time`, а счётчик дисковых временных таблиц в MySQL может не учитывать файлы, отображённые в память. Низкое соотношение не доказывает отсутствие узкого места. Подтвердите тенденции при типичной нагрузке, проверьте планы выполнения запросов и повторное использование подключений, а также измерьте потребление памяти на **хосте базы данных**, прежде чем изменять размеры буферов или ограничения подключений.

Если метрики недоступны, проверьте поддержку со стороны сервера и доступ учётной записи Cacti к `SHOW GLOBAL STATUS` и `SHOW GLOBAL VARIABLES`; Doctor не запрашивает повышенные привилегии. Определения счётчиков взяты из [справочника по переменным состояния MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-status-variables.html) и [справочника по переменным состояния MariaDB](https://mariadb.com/docs/server/server-management/variables-and-modes/server-status-variables). Скрипты или код MySQLTuner не используются.

Миграция схемы или конфигурации не требуется. Разверните файлы плагина обычным способом; откат этих файлов удалит добавленные диагностические проверки. Существующее состояние расписания обновляется при следующем запуске.

## Как обеспечивается безопасность

Диагностический инструмент работает с привилегиями поллера или веб-сервера и считывает пути из таблицы настроек, поэтому он должен осторожно относиться к тому, что запускает и изменяет.

- Диагностические проверки выполняются только на чтение. Они никогда не изменяют файлы, настройки или данные.
- Doctor запускает настроенный исполняемый файл только в том случае, если его имя совпадает с ожидаемой программой (`php`, `rrdtool`, `snmpget` или `snmpwalk`). В противном случае любой пользователь с правами записи в таблицу настроек мог бы выбирать, что запускает Doctor. О любом другом имени сообщается как о предупреждении, и оно не выполняется.
- Doctor никогда не запускает настроенные исполняемые файлы от имени root и сообщает, если сам запущен от имени root.
- Исправления выбираются из фиксированного списка разрешённых действий. Каждое из них требует подтверждённого действия администратора в веб-интерфейсе или флага `--yes` в CLI, и каждое исправление записывается в журнал Cacti.

## Установка

Скачайте `doctor-VERSION.tar.gz` или `doctor-VERSION.zip` и `SHA256SUMS` со страницы
[GitHub Releases](https://github.com/somethingwithproof/plugin_doctor/releases).
Проверьте контрольную сумму SHA-256 архива, затем распакуйте его каталог `doctor/` в каталог
`plugins/` вашей установки Cacti. Это готовые к установке пакеты; автоматические архивы
исходного кода GitHub имеют другое имя каталога. Чтобы запускать ещё не выпущенные изменения
из ветки `develop`, установите плагин из локальной копии репозитория.

Для установки из исходного кода:

Клонируйте или распакуйте репозиторий как `plugins/doctor` внутри каталога установки Cacti. Каталог должен называться `doctor`, а не `plugin_doctor`.

```console
cd /path/to/cacti/plugins
git clone https://github.com/somethingwithproof/plugin_doctor.git doctor
```

Установите и включите **Cacti Doctor** в разделе **Configuration > Plugin Management**, затем предоставьте права области **Doctor Viewer**, **Doctor Operator** или **Doctor Administrator** через права пользователей или групп Cacti. Существующие права **Cacti Doctor** сохраняют доступ уровня Administrator после обновления. Отчёт отображается в разделе **Utilities > Cacti Doctor**.

## Языки

Doctor поставляется с 48 неанглоязычными каталогами переводов в `locales/po/` и `locales/LC_MESSAGES/`, охватывающими локали расширенного первого уровня (`ar-SA`, `de-DE`, `es-ES`, `es-419`, `fr-FR`, `hi-IN`, `id-ID`, `it-IT`, `ja-JP`, `ko-KR`, `nl-NL`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `tr-TR`, `uk-UA`, `vi-VN`, `zh-CN`, `zh-TW`), а также африканские (`af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`), азиатские (`bn-BD`, `fa-IR`, `he-IL`, `mr-IN`, `ms-MY`, `ta-IN`, `te-IN`, `th-TH`, `ur-PK`, `fil-PH`) и юго-восточноевропейские (`bs-BA`, `hr-HR`, `sr-RS`). Cacti отображает каталог, если включена языковая поддержка (**Configuration > Settings > General > Language Support**) и пользователь выбрал локаль, которую Cacti предлагает в своём списке выбора языка; каталоги для локалей, которых ещё нет в списке выбора языка Cacti, вступят в силу, как только Cacti добавит их. Веб-страница, настройки, а также сообщения и текст отчёта, выводимые в командной строке, используют язык Cacti; сам отчёт командной строки использует язык Cacti по умолчанию, который остаётся английским, если вы не измените его.

Машиночитаемый вывод никогда не переводится: идентификаторы проверок, ключи JSON и значения статусов, вывод `--format=nagios` и `--format=prometheus`, строки журнала и заголовки разделов пакета диагностики остаются на английском языке, чтобы скрипты и системы мониторинга продолжали работать при любом языке. Единственной переводимой частью отчёта JSON является текст полей `summary` и `detail` каждой проверки.

Также в комплекте поставляется каталог для латиноамериканского испанского (`es-419`), но ни в Cacti 1.2, ни в Cacti 1.3 нет локали для латиноамериканского испанского, поэтому он начнёт действовать только после того, как Cacti добавит её. До тех пор выбирайте испанский (`es-ES`).

Cacti загружает каталог переводов плагина из `plugins/doctor/locales/LC_MESSAGES/<locale>.mo` с доменом текста `doctor` как в версии 1.2.x, так и в 1.3 (версия 1.3 определяет каталог плагина через настраиваемый путь к плагинам).

| Doctor Viewer | Просмотр статусов последних плановых проверок, времени наблюдения, актуальности и недавней агрегированной истории. Без диагностических команд, необработанных подробностей, настройки и исправлений. |
| Doctor Operator | Запуск диагностического отчёта с ограничением времени выполнения процесса в 120 секунд, просмотр маскированных подробностей и подтверждение обнаруженных проблем. Без изменения настроек и исправлений. |
| Doctor Administrator | Возможности Operator плюс существующие исправления из списка разрешённых и настройки Doctor. Для исправлений и настроек также требуется область Settings/System Utilities в Cacti. |

Меню Utilities открывает страницу, соответствующую наивысшей области Doctor, предоставленной пользователю, включая права, выданные через группы. Новые области Viewer и Operator не получают автоматических разрешений. Исходный идентификатор области остаётся привязанным к `doctor.php` с уровнем Administrator, что сохраняет существующий доступ пользователей и групп.

Данные для Viewer поступают из плановых проверок. Включите планировщик до предоставления доступа Viewer; при отсутствии или устаревании наблюдений отображается статус **unknown**, а не исправный статус. История хранит агрегированные счётчики за последние 20 плановых запусков и не включает статусы устройств. Операторы запускают новую диагностику явно; при обычном обновлении страницы используется последний отчёт из их сессии.

Подробности и итоговые показатели по устройствам используют права доступа текущего пользователя к устройствам. Для просмотра фрагментов журнала дополнительно требуется область Log Administration в Cacti. Секретные данные маскируются до сохранения диагностических подробностей в веб-сессии или их отображения. Доступ через CLI по-прежнему определяется учётной записью операционной системы.

Подтверждения являются персональными и записываются в журнал Cacti. Они применяются только к той же проблеме и тем же доказательствам; при изменении доказательств требуется новое подтверждение. Они никогда не изменяют статус pass/warn/fail, не подавляют оповещения и не помечают сбойную проверку как исправную. Это отдельный механизм от исключений принятых предупреждений, которые влияют на политику оповещений без изменения наблюдаемого статуса и описаны ниже.

Каждое действие требует запроса POST и действительного CSRF-токена. Для исправлений открывается отдельная страница подтверждения со ссылкой Cancel, не отправляющей форму, а действующий пользователь и результат записываются в журнал Cacti.

## Командная строка

Выполняйте эти команды из корневого каталога Cacti от имени пользователя поллера Cacti, а не root:

```console
php plugins/doctor/cli/doctor.php
php plugins/doctor/cli/doctor.php --json
php plugins/doctor/cli/doctor.php --repair=runtime_directories --yes
```

Текстовый вывод печатает по одной строке на каждую проверку с её статусом, категорией, кратким описанием и подробностями. Флаг `--json` выводит объект `summary` со счётчиками статусов и массив `checks`, элементы которого содержат `id`, `category`, `status`, `summary`, `detail`, а также `repair`/`repairable`, если применимо исправление из списка разрешённых.

| Код выхода | Значение |
|---|---|
| `0` | Ни одна проверка не завершилась сбоем, либо запрошенное исправление выполнено успешно. Предупреждения не меняют код выхода. |
| `1` | Хотя бы одна проверка завершилась сбоем, либо запрошенное исправление не удалось. |
| `2` | Ошибка использования: запуск исправления без флага `--yes` (для `--preview` он не требуется), неизвестный идентификатор исправления, неизвестный формат вывода, неподдерживаемая комбинация `--symptom` или формата, либо невозможность определить каталог установки Cacti. |

Cacti повышает `memory_limit` для каждого CLI-скрипта, поэтому проверка конфигурации среды выполнения PHP имеет смысл только на веб-странице.

## Плановые проверки и оповещения

В разделе **Configuration > Settings > Doctor** включите **Run Checks on a Schedule** и выберите интервал от 15 минут до одного дня. После каждого цикла поллера, на который выпадает запуск, Doctor выполняет все проверки в фоновом процессе, поэтому время работы самого поллера не увеличивается.

Каждый запуск фиксирует наблюдаемый статус каждой проверки. Активные исключения предупреждений влияют на политику оповещений, не изменяя само наблюдение. Когда проверка начинает или перестаёт завершаться сбоем, Doctor записывает изменение в журнал Cacti и, если задано поле **Alert Email Addresses**, отправляет письмо на эти адреса через настройки почты Cacti. Параметр **Alert on Warnings** добавляет уведомления о переходах в статус предупреждения и выходе из него. Первый запуск фиксирует только базовое состояние.

Плановые отчёты запускаются на основном поллере под рекомендательной блокировкой базы данных и имеют ограничение времени работы воркера в две минуты. Doctor отображает время последнего запуска и последнего успешного завершения, чтобы отсутствующие или устаревшие результаты были видны. Результаты считаются актуальными в течение выбранного интервала плюс одного цикла опроса и трёх минут. Незавершённый запуск повторяется через 5, 10, 20 и более минут, вплоть до обычного интервала. Неудачные доставки оповещений сохраняются для выполнения до трёх повторных попыток с увеличивающимися задержками; после этого исправьте настройки почты Cacti и выполните `php plugins/doctor/cli/doctor.php --scheduled --retry-alerts` от имени пользователя поллера. Принятие письма почтовым сервером не гарантирует доставку во входящие.

На той же вкладке задаются пороговые значения для времени работы поллера (80% от интервала), свободного места на диске для RRA (предупреждение ниже 10%, сбой ниже 2%), расхождения часов базы данных (предупреждение свыше 5 секунд, сбой свыше 60) и размера журнала Cacti (100 МБ). При пустых или некорректных значениях используются эти значения по умолчанию.

## Интеграция с мониторингом

```console
php plugins/doctor/cli/doctor.php --format=nagios
php plugins/doctor/cli/doctor.php --format=prometheus > /var/lib/node_exporter/textfile/cacti_doctor.prom
```

Флаг `--format=nagios` выводит одну строку статуса с данными производительности и завершается с кодом `0` (OK), `1` (WARNING) или `2` (CRITICAL), поэтому Nagios, Icinga или любая совместимая система может запускать команду напрямую. Флаг `--format=prometheus` формирует текстовый формат Prometheus для коллектора textfile в node_exporter: `cacti_doctor_check_status` для каждой проверки (0 — успех или принятое предупреждение, 1 — предупреждение, требующее внимания, 2 — сбой), `cacti_doctor_check_observed_status` до применения исключений, `cacti_doctor_check_accepted`, `cacti_doctor_checks` по каждому статусу и `cacti_doctor_last_run_timestamp_seconds`. Строки проверок в JSON содержат поле `assessment`; значение `not_assessed` означает, что проверке не удалось сделать вывод на основе доступных данных.

## Пакет диагностики

```console
php plugins/doctor/cli/doctor.php --bundle=/tmp/cacti-doctor.txt
```

Пакет представляет собой один текстовый файл с версиями Doctor, Cacti, PHP, ОС и базы данных, статистикой поллера и Boost, полным отчётом и последними 200 строками журнала Cacti. Значения, следующие за именами паролей, секретов, токенов, community-строк и ключей, маскируются. Doctor создаёт файл с правами на чтение только для его владельца и отказывается перезаписывать существующий файл. Просмотрите файл перед тем, как публиковать его где-либо.

## Политика исправлений

Doctor включает одно исправление — `runtime_directories`. Оно создаёт отсутствующие рабочие каталоги Cacti и добавляет биты чтения, записи и выполнения для владельца, не удаляя существующие права доступа.

Исправление затрагивает `$cache_path`, `$log_path` и `$rra_path` в Cacti 1.3 либо каталоги `cache`, `log` и `rra` внутри установки Cacti в остальных версиях. Оно пропускает каталоги, которые уже доступны для записи, отклоняет каталоги за пределами установки Cacti (например, каталог журналов в `/var/log`), отклоняет символические ссылки и отказывается запускаться от имени root. Оно никогда не использует `path_cactilog`, поэтому файл журнала, настроенный внутри каталога с кодом, не может перенаправить туда исправление. Диагностика при этом продолжает проверять каталог настроенного файла журнала в любом выпуске.

Исправление не изменяет владельца, не запускает команды оболочки, не перезаписывает конфигурацию и не модифицирует данные приложения Cacti. Каждое новое исправление должно включать диагностическую проверку, обработчик из разрешённого списка, подтверждение, журналирование аудита и тесты.

## Исследование симптомов

Операторы и администраторы могут выбрать **Исследовать симптом** на странице Doctor. Те же правила доступны через `--symptom=graphs_stopped`, `slow_polling`, `devices_missing` или `alerts_missing` с выводом в текстовом формате или JSON. Пакеты диагностики для поддержки включают соответствующие исследования симптомов.

Каждый кандидат содержит список наблюдаемых проверок и следующий шаг верификации. Кандидаты являются гипотезами, а не подтверждёнными первопричинами. Отсутствующие, невыполненные или устаревшие наблюдения никогда не устанавливают причину. Веб-исследования используют отчёт, отфильтрованный по правам доступа; отчёты CLI используют права учётной записи операционной системы.

## Актуальность обновлений RRD

`filesystem.rrd_stale` проверяет до 500 активных источников данных, исключая отключённые и недоступные устройства. В крупных установках выборка меняется каждый час, поэтому повторные запуски охватывают разные файлы. Проверка сравнивает время модификации файла с наибольшим из значений — интервалом поллера, шагом исходного RRD и шагом профиля — умноженным на **Интервалы устаревания RRD** (по умолчанию 3). Она показывает три самых старых устаревших файла и количество затронутых устройств. Веб-результаты включают только разрешённые устройства.

`filesystem.rrd_files` — это отдельная проверка наличия файлов. Она проверяет существование RRD-файлов для до 5 000 активных источников данных, включая данные на отключённых или недоступных устройствах, и использует ту же ежечасную выборку.

Boost добавляет удвоенный настроенный интервал сброса в качестве допуска на запись на диск. Для другого механизма отложенной записи настройте **Допуск на отложенную запись RRD (в секундах)**. Указанный параметр `RRDCACHED_ADDRESS` без допуска или некорректный интервал Boost приводят к результату «не оценено». Doctor никогда не сбрасывает кэш для выполнения этой проверки. Время модификации свидетельствует об активности диска, но не доказывает успешный сбор данных. Внешнее кэширование, которое Doctor не может обнаружить, должно быть настроено явно.

Отсутствующие, нечитаемые файлы и файлы с меткой времени из будущего учитываются в подробностях. Результат считается неоценённым только в том случае, если ни один файл в выборке не доступен для чтения. Выборочный результат сообщает, что он охватывает лишь часть установки; успешная проверка не распространяется на файлы вне выборки.

## Предпросмотр исправлений и история аудита

Страница исправлений для администратора показывает каждый затрагиваемый путь, предлагаемое действие, текущие права доступа и целевые права доступа. Одобрение привязано к этому предпросмотру, действующему пользователю и пятиминутному сроку действия. Подтверждение расходует предпросмотр; изменение файловой системы требует нового предпросмотра. Выполнение от имени root, пути за пределами установки, ссылки, требующие исправления, и невыполненные права доступа файловой системы блокируют одобрение.

`--repair=runtime_directories --preview` выводит план в формате JSON в режиме только для чтения. `--repair=runtime_directories --yes` одобряет заново вычисленный план CLI и повторно проверяет его перед выполнением. Учётная запись CLI уже должна иметь права на исправление установки; она не наследует веб-роли.

Структурированная запись `repair.started` должна быть сохранена до любых изменений в файловой системе. Связанная запись `repair.completed` содержит снимок состояния после исправления и результат верификации. Прерванная операция оставляет запись о запуске для расследования. Ошибка записи завершения в журнал аудита считается сбоем, даже если изменения в файловой системе были выполнены. Doctor добавляет права владельца и создаёт каталоги; он не пытается выполнять автоматический откат.

Администраторы с правом Cacti «Настройки/Системные утилиты» могут просматривать последние 20 записей аудита на странице Doctor. Плагин хранит последние 200 записей в таблице `plugin_doctor_audit`; журнал Cacti также фиксирует их идентификаторы, действия и исполнителей. Полезная нагрузка аудита проходит редактирование конфиденциальных данных.

## Принятые предупреждения

Администраторы с правом Cacti «Настройки/Системные утилиты» могут создать **Исключение для предупреждения** на основе актуального оценённого предупреждения на странице Doctor. Для исключения требуются владелец, причина и дата пересмотра по UTC в пределах 90 дней. Срок действия истекает в полночь по UTC в начале указанной даты. Можно настроить до 100 исключений. Список отображает истёкшие записи и идентификаторы, отсутствующие в текущем отчёте, а также позволяет удалять их.

Наблюдаемое предупреждение остаётся видимым с указанием владельца, причины и срока действия в деталях диагностики. JSON сохраняет наблюдаемый статус и добавляет метаданные `accepted` и `acceptance`. Nagios исключает активные принятые предупреждения из кода завершения, но перечисляет их в своём выводе. Prometheus экспортирует как наблюдаемую, так и требующую действий критичность. Обычный код завершения CLI остаётся без изменений: предупреждения по-прежнему завершаются с кодом ноль, ошибки — с кодом один.

Плановые оповещения о предупреждениях подавляются на время действия исключения; истечение срока или удаление вновь делает сохраняющееся предупреждение доступным для оповещений о предупреждениях. Переходы в состояние ошибки и восстановление после ошибки по-прежнему вызывают оповещения. Неоценённый результат или ошибку нельзя принять как исключение. Персональное подтверждение существует отдельно и ничего не подавляет. Создание и удаление исключений выполняются транзакционно вместе с записью аудита.

Обновление создаёт таблицы `plugin_doctor_audit` и `plugin_doctor_acceptance`, не изменяя данные приложения Cacti. Экспортируйте нужную историю перед удалением плагина: удаление стирает обе таблицы плагина и его настройки. Откат файлов плагина оставляет таблицы доступными для расследования, но более старые версии не учитывают исключения для предупреждений.

## Требования

| Cacti | PHP | Примечания |
|---|---|---|
| 1.2.20 | 5.4 или новее | Собственный код Doctor совместим с PHP 5.4, чтобы диагностировать устаревшие системы перед обновлением |
| 1.2.31 | 8.0 или новее | В `composer.json` Cacti требуется `>=8.0` |
| Текущая 1.2.x | 8.2 или новее | В `composer.json` Cacti требуется `>=8.2` |
| `develop` (1.3) | 8.3 или новее | В `composer.json` Cacti требуется `^8.3` |

Строка **Совместимость PHP с установленной версией Cacti** сравнивает работающую версию PHP с требованием к PHP в собственном корневом файле `composer.json` Cacti, включая верхнюю границу каретного ограничения, например `^8.3`. Настроенный исполняемый файл PHP CLI проверяется по тому же требованию. Doctor распознаёт формы ограничений `>=` и `^`, используемые этими пакетами Cacti. Нечитаемое, некорректное, отсутствующее или нераспознанное требование вызывает предупреждение; установки Cacti 1.2.20–1.2.30 без манифеста сохраняют задокументированный минимальный порог установщика PHP 5.4. Собственная совместимость Doctor с PHP 5.4 не означает совместимость с более новой установкой Cacti.

Строка **Поддержка безопасности PHP разработчиками** отвечает на другой вопрос: продолжает ли данная ветка выпуска PHP получать исправления безопасности от проекта PHP? Она сообщает опубликованную дату окончания поддержки безопасности ветки и предупреждает после этой даты. Например, PHP 8.1 может удовлетворять требованиям среды выполнения более старой установки Cacti, но больше не получать исправлений безопасности от разработчиков. Успешный результат не означает, что установленный корректирующий выпуск актуален, а Doctor не может определить, предоставляет ли поставщик ОС портированные исправления.

Даты поддержки поставляются вместе с Doctor на основе [графика поддержки PHP](https://www.php.net/supported-versions.php) и [списка версий с завершённой поддержкой](https://www.php.net/eol.php), последний раз проверенных 2026-11-08. Неизвестные ветки и предварительные выпуски вызывают предупреждение, а не предполагаемый успех. Во время диагностики сетевые запросы не выполняются. Обновляйте данные поддержки Doctor при публикации нового графика PHP. Существующие идентификаторы JSON и мониторинга `php.version` и `php.security_baseline` не изменены.

Тесты заменяют функции Cacti, вызываемые Doctor, небольшими заглушками в `tests/CactiStubs.php`, поэтому они работают без установленного Cacti.

GitHub Actions запускает четыре вида проверок при каждом push и pull request:

- `php -l` для каждого PHP-файла под PHP 5.4, 5.6, 7.0, 7.1, 7.4 и с 8.0 по 8.4.
- Модульный набор тестов на PHP 8.2, 8.3 и 8.4.
- `locales/build_gettext.sh --check`, который завершается ошибкой при устаревшем шаблоне перевода, неполном или неточном (fuzzy) каталоге либо при отличии скомпилированного каталога от исходного.
- Семь интеграционных заданий, которые устанавливают Cacti 1.2.20, текущую ветку 1.2.x и `develop` с MySQL и MariaDB, используя как cmd.php, так и Spine. Каждое задание устанавливает и включает плагин, запускает полный отчёт CLI и проверяет схему отчёта, итоговые суммы сводки, ожидаемые статусы и точный набор ошибок. Затем оно ломает путь к бинарному файлу и метку времени поллера, подтверждает обнаружение обеих проблем, восстанавливает их, проверяет исправление и его подтверждение, а также выполняет отключение, включение, удаление и повторную установку. JSON-отчёт сохраняется как артефакт при сбое задания.

## Участие в разработке

Pull-запросы отправляйте в ветку `develop`. Сохраняйте совместимость рабочих файлов с PHP 5.4 и придерживайтесь стиля кода Cacti: отступы табуляцией, строки в одинарных кавычках и вспомогательные функции Cacti, такие как `read_config_option()` и `db_fetch_cell()`. Добавляйте модульный тест для каждого изменения поведения, подписывайте коммиты (`git commit -s`) и добавляйте строку в `CHANGELOG.md`.

### Переводы

Оборачивайте каждое видимое пользователю сообщение в `__('...', 'doctor')` (или `__n()`, `__x()`, `__esc()`), а предложение со значением оформляйте единой строкой форматирования с последовательными заполнителями `%s`/`%d`, а не склеивайте из фрагментов. Функция `__()` в Cacti форматирует сообщение только при наличии спецификатора формата и не поддерживает позиционные формы `%1$s`. Она также преобразует `%%` в `%` перед форматированием, поэтому никогда не вставляйте буквальный знак процента в сообщение: передавайте значение вместе со знаком как аргумент (`__('Usage: %s', '50%', 'doctor')`). Строки журнала остаются на английском языке: используйте `doctor_repair_message()` для текста исправлений и `doctor_n_()` для сообщений, которые записываются в журнал и переводятся только при отображении. Не переводите идентификаторы проверок, ключи JSON, ключевые слова статусов, вывод мониторинга и строки журнала.

Скрипт `locales/build_gettext.sh` заново генерирует шаблон `locales/po/cacti.pot`, объединяет его с каждым каталогом `locales/po/<locale>.po` и компилирует `locales/LC_MESSAGES/<locale>.mo`; включайте в коммит все три файла. CI запускает `sh locales/build_gettext.sh --check`, и проверка завершается ошибкой, если шаблон устарел, в каталоге отсутствует запись или есть нечёткая запись (fuzzy), различаются заполнители или устарел скомпилированный файл. Поэтому при изменении сообщения необходимо обновить его переводы в том же pull-запросе. Для работы требуется GNU gettext (`xgettext`, `msgmerge`, `msgfmt`, `msgunfmt`). Новый язык добавляется как новый файл `<locale>.po`, названный в соответствии с соглашением Cacti для локалей (например, `pt-BR`).
